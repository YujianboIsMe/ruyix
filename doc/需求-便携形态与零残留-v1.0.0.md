# 需求：便携形态与零残留（v1.0.0）

**归属版本**：v1.0.0
**提出人**：用户
**原话（两轮，后者是设计基准）**：
> ① *"我们发行的是单可执行文件。所以比较难插件化。除非改发行包为 zip。……启动 1.0.0 版本，开始直接改发行包为 zip。
> zip 内部为可执行文件 + 全局配置文件目录 + 全局数据目录 + 项目目录。按照惯例，先不动代码，先写需求/架构/排期文档。"*
> ② *"其实我的想法是什么呢？单 exe 也能跑，但是用户的全局配置、项目配置、全局数据、项目数据、后期的插件目录
> 都和 exe 同目录，这样用户卸载时就不会有残留。"*
> ③ *"我们的软件，最后我拍板了，就是一个可执行文件 + global 目录 + projects 目录 + plugins 目录。绿色、简洁。"*
> ④ *"把这个图贴进 README.md，说这是他们的软件！"*（图 = 别人家的软件堆满用户主目录，见 `doc/their-softwares.png`）

---

## 〇、一句话把意图钉死

**exe 所在目录 = 唯一根。程序写下的一切（全局配置 / 项目配置 / 全局数据 / 项目数据 / 插件）都在这个目录里；
把文件夹删掉 = 卸载干净。**

这条同时决定了三件事：
1. **zip 只是"推荐发行形态"，不是前置条件** —— 单个 exe 也能跑，它自己会在同级建出那几个目录；
2. **不再有"遗留模式"** —— `~/.ruyix/code` 只作为**一次性导入源**存在（见 §六 迁移），1.0.0 之后没有"长期双根"；
3. **项目状态必须搬出用户仓库** —— 这是本条最容易被忽略、却最值钱的一半，见下。

### 附带收益（这条其实是用户最在意的）

现在：**打开一个项目就在用户的仓库里写下 `<项目>/.ruyix/`**（7 类东西，见 §二），用户得自己加 `.gitignore`；
改完：**用户仓库永远干净**（`git status` 只反映用户自己的改动）。

> ⚠️ 订正：本文档第一版把"不动项目级 `<项目>/.ruyix/`"写成了非目标 —— **那是误读**。
> 用户澄清的"项目配置、项目数据都与 exe 同目录"意味着它必须搬。第一版的 `zip 内 projects/ 目录`假设也一并删除
> （用户的项目在他自己的地方，IDE 不需要一个"默认工作区"）。

## 一、为什么改（诉求的真实来源）

单 exe 形态的硬伤不只是"没地方放插件"，更是**没有"自己的家"**：

- 插件（语法高亮扩展、附加语法、脚本）需要用户可见可写、且随包分发的位置 —— 单文件 exe 给不了，
  这就是 `doc/v0.x/需求-高亮插件化-v0.14.md` 里"法子 2/4"绕不过去的墙；
- 数据与程序分离后，"备份 / 迁移 / 换机 / 卸载"从"翻 `~/.ruyix` 和各个仓库"变成"拷/删一个文件夹"。

## 三、目标形态（根 = exe 同目录）

```
ruyix/                          # ← 这一整个文件夹就是"程序的家"（放哪儿都行）
├── ruyix.exe                   #   单文件；单独拷走也能跑（自己建下面这些目录）
├── global/                     #   ① 全局配置 + ② 全局数据（都在这一层里）
│   ├── *.toml                  #      分节配置 + projects.toml（项目列表，每条带 key）
│   ├── runs/                   #      agent 沙箱产物（原 ~/.ruyix/code/agent/runs）
│   ├── logs/debug.log          #      --debug 落盘
│   ├── cache/                  #      命令发现缓存等
│   ├── webview/                #      WebView2 user data（便携的关键）
│   └── README.md               #      "改坏了就删，程序会重新生成"
├── projects/                   #   ③ 项目状态：一个项目一个桶（原 <项目>/.ruyix/**）
│   └── <项目key>/
│       ├── project.toml        #      自证：key + 原始绝对路径 + 名字
│       ├── *.toml              #      项目作用域配置（含项目级 mcp/a2a/tools/skills）
│       ├── stage/  backups/  proc/  env/  sessions/  verify/
│       └── plugins/            #      该项目专属插件（全局插件在根上）
├── plugins/                    #   ④ 全局插件（v1.0.0 只建目录 + README，加载见 v0.14）
│   └── highlight/
├── README.md  LICENSE  SHA256SUMS.txt
```

**项目状态（③）在 `projects/<项目key>/` 下的对应关系：**

| 原来（写进用户仓库 ✗） | 现在 |
|---|---|
| `<项目>/.ruyix/stage/**` | `projects/<key>/stage/**` |
| `<项目>/.ruyix/backups/**` | `projects/<key>/backups/**` |
| `<项目>/.ruyix/proc/*.log` | `projects/<key>/proc/*.log` |
| `<项目>/.ruyix/env/installs.jsonl` | `projects/<key>/env/installs.jsonl` |
| `<项目>/.ruyix/code/agent/sessions/*.json` | `projects/<key>/sessions/*.json` |
| `<项目>/.ruyix/target-verify`、`out-verify` | `projects/<项目key>/verify/{target,out}`（**绝对路径**注入环境变量） |
| `<项目>/.ruyix/code/*.toml` | `projects/<key>/*.toml` |

**`<项目key>` 怎么定**（待拍板，倾向可读）：`D--Projects-Rust-ruyix` 这种"可读 slug"（盘符去冒号、分隔符换 `--`），
并把 `key` 记进 `global/projects.toml` 的项目条目里（与原路径同源，**少一个索引文件**）——
比纯 hash 好排查，也能一眼看出哪个是孤儿；同时写一份 `projects/<key>/project.toml` 自证。

## 四、需求条目

| # | 需求 | 判据 |
|---|---|---|
| **R1** | **单 exe 也能跑**：只拷 exe 到空文件夹双击 → 自己建出 `global/`、`projects/`、`plugins/` 并用起来 | 空目录只放 exe → 启动 → 目录出现、程序可用、能开项目 |
| **R2** | **根 = exe 同目录**（唯一根）；`RUYIX_HOME` 可覆盖（脚本/多环境逃生口） | `--debug` 日志头打印"根/模式"，三种摆放各跑一次 |
| **R3** | **全局路径只有一个解析点**（`Paths` 门面）；除它之外不许再出现 `home_dir()` 拼路径 | 静态门禁：全仓 grep `home_dir()` 只允许 `paths.rs` 与引擎 `expand_home` |
| **R4** | 首启按模板创建缺失目录（幂等，不覆盖已有文件） | 删 `global/`+`projects/` → 启动 → 回来且可用 |
| **R5** | **项目侧 7 类写入全部搬出用户仓库**（见 §二 B） | 打开项目 → 跑 agent（暂存/备份/验证/起服务）→ **用户仓库里不出现 `.ruyix`** |
| **R6** | **仓库干净**：全过程用户仓库 `git status` 只反映用户自己的改动 | 场景化判据：跑完一轮 agent + 暂存确认 + 验证，`git status --porcelain` 与跑之前**除用户改动外一致** |
| **R7** | **迁移**：检测到遗留 `~/.ruyix/code` 或用户仓库里的 `.ruyix/` → 提供一次性导入 + 询问是否清理旧残留 | 造遗留数据 → 首启 → 提示出现；导入成功写标记；**删除旧目录必须用户显式同意**（默认不删） |
| **R8** | WebView2 user data 落根内（`global/webview`） | 启动后 `%LOCALAPPDATA%` 不新增 ruyix 数据；`global/webview/` 有 |
| **R9** | 引擎默认工作区默认值改到根内；全仓无 `.darkhorse` | 引擎单测改成新路径；grep 无 `.darkhorse` |
| **R10** | 元数据对齐：`1.0.0` + `productName = ruyix` + 图标 + description/authors | exe 属性页正确 |
| **R11** | 发行包：zip（exe + 预置目录 + README + LICENSE + SHA256SUMS）；打包脚本进 `scripts/` | 一条命令产出 zip；解压逐项存在、sha256 可校验 |
| **R12** | 单实例语义按根区分（便携天生允许多份副本并存） | 解压两份到不同目录、各起一个 → 都正常 |
| **R13** | **边界行为明确**：exe 在只读目录 / 在系统临时目录（从 zip 里直接双击）时给人话，不静默乱写 | 两种摆放各跑一次，看提示与日志；**不许**出现"悄悄写到别处" |
| **R14** | 术语与文档同步：`.ruyix` 在文档/提示词里的描述改成新位置（含 `AGENT_SYSTEM` 里那两句"已暂存到 `.ruyix/stage/`"） | 全仓 grep `.ruyix` 只剩"迁移源/历史"语境；模型提示词里的路径正确 |

## 五、非目标（这一版不做）

- 不做安装器（NSIS/MSI）、不做自动更新、不做多用户/服务化（便携版是**单用户形态**，文档里写明）；
- **不实现插件加载**（只建 `plugins/` + 定清单位置），加载是 `doc/v0.x/需求-高亮插件化-v0.14.md` 的事；
- **不做"多根并存"**：没有长期双根，遗留目录仅供一次性导入；
- 不改 agent 沙箱的语义（`runs_root` 的**位置**变，产物格式与隔离纪律不变）。

## 六、迁移（老用户怎么到新形态）

| 来源 | 内容 | 处理 |
|---|---|---|
| `~/.ruyix/code/**` | 全局配置、项目列表、agent runs、debug 日志 | 复制到 `global/`（runs 这类大目录**默认不搬**，可选）；写 `.migrated-from-legacy` |
| `<各项目>/.ruyix/**` | 项目作用域配置、暂存、备份、会话、进程日志 | **按需**：项目作用域配置可搬；暂存/备份/日志默认不搬（都是临时产物） |
| 用户仓库里剩下的空 `.ruyix/` | 残留目录 | 提示"可以删了"（**用户确认才删**，默认保留） |

**恒定纪律**：复制不移动、可拒绝、幂等、失败不半途退出、旧目录在读期间只读。

## 七、待拍板点

**已拍板（2026-09-24）**：发行形态 = **一个可执行文件 + `global/` + `projects/` + `plugins/`** ——
绿色、简洁（§三 的布局就是这个决定；原方案里的 `config/` + `data/` 两分作废）。
由此连带定下：`projects/` 是**项目状态桶**（不是一个"IDE 自带的工作区"）、项目作用域配置与项目数据
**同一个桶**（都是一个项目的）、项目级插件放 `projects/<key>/plugins/`。

| # | 问题 | 我的倾向 |
|---|---|---|
| 1 | 项目 key 用**可读 slug** 还是 hash？ | 可读 slug（`D--Projects-Rust-ruyix`）；key 记进 `global/projects.toml` 的条目里 |
