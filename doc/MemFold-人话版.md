# MemFold（记忆折叠）人话版

> 这份文档讲的是我们 agent 里那套**「记忆折叠」**机制：长任务跑到后面，
> **正文会越攒越多，怎么办**。
> 落地代码：`crates/harness-engine/src/agent/findings.rs`（结论与账本，永不折）、
> `agent/tools.rs::fold_history`（折叠动作）、`agent/capsule.rs`（折掉的正文去哪）、
> `agent/scheduler.rs`（什么时候折）。
> 需求与实测：`doc/v1.1/需求-Agent-进展记忆与循环守卫-v1.1.md`、
> `doc/v1.2/需求-Agent-上下文布局与去重账本-v1.2.md`。

## 0. 先说名字

「**MemFold**」这个名字在仓库代码里**没有对应的标识符**（`LSC`/`capsule`/`ledger` 这些都有，
`MemFold` 没有）。能对上的就是这套机制本身：**记忆折叠 = 历史折叠（fold）+ 进展记忆（findings）**。

如果你说的是别的东西（某个上游模块/论文里的 MemFold），说一声，我把这份文档换过去。
如果你想给它起个正式名，我建议就叫 **记忆折叠（memory folding）**，与代码里的 `fold_history` 对齐。

顺带区分两个容易混的东西（§9 细说）：

| 名字 | 管什么 | 生命周期 |
|---|---|---|
| **记忆折叠（本文）** | **单次 run 内**的对话上下文怎么压 | 一次 run |
| **项目记忆**（`src-tauri/src/mem_cmds.rs`、记忆面板） | **跨 run 的知识库**（带向量检索） | 长期 |

## 1. 一句话说清

> 老轮次的**正文**可以折成一行事实（那些内容噪声居多）；
> 但**结论**和**「我已经做过什么」**一个字都不许折。

**类比**：开会。原始录音几十小时，留着又贵又没人听；但如果会议**决议**和**谁负责什么**也没了，
这个会就白开了。所以正确的做法是：

- 录音（= 每轮的原始正文）→ 压成**纪要一行**（谁提了什么、成没成）；
- **决议**（= 模型确认的结论）→ 单独记一份，**永不删**；
- 原始录音 → 不是烧掉，是**归档**（磁盘侧存），需要查证时按哈希取回原文。

## 2. 为什么非折不可

两个原因，一个省钱一个保命：

1. **钱**：模型的上下文按 token 计费，而且**每轮都要把历史重发一遍**。历史只涨不缩 ⇒ 越跑越贵。
2. **命**：上下文有硬上限。撑爆的两种死法——要么请求被拒，要么模型的话被**截断**
   （`finish_reason=length`，输出只剩半句，那一轮直接废）。

但不折也有个**隐藏成本**：折叠会**打断前缀缓存**（前缀一断，后面全部重算）。
所以「折」不是免费的午餐 ⇒ 需要**门槛**（§6）。

## 3. 折什么：老轮次 → 一行事实

规则很短：**最近的 `keep` 轮正文一字不动，更老的轮次折成一行**。

一行里放四件事（`fold_history` / `outcome_line`）：

```text
<工具> <参数摘要> ✓/✗ <输出首行>
```

真实形状举例（`read` 的结果首行本来就是它的文件头）：

```text
read src/agent/tools.rs ✓ --- src/agent/tools.rs ---
execute cargo test -q ✗ error: expected one of ...
```

为什么取「输出首行」：对四种能力刚好都是最有信息量的那行——`read` 是文件头，
`write` 是「已写入/已改」，`execute` 的第一行往往就是那行错误。

三个工程细节：

- **幂等**：已经折过的轮次再折一次，写进去的是同一串文本 ⇒ 每轮都调它没有副作用；
- **两个位置**：模型那轮（调了什么）和结果那轮（成没成）分别折，各自一行；
- **返回值**：折了几轮、省下多少字节（读数要能看见，不然「有没有折到」没人知道）。

## 4. 绝不折什么：结论、证据、账本

这是这套机制的**灵魂**，三条不变量写在 `findings.rs` 抬头：

> **永不静默丢弃** · **取代不改历史** · **字节要可观测**

| 东西 | 谁写 | 怎么活 |
|---|---|---|
| **结论**（`record_findings`） | **模型自己**写 | 带短 id（`F1`、`F2`…）、一句话结论、**证据指针**（`path:line` 或「命令 + 退出码」）。**空证据不许入库**——结论的价值全在可核对 |
| **已做账本**（读过哪些文件、跑过哪些命令） | **引擎**写 | 不靠模型自觉（越乱的 run 越需要它）：模型忘了，引擎记着 |
| 证据本身 | 模型 + 引擎 | 永远留在提示词里 |

几条容易忽略但很关键的规则：

- **取代不改历史**：模型说「F3 取代 F1」时，F1 **留在账本里**，只是**从提示词里退出**（不删）；
- **超上限不静默丢**：结论攒太多时，最老的条目**落盘**并在提示词里留一行指针——
  **落盘 ≠ 删除**；
- **措辞也是判据**（真被测试钉住的）：折叠后的摘要必须①留下「我读过什么」的痕迹、
  ②说清「正文去哪了」、③**指向进展记忆**（先落结论，再谈重读）。

## 5. 折掉的正文去哪：侧存（capsule）

**折 ≠ 删。** 被折掉的、以及被去重命中要「还回去」的全量结果，落到磁盘：

```text
<便携根>/projects/<项目键>/ctx/<run-id>/
    <step>-<tool>-<hash8>.txt   # 正文原文
    index.jsonl                 # 一行一条索引（含 sha256、len、版本…）
```

- **绝不写用户仓库**（IDE 的状态属于 IDE）；
- 召回时**逐字节 sha256 校验**：不符就**报错并计数**，绝不静默给脏数据；
- 于是就有一条硬指标：**「为了找回已读内容而重跑工具」的次数**——它必须为 0。
  压掉的东西靠**读磁盘**拿回来，不靠再跑一遍命令。

## 6. 什么时候折：窗口是下限，策略在调度器

老做法是拍一个「保留最近 N 轮」。现在这个数字降级成**安全下限**（绝不在 N 轮之内折），
**真正决定权**在重基线调度（`scheduler.rs`）：

- 把「携带历史的费用」和「丢一次重建的费用」写成代价模型（携带便宜、重建贵）；
- 状态只有一维（距上次折几轮）⇒ 可以直接动态规划算出最优折点；
- 每轮用**实测增长**做滚动重规划，只取第一步（视野比预想的长就退化成 ski-rental 在线策略）；
- 判定顺序：**预算越界 → 强制折**；否则 **≥ 安全下限** 再谈 DP；
- 最后还有一条 `MARGIN = 5%` 的**材料性下限**：算出来的差额只有几个百分点就不折腾
  （折一次要打断前缀，不值当）。

一句话：**折的时机是算出来的，不是拍出来的；拍出来的那个数字退化成「不许更早」的红线。**

## 7. 折错了会怎样：一次真实的 96 轮 0 结论

这是这套机制存在的直接原因（ISSUE-8）。当时的折叠摘要里写着：

> 「正文已从上下文移除，**需要时重新 read**」

后果是一个死循环：

```text
读文件（答案在正文里）→ 6 轮后正文被折掉，只剩「我读过它」→ 模型发现自己没有内容 →
按摘要的指示「重新 read」→ 再被折掉 → 再读 …… 96 轮跑完，一个结论都没有
```

**病根不是「折」这件事，是折完之后模型没有别的路可走**：唯一能拿回事实的方式是重跑工具，
而重跑又会被折掉。修法就是本文的两条：**折掉的正文进侧存（可无损召回）** +
**结论永不折（先把事实钉下来）**。

## 8. 怎么量它（读数，不是感觉）

| 读数 | 意义 |
|---|---|
| **折叠次数** | 折得太勤 = 前缀一直被断；太少 = 上下文要爆。这是我们 P4 的判据之一（实测 **8 次 → 1 次**） |
| **前缀占比（G1）** | 折叠会打断前缀 ⇒ 它掉下来就是折多了。**但注意：它不能当「该不该折」的判据**（折得越多比值反而越高，等于奖励多折） |
| **prompt 上界（G2）** | 真正的硬指标：不许越界、不许出现截断 |
| **「为召回而重跑工具」次数** | 必须是 **0**：折掉的东西只能靠侧存拿回 |
| **召回无损** | 召回内容与原文 **sha256 相等** |

读数纪律（踩过才写的）：一律走**配对**（同一份输入过两臂），未配对时两次观察会得出相反结论；
无效轮**剔除并列出**，不当 0、也不当满分。

## 9. 它和「项目记忆」不是一回事

| | 记忆折叠（本文） | 项目记忆 |
|---|---|---|
| 范围 | **单次 run 内**的上下文 | **跨 run** 的知识库 |
| 落点 | `<便携根>/projects/<键>/ctx/<run-id>/` | 项目状态桶里的记忆库（带向量检索） |
| 谁写 | 模型（结论）+ 引擎（账本） | 用户 + agent |
| 失效 | run 结束即结束 | 长期留存、可检索 |
| 目的 | 在预算内跑完长任务 | 越用越懂这个项目 |

两者共同的信条只有一条：**证据不许丢**。

## 10. 一句话版（面试/讲给别人听）

> 长任务的对话历史只涨不缩，既贵又有上限。**记忆折叠**的做法是：把老轮次的**正文**折成
> 一行事实（调了什么、成没成、输出首行），但**模型确认的结论与引擎记的账本一个字都不折**；
> 被折掉的正文**归档到磁盘侧存**、按哈希校验召回，所以「折」不等于「删」；
> 折的**时机**由代价模型算（预算兜底 + 安全下限 + 材料性门槛），不是拍一个固定轮数。
> 它治的是一个真实死循环：折掉正文后模型只能重读，重读又被折掉——96 轮 0 结论。

**名词表**：`keep` = 保留最近几轮正文不动；`findings` = 模型确认的结论（带 id 与取代语义）；
`capsule` = 侧存（折掉正文的落点）；`rebase` = 重基线（一次大压缩）；
`G1/G2` = 前缀占比 / prompt 上界；`MARGIN` = 差额不够大就不折腾的那条门槛。
