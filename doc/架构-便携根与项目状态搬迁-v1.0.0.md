# 架构：便携根与项目状态搬迁（v1.0.0）

**归属版本**：v1.0.0　**上游需求**：`doc/需求-便携形态与零残留-v1.0.0.md`
**一句话**：① 把"全局路径从哪儿来"收敛成**唯一解析点**（根 = exe 同目录）；
② 把**项目侧 7 类写入从用户仓库搬进那个根**（按项目 key 分桶）。
两个目标共用一个前提：**所有路径必须出自同一处代码**，否则"零残留"必然漏。

## 二、`Paths` 门面（宿主唯一的解析点）

```rust
/// 唯一解析点。构造一次（启动最早期），注入给各处 —— 含引擎（引擎是库，不许自己找 exe）。
pub struct Paths {
    root: PathBuf,   // = exe 所在目录（或 RUYIX_HOME）
}

impl Paths {
    pub fn discover(exe_dir: &Path) -> Paths;          // §三 的判定只在这里
    pub fn global_dir(&self) -> PathBuf;               // <root>/global   全局配置 + 全局数据
    pub fn projects_dir(&self)-> PathBuf;              // <root>/projects 项目状态桶（一个项目一个）
    pub fn plugins_dir(&self)-> PathBuf;               // <root>/plugins  全局插件

    /// 项目 key（§五）：把任意项目路径映射成文件夹名
    pub fn project_key(&self, project: &str) -> String;
    pub fn project_dir(&self, key: &str)   -> PathBuf;  // <projects>/<key>（配置与数据同一个桶）
    /// 项目桶内的子目录（stage / backups / proc / env / sessions / verify / plugins）
    pub fn project_bucket(&self, key: &str, bucket: &str) -> PathBuf;

    // 全局数据（都在 global/ 下）
    pub fn runs_root(&self)   -> PathBuf;              // <global>/runs
    pub fn debug_log(&self)   -> PathBuf;              // <global>/logs/debug.log
    pub fn webview_data(&self)-> PathBuf;              // <global>/webview
    pub fn cache_dir(&self)   -> PathBuf;              // <global>/cache
}
```

**顶层只有三个目录，按"归属"分而不是按"配置/数据"分**：`global/`（大家的）、`projects/<key>/`（某个项目的）、
`plugins/`（插件的）—— 用户拍板的原话就是"一个可执行文件 + global + projects + plugins"；
少一层嵌套 = 少一层要解释的东西。全局配置与全局数据同住 `global/`，项目配置与项目数据同住一个桶，
**读写同一个函数**（避免"读了旧的、写了新的"）。

**没有"模式"分支**（第一版设计里的 Portable/Legacy 双根已取消）：根只有一个，
遗留目录**已经不存在**（2026-09-24 人工清完，见需求 §六）—— 代码里连"旧路径"这一支都没有，
架构因此比第一版更简单，这是用户澄清带来的红利。

**引擎侧**：不 `discover`。它从 `AppConfig.workspace_root` 拿根（字段已存在，`config_bridge.rs:69` 已在注），本单只改：
① 默认值去掉 `~/.darkhorse/harness/runs`（`engine/config.rs:41`）；② 相对路径解析相对**注入的根**而非 home（`:965-974`）；
③ **新增**：引擎需要知道"项目数据根"，这样 `stage`/`backups`/`proc` 才写得对 —— 用一个显式字段注入
（`AppConfig` 里加 `project_state_root: Option<PathBuf>`，由宿主填 `<root>/projects`），引擎**不许**自己拼。

## 三、根判定（唯一实现）

```
discover(exe_dir):
  1) RUYIX_HOME 非空 → root = RUYIX_HOME
  2) 否则            → root = exe 所在目录
```
**边界行为（都必须有明确动作，不许"看情况"）**：

| 情形 | 行为 |
|---|---|
| 根不可写（Program Files / 只读介质） | **拒绝启动** + 人话（"这个目录不可写：请把 ruyix 放到可写位置，或设 RUYIX_HOME"）；**不静默写到别处** |
| 根在系统临时目录（从 zip 里直接双击，Windows 解压到 `%TEMP%`） | 照常启动，但首次给一句"请先解压到固定位置（当前数据存在临时目录，重启系统会丢）" + 日志一行 |
| 根在同一台机器被多个 Windows 用户使用 | 文档写明"便携版是单用户形态"；写失败走上一条 |
| `current_exe()` 失败 | 用 `RUYIX_HOME`；都没有则报错退出（不猜） |

判定只做一次并缓存；`--debug` 会话头**必须**打印 `根=… | 可写=… | webview=…`（A2/R13 的证据）。

## 五、项目 key 与索引

- **key 规则**（可读，待拍板）：绝对路径 → 盘符去冒号、`\`/`/` → `--`，例
  `D:\Projects\Rust\ruyix` → `D--Projects-Rust-ruyix`；非 `[A-Za-z0-9._-]` 的字符转 `_`；
  过长则截断 + 4 字节 hash 后缀（Windows 路径长度风险）；
- **索引**：**不另开索引文件** —— `key` 直接写进 `<root>/global/projects.toml` 的项目条目里
  （与原路径同源，少一个要同步的文件；写入时机 = 打开项目时），
  同时写一份 `projects/<key>/project.toml` 自证，哪个文件夹属于哪个项目一眼可见；
- **孤儿**：项目被移动/删除后 `projects/<key>/` 仍在 → 提供"清理孤儿状态"入口（**不自动删**）；
  路径比较沿用现有 `clean_path` 纪律（大小写/短路径不猜）；
- **同名不同路径**永不撞（slug 不同）；**同路径不同副本**必然同 key（这正是"同一项目状态共享"的期待行为）。

## 八、WebView2 data dir 与单实例（**P0 已实测**，2026-09-24）

**结论一：WebView2 的用户数据目录能落进根内，机制是 `WebviewWindowBuilder::data_directory()`。**

- API（`tauri 2.11.5`）：`tauri::WebviewWindowBuilder::data_directory(PathBuf)`
  （`webview_window.rs:1024`；`WebviewBuilder` 上同名，`webview/mod.rs:963`）→ 透传给 wry 的
  `WebContext::new(Some(path))` → Windows 上就是 WebView2 的 **userDataFolder**。
  **不需要退路方案**（`WEBVIEW2_USER_DATA_FOLDER` 环境变量留在兜底位置，不必启用）。
- 实测（`node scripts/p0-probes.mjs`，两条臂都要跑）：

  | 臂 | 关键原始证据 | 判定 |
  |---|---|---|
  | 指定臂 `--data-dir <tmp>` | `profile_created_at_target=true`、`profile_path=<tmp>\EBWebView`、`new_localappdata_entries=[]`、`localappdata_identifier_touched=false`（`Local State` 时间戳前后**逐位相同**：`134347328037788554`） | ✅ 三个条件全达 |
  | 对照臂 `--default`（今日形态） | `localappdata_identifier_touched=true`（`...037788554` → `…456053498`）、`profile_path=%LOCALAPPDATA%\com.ruyix.code` | ✅ 对照组成立 → **不指定必然外溢**，不是我猜的 |

  → **A5 可做**：把 data dir 指到 `<root>/global/webview` 就成立，"删文件夹即净"成立。
  → 顺带记一笔现状体量：`%LOCALAPPDATA%\com.ruyix.code\EBWebView` 实测 **41MB**（老血统那台
  `com.darkhorse.harness` 还留着 **34MB**，是另一个值得在 release 里提一句的残留）。

**结论二：单实例互斥体按根区分可行；今天的写死名字确实会撞。**

| 臂 | 结果 | 判定 |
|---|---|---|
| 同根并发两份 | 一个 `first_instance=true`、一个 `false`，同一个名字 `Local\ruyix-instance-<root 指纹>` | ✅ P2-A |
| 不同根并发（按根命名） | 两个都 `true`，名字 `…-d0ca4b45c56029cb` vs `…-873e7090c06d4766` | ✅ P2-B |
| 不同根并发（`--name-mode global` = 现状） | 第二个 `false` —— 撞了 | ✅ P2-C（对照臂：所以现状必须改） |

两条读代码得到的事实（与上面互证）：① 这个互斥体**不阻止启动**，只让第二个实例不自动打开
上次项目（前端读 `is_another_instance` 命令）；② 两份副本真正的冲突点是**共享 WebView2 profile**，
所以 **data dir 与 mutex 必须一起按根**（同 §八 开头那条"两条同批做"）。

**探针怎么重跑**（一条命令跑完所有臂，打印原始输出 + 按预注册判据判定）：

```bash
node scripts/p0-probes.mjs          # 内部先 cargo build -p ruyix --examples
```

预注册判据写在脚本头部与 `src-tauri/examples/{webview_data_probe,instance_mutex_probe}.rs` 里；
退出码 0 = 全部达预期（当前 **8/8**）。

> ⚠️ **踩坑记录**（示例二进制为什么"一个字都不输出"）：示例拿不到 tauri-build 给主程序嵌的
> 应用清单，而 tao/wry 会导入 comctl32 **v6 才有**的 `SetWindowSubclass` / `TaskDialogIndirect`；
> 没清单时加载器挑 system32 里的 v5，进程在 `main` 之前就死在 **`0xC0000139`**
> （STATUS_ENTRYPOINT_NOT_FOUND），stdout/stderr 全空 —— 看起来像"探针没干活"。
> 修法：`src-tauri/build.rs` 补 `cargo::rustc-link-arg-examples=/MANIFEST:EMBED`
> + `examples/probe.manifest`（**只影响 examples，不碰发布产物**）。
> 排查路径留存：PE 导入表对比（两个 exe 导入的系统 DLL 一样）→ 二进制里搜
> `Microsoft.Windows.Common-Controls` / `SetWindowSubclass` → 差异只剩清单。

**A3/A4「仓库干净」怎么跑才可信**：`scripts/repo-clean-scenario.mjs`

- 快照写在**项目之外**（`%TEMP%/ruyix-repo-clean-scenario`）—— 一个用来证明"零写入"的工具，
  自己先不能往仓库里写；
- `--phase before` → （打开项目 → agent 暂存 → 确认写回 → 起托管服务 → 跑验证 → 收尾）→ `--phase after`
  → 自动判定：`git status --porcelain` 的**新增行**必须为空、`find -name .ruyix` 必须为空；
- `--selftest`：自检判定逻辑（"什么都没写"要放行、"写了 `.ruyix`"要报红）——收尾已跑通。

## 十、不变量与门禁

1. **`home_dir()` 只允许出现在 `paths.rs`**（宿主）与引擎 `expand_home`（`~/` 展开）→ 静态门禁 + 单测；
2. **全仓无 `.darkhorse`**（含文档示例）；
3. **用户项目目录里不出现 IDE 文件** → 这是本单最有价值的判据，两层：
   - **动态**（主判据）：一个真机场景跑一遍（打开项目 → 让 agent 暂存一次 + 交付一次 → 起一个托管进程 → 跑一次验证），
     然后 `git status --porcelain` 只剩用户自己的改动、`find <项目> -name .ruyix` 为空；
   - **静态**（辅助）：全仓 grep `<项目>/.ruyix` 形态的拼接（防止有人新写一处）；
4. `Paths::discover` 表驱动单测：`RUYIX_HOME` × exe 同级 ×（有/无预置目录）× 可写性；
5. `project_key` 单测：Windows 路径、UNC、中文、超长、大小写；
6. 打包脚本用 `RUYIX_HOME` 指向临时目录（门禁不污染开发机）。
