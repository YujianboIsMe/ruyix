# 架构：便携根与项目状态搬迁（v1.0.0）

**归属版本**：v1.0.0　**上游需求**：`doc/需求-便携形态与零残留-v1.0.0.md`
**一句话**：① 把"全局路径从哪儿来"收敛成**唯一解析点**（根 = exe 同目录）；
② 把**项目侧 7 类写入从用户仓库搬进那个根**（按项目 key 分桶）。
两个目标共用一个前提：**所有路径必须出自同一处代码**，否则"零残留"必然漏。

---

## 一、改造清单（全量，带行锚 —— 逐项勾掉才算完成）

见需求文档 §二 的两张表（全局 8 处 / 项目侧 7 类）。这里只强调分类纪律：

| 类别 | 数量 | 处置 |
|---|---|---|
| 全局侧 `home_dir()` 拼接 | 8 处（7 个文件） | **全部收敛**到 `Paths` 门面 |
| 项目侧 `.ruyix` 写入 | 7 类（9 处代码） | **全部改指**根内 `projects/<key>/`（配置与数据同一个桶） |
| 项目侧**读取**（项目级 tools/skills/mcp/a2a） | 4 处 | 同步改指（读与写必须同一处解析，否则"读了旧的、写了新的"） |
| 沙箱副本里的 `.ruyix` | `engine/workspace.rs:253` | **不动**（那是沙箱复制品，不是用户仓库） |

## 二、`Paths` 门面（宿主唯一的解析点）

```rust
/// 唯一解析点。构造一次（启动最早期），注入给各处 —— 含引擎（引擎是库，不许自己找 exe）。
pub struct Paths {
    root: PathBuf,   // = exe 所在目录（或 RUYIX_HOME）
}

impl Paths {
    pub fn discover(exe_dir: &Path) -> Paths;          // §三 的判定只在这里
    pub fn global_dir(&self) -> PathBuf;               // <root>/global   全局配置 + 全局数据
    pub fn projects_dir(&self)-> PathBuf;              // <root>/projects 项目状态桶（一个项目一个）
    pub fn plugins_dir(&self)-> PathBuf;               // <root>/plugins  全局插件

    /// 项目 key（§五）：把任意项目路径映射成文件夹名
    pub fn project_key(&self, project: &str) -> String;
    pub fn project_dir(&self, key: &str)   -> PathBuf;  // <projects>/<key>（配置与数据同一个桶）
    /// 项目桶内的子目录（stage / backups / proc / env / sessions / verify / plugins）
    pub fn project_bucket(&self, key: &str, bucket: &str) -> PathBuf;

    // 全局数据（都在 global/ 下）
    pub fn runs_root(&self)   -> PathBuf;              // <global>/runs
    pub fn debug_log(&self)   -> PathBuf;              // <global>/logs/debug.log
    pub fn webview_data(&self)-> PathBuf;              // <global>/webview
    pub fn cache_dir(&self)   -> PathBuf;              // <global>/cache
}
```

**顶层只有三个目录，按"归属"分而不是按"配置/数据"分**：`global/`（大家的）、`projects/<key>/`（某个项目的）、
`plugins/`（插件的）—— 用户拍板的原话就是"一个可执行文件 + global + projects + plugins"；
少一层嵌套 = 少一层要解释的东西。全局配置与全局数据同住 `global/`，项目配置与项目数据同住一个桶，
**读写同一个函数**（避免"读了旧的、写了新的"）。

**没有"模式"分支**（第一版设计里的 Portable/Legacy 双根已取消）：根只有一个，
遗留目录只出现在**迁移**里（读一次、复制、可选清理）—— 架构因此比第一版更简单，这是用户澄清带来的红利。

**引擎侧**：不 `discover`。它从 `AppConfig.workspace_root` 拿根（字段已存在，`config_bridge.rs:69` 已在注），本单只改：
① 默认值去掉 `~/.darkhorse/harness/runs`（`engine/config.rs:41`）；② 相对路径解析相对**注入的根**而非 home（`:965-974`）；
③ **新增**：引擎需要知道"项目数据根"，这样 `stage`/`backups`/`proc` 才写得对 —— 用一个显式字段注入
（`AppConfig` 里加 `project_state_root: Option<PathBuf>`，由宿主填 `<root>/projects`），引擎**不许**自己拼。

## 三、根判定（唯一实现）

```
discover(exe_dir):
  1) RUYIX_HOME 非空 → root = RUYIX_HOME
  2) 否则            → root = exe 所在目录
```
**边界行为（都必须有明确动作，不许"看情况"）**：

| 情形 | 行为 |
|---|---|
| 根不可写（Program Files / 只读介质） | **拒绝启动** + 人话（"这个目录不可写：请把 ruyix 放到可写位置，或设 RUYIX_HOME"）；**不静默写到别处** |
| 根在系统临时目录（从 zip 里直接双击，Windows 解压到 `%TEMP%`） | 照常启动，但首次给一句"请先解压到固定位置（当前数据存在临时目录，重启系统会丢）" + 日志一行 |
| 根在同一台机器被多个 Windows 用户使用 | 文档写明"便携版是单用户形态"；写失败走上一条 |
| `current_exe()` 失败 | 用 `RUYIX_HOME`；都没有则报错退出（不猜） |

判定只做一次并缓存；`--debug` 会话头**必须**打印 `根=… | 可写=… | webview=…`（A2/R13 的证据）。

## 四、布局映射（旧 → 新，逐项机械可对）

| 内容 | 旧位置 | 新位置 |
|---|---|---|
| 全局分节配置 | `~/.ruyix/code/<section>.toml` | `<root>/global/<section>.toml` |
| 项目列表（每条带 `key`） | `~/.ruyix/code/projects.toml` | `<root>/global/projects.toml` |
| MCP / A2A / 工具 / 技能（全局） | `~/.ruyix/code/{mcp,a2a,tools,skills}.toml` | `<root>/global/…` |
| **项目作用域配置**（含项目级 mcp/a2a/tools/skills） | `<项目>/.ruyix/code/*.toml` | `<root>/projects/<key>/*.toml` |
| agent 沙箱产物 | `~/.ruyix/code/agent/runs` | `<root>/global/runs` |
| **确认模式暂存** | `<项目>/.ruyix/stage/**` | `<root>/projects/<key>/stage/**` |
| **写前备份** | `<项目>/.ruyix/backups/**` | `<root>/projects/<key>/backups/**` |
| **托管进程日志** | `<项目>/.ruyix/proc/*.log` | `<root>/projects/<key>/proc/*.log` |
| **环境安装留痕** | `<项目>/.ruyix/env/installs.jsonl` | `<root>/projects/<key>/env/installs.jsonl` |
| **会话存档** | `<项目>/.ruyix/code/agent/sessions/*.json` | `<root>/projects/<key>/sessions/*.json` |
| **验证产物** | `<项目>/.ruyix/target-verify`、`out-verify` | `<root>/projects/<key>/verify/{target,out}`（**绝对路径**注入） |
| 调试日志 | `~/.ruyix/code/debug.log` | `<root>/global/logs/debug.log` |
| WebView2 user data | `%LOCALAPPDATA%`（OS 默认） | `<root>/global/webview` |
| 插件（全局） | （无） | `<root>/plugins/` |
| 插件（项目专属） | `<项目>/.ruyix/plugins/` 不存在 | `<root>/projects/<key>/plugins/` |
| 命令发现缓存 | （进程内） | `<root>/global/cache/` |

> 用户仓库里**一个字节都不写**（`api/apply` 的产物写回除外 —— 那是用户要的结果，不是 IDE 的状态）。

## 五、项目 key 与索引

- **key 规则**（可读，待拍板）：绝对路径 → 盘符去冒号、`\`/`/` → `--`，例
  `D:\Projects\Rust\ruyix` → `D--Projects-Rust-ruyix`；非 `[A-Za-z0-9._-]` 的字符转 `_`；
  过长则截断 + 4 字节 hash 后缀（Windows 路径长度风险）；
- **索引**：**不另开索引文件** —— `key` 直接写进 `<root>/global/projects.toml` 的项目条目里
  （与原路径同源，少一个要同步的文件；写入时机 = 打开项目时），
  同时写一份 `projects/<key>/project.toml` 自证，哪个文件夹属于哪个项目一眼可见；
- **孤儿**：项目被移动/删除后 `projects/<key>/` 仍在 → 提供"清理孤儿状态"入口（**不自动删**）；
  路径比较沿用现有 `clean_path` 纪律（大小写/短路径不猜）；
- **同名不同路径**永不撞（slug 不同）；**同路径不同副本**必然同 key（这正是"同一项目状态共享"的期待行为）。

## 六、搬迁的七处技术细节（照做，别各自发挥）

1. **`config.rs:911`（项目配置根）**：改为 `Paths::project_config(&key)`；读路径与写路径必须同一个函数（避免"读了旧的写了新的"）；
2. **`stage.rs:24` / `engine/agent.rs:2451`（暂存）**、**`apply.rs:25` / `stage.rs:126` / `engine/agent.rs:2413`（备份）**：
   改指 `project_bucket(key, "stage"|"backups")`。**路径封闭规则要跟着改**：现在拒绝写 `.ruyix/**`
   （`stage.rs:30,103`），改为**拒绝写 IDE 状态根**（`<root>/**`）—— 判据从"名字"换成"是不是我们的家"；
3. **`engine/proc.rs:211`（进程日志）**：改指 `project_bucket(key, "proc")`；日志是引擎写、按 pid 命名，路径由引擎从注入的状态根拼；
4. **`env_setup.rs:241`**：改指 `project_bucket(key, "env")`；
5. **`sessions.rs:123`**：改指 `project_bucket(key, "sessions")`；`agent/mod.rs:547` 那句
   "会话跟项目走：没有项目就没有 `<root>/.ruyix` 可写"的注释与逻辑要一起改（现在没有项目就**可以**有状态根）；
6. **`verify.rs:495,528`**：`CARGO_TARGET_DIR` 与输出目录改**绝对路径**注入（`<root>/projects/<key>/verify/…`）。
   注意：exe 与项目跨盘时 cargo 不能硬链接 → 编译慢一点（可接受，文档说明）；
7. **提示词与文案**：`AGENT_SYSTEM` 里两处"已暂存到 `.ruyix/stage/`"（`engine/agent.rs:1465,1528`）与
   系统提示里的 `.ruyix` 说明（`:484`）必须改成新位置 —— **模型看到错路径会去 `read` 一个不存在的地方**，
   这类"提示词描述与实际不符"在这个仓库里已经被抓过两次。

## 七、迁移（两类来源，见需求 §六）

- `~/.ruyix/code/**` → `global/`（`runs/` 默认不搬）；
- 用户仓库 `<各项目>/.ruyix/**` → 只搬"项目作用域配置"（`code/*.toml`），
  暂存/备份/日志/会话默认不搬（都是临时产物）；搬完提示"可以删 `.ruyix/` 了"，**用户确认才删**；
- 幂等标记：`global/.migrated-from-legacy`、`global/.migrated-projects`；复制不移动、可拒绝、失败不半途退出。

## 八、WebView2 data dir 与单实例（与 v1 设计相同，但依赖性更强）

- 便携形态下 WebView2 数据**必须**在根内，否则"删文件夹即净"不成立（A5）；
- `instance.rs` 的全局命名 mutex 改为**按根区分**（名字带 `<root>` hash）—— 两份副本并存才是便携的常态；
- **两条必须同批做**：只做 data dir 会出现"第二个实例起不来、缓存却被共用"的更坏状态。

## 九、与插件化（v0.14）的接口

`<root>/plugins/`（全局）+ `<项目>/.ruyix/plugins/` 不再存在（**项目级插件放 `<root>/projects/<key>/plugins/`**，
与"用户仓库零写入"一致）——这条要与 v0.14 文档同步修订。

## 十、不变量与门禁

1. **`home_dir()` 只允许出现在 `paths.rs`**（宿主）与引擎 `expand_home`（`~/` 展开）→ 静态门禁 + 单测；
2. **全仓无 `.darkhorse`**（含文档示例）；
3. **用户项目目录里不出现 IDE 文件** → 这是本单最有价值的判据，两层：
   - **动态**（主判据）：一个真机场景跑一遍（打开项目 → 让 agent 暂存一次 + 交付一次 → 起一个托管进程 → 跑一次验证），
     然后 `git status --porcelain` 只剩用户自己的改动、`find <项目> -name .ruyix` 为空；
   - **静态**（辅助）：全仓 grep `<项目>/.ruyix` 形态的拼接（防止有人新写一处）；
4. `Paths::discover` 表驱动单测：`RUYIX_HOME` × exe 同级 ×（有/无预置目录）× 可写性；
5. `project_key` 单测：Windows 路径、UNC、中文、超长、大小写；
6. 打包脚本用 `RUYIX_HOME` 指向临时目录（门禁不污染开发机）。
