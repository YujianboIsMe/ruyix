# 运行
自学习的运行机制。
对于任意后缀的文件，IDE有三种记忆状态：
1. 该文件可以运行
2. 该文件不可以运行
3. 未知
下面分三个章节讨论这三种情况。

----

## 可以运行
IDE从全局配置里读取execute.toml
该配置里记录了每种后缀的能否运行的判断。
当用户在【项目文件】里右键一个文件时，右键菜单出现【运行】选项。
但是这时候还需要细分：
1. 运行目标已经绑定了这个文件
2. 运行目标未绑定这个文件

如果是情况1，点击则执行运行目标。
如果是情况2，点击则创建运行目标。

### 预置清单文件（按内容生成，不猜）
除了 execute.toml，还有一批**知名清单文件**，它们的运行目标由**文件内容**推断：

| 清单文件 | 生成的运行目标 |
|---|---|
| `package.json` | `scripts` 里**每个脚本一条**（`dev`/`build`/`test`…），命令 `<包管理器> run <脚本名>` |
| `Cargo.toml` | `cargo run` |
| `Makefile` | `make` |

- 包管理器按**同目录锁文件**识别：pnpm-lock.yaml / yarn.lock / bun.lockb / 否则 npm
- 排序：dev → start → serve → 其余
- 名称冲突时加父目录前缀（如 `admin-web:dev`）
- `package.json` 没有 `scripts` 时**不生成**运行目标，只提示"没有可运行的 scripts"
  （绝不回退成写死的 `npm start`）

### 工作目录
运行目标绑定清单文件后，命令在**该文件所在目录**执行（如 `admin-web\package.json` → `<项目根>\admin-web`），
未绑定则用项目根。详见 [bug-运行目录错误](./v0.x/bug-运行目录错误-v0.0.4.md)。

## 不可以运行
这种情况最简单了，不显示任何与运行有关子菜单

---

## 未知
让IDE不知道某个文件后缀是可以运行时，右键菜单显示【试跑】选项。
此时流程如下：
1. 将该文件的**绝对路径 + 文件内容（截断 4000 字符）+ 同目录线索**（锁文件、Cargo.toml、
   pyproject.toml、go.mod 等）发送给LLM，询问该文件是否能运行，并询问需要追加什么条件；
   —— 只发路径是不够的：LLM 看不见文件内容时只能按文件名猜命令（如把 package.json 猜成 npm start）
2. 若LLM回复不能运行，则记录下来；
3. 若LLM回复可以运行，不需要追加条件时，则记录在本地；
4. 若LLM回复可以运行，但是需要追加条件时，这个场景，先回复用户【功能待开发】。
