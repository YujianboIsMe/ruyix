## 1. 现象与证据（一次真实 run）

会话里问了一句**诊断题**（*"为什么配置模型后，会话 UI 里却一直是模型未知？难道是 anthropic 兼容接口无法
探测可用模型？"*），结果是：

| 观测 | 值 |
|---|---|
| 轮数 | **96（上限）**，循环被掐断 |
| 工具调用 | **207 次** |
| 文件变更 | **0**（诊断题，本不要求改文件，但 96 轮里没有产出结论） |
| 重复行为 | 反复 `read ui/scripts/session.js`（第 93/95 轮等）、反复 `findstr` 同一批符号 |
| 结束语 | *「达到 96 轮上限，循环停止。已完成 207 次工具调用、0 个文件变更；请基于以上进展继续指示。」* |
| trace 里的折叠行 | `历史折叠 1 轮（省 236 字节；保留最近 6 轮正文）` —— **每一轮都折**，且连 236 字节都折 |

**结论不是"模型笨"**：同一道题我直接用后端两条命令问了一次就有答案（见 §6 标准题）。是**证据在途中被删掉**了。

## 2. 病根（读代码得到，不是推测）

`crates/harness-engine/src/agent.rs::fold_history`：超出保留窗口的每一轮，被替换成**两个摘要**：

```rust
// 折叠后 assistant 那半替换成什么（只留"调了什么"，不留 content 正文）
call_digest:    format!("{{\"folded\":\"第 {step} 轮调用（{shape}）—— 请求正文已折叠\"}}"),
// 折叠后 result 那半替换成什么（一行事实）
outcome_digest: format!("{{\"ok\":{all_ok},\"folded\":\"第 {step} 轮结果（{outcome}）—— 正文已从上下文移除，需要时重新 read\"}}"),
```

三个事实叠起来就是循环的生成机制：

1. **`call_shape` 保留了 `read <path> (a-+b)`**（路径与区间还在）⇒ 引擎并不是失忆，
   它记得「做了什么」；
2. **`outcome_line` 只留输出的第一行（截 100 字符）** ⇒ 丢的是「知道了什么」——
   而诊断题的答案恰好全在文件正文里（某个函数从哪取值、配置链怎么走）；
3. **摘要的措辞是「需要时重新 read」** ⇒ 引擎在**字面上教模型重读**。读一次、六轮后被折掉内容、
   只剩"我读过它"，于是再读一次——**闭环**。

保留窗口是 `cfg.agent.history_keep_rounds`（默认 **6**）。**先不要调大它**：那只是把天花板抬高、
token 线性上涨，症状晚点出现而已。要动的是"被折叠的是哪一类东西"。

| ① 上限与溢出 | 超限 ⇒ **落盘 + 提示词里留指针**；默认上限 **8KB** |

## 4. 方案：一份账本，三个消费者

核心口径：**证据与噪声分开。** 工具输出的正文可以折（噪声居多），**结论与"已确认的事实"不许折**。
账本只有一份，三个消费者共用，避免同一块数据写两遍。

### 4.1 引擎账本（引擎写，永不折叠）

每轮由**引擎**追加一行结构化事实（不是模型写的，所以它一定会被写下来）：

```
[账本] r12 read ui/scripts/session.js 296-334 ✓ 命中 paintModel
[账本] r13 execute findstr /s /n "ai_list_models" src-tauri/src/*.rs ✓ 退出码 0（命中 3 处）
[账本] r14 execute cargo test -p harness-engine ✗ 退出码 101
```

- 与现有 `call_shape` 的差别是：账本**独立存放**（不随那一轮被折）、**含退出码与命中摘要**、
  且**只增不改**；
- 它让模型第 40 轮仍然知道"第 12 轮读过这个文件的这一段" ⇒ 与 §4.3 的重复读守卫直连。

### 4.2 `record_findings`（模型写，永不折叠）

新增工具（**第 8 个**：`read/write/execute/connect/plan/ask_user/final/record_findings`）。
模型把**结论 + 证据指针**写进来，带唯一 id：

```json
{"tool":"record_findings","args":{"items":[
  {"claim":"会话工具栏的模型名来自 wrap._webCaps.model，下拉项来自 wrap._models",
   "evidence":"read ui/scripts/session.js 296-334","supersedes":7},
  {"claim":"两条数据源只在打开/刷新时取一次，会话标签从磁盘恢复时不再取 ⇒ 一次失败就永远显示未知",
   "evidence":"read ui/scripts/session.js 302-313；未在别处找到重取触发"}
]}}
```

- **id 由引擎分配**（`F1…`），并在工具结果里回给模型 —— 它要 `supersede` 就得先知道 id；
- **`supersede`**：把被取代的那条标 `superseded` ⇒ **不再进提示词**，但**仍在账本与落盘文件里**
  （"不物理删除"）；提示词里只放 `active` 条目 —— 这是"不压缩"能长期成立的唯一办法，
  否则 findings 会线性膨胀到把上下文挤爆；
- **允许进批**（`plan`/`final` 那类控制动作不许进批，`record_findings` 是**例外**：
  它对外部世界没有副作用、没有顺序风险，能搭车就不该多花一轮）；
- 注入位置：**system 消息的尾部追加一个 findings 块**（前缀稳定 ⇒ 只有块本身变化时字节才变）。

### 4.3 守卫①：重复读

引擎账本已知道每次 `read` 的 `(path, range)`。同一 `(path, range)`（区间**相交**）在本 run 第 **2**
次出现时，在该次工具结果后追加一行：

```
（第 12 轮已读过 ui/scripts/session.js 的同一段。当时若得出过结论，它在 F3；
 若这一读没有带来新事实，请停止重读并推进下一步；若有新事实，请立刻 record_findings。）
```

要点：**不是禁止重读**（重读有时正当：文件被改过、要引用具体行），而是让它在**知情**的前提下重读。

### 4.4 守卫②：停滞（K = 8 ⇒ 强制 final）

判据是**引擎可观测的**两个量：

> 连续 **8 轮**内 **既没有新增 findings**、**也没有文件变更** ⇒ 判为停滞。

到点后**强制 final**：拒绝该轮的一切工具调用，并把一条硬指令回灌给模型 ——

```
（停滞守卫：连续 8 轮没有新结论、没有文件变更。本轮不再接受任何工具调用。
 必须立刻给出 final：① 已确认的事实（引用 findings id 与证据指针）② 卡在哪 ③ 需要用户提供什么。）
```

- **必须硬**：模型若不照做（又发了工具调用），引擎**直接终止该 run**，并按已确认的账本给一份诚实报告
  —— 不允许"守卫被绕过"这种半成品状态；
- 这条把「96 轮 0 变更、什么也没说」变成「≤20 轮 + 一个说清楚的问题」，这是本轮最直接的收益。

### 4.5 折叠措辞（同一批，成本最低）

把摘要里那句**教人重读**的话换掉（`agent.rs` 的两个 `digest`）：

```
旧：{"folded":"第 N 轮结果（outcome）—— 正文已从上下文移除，需要时重新 read"}
新：{"folded":"第 N 轮结果（outcome）正文已折叠。这段若得出结论，请立刻 record_findings
     （claim + path:line）；确需正文时用 read 带**精确区间**取回，不要整文件重读。"}
```

## 5. 不变量（实现时不许越过）

1. **findings 永不静默丢弃**：超 8KB 时，最老的 `active` 条目**落盘**（清单见下），
   提示词里留一行指针（`F7–F12 已落盘：<路径>`）。**落盘 ≠ 删除**。
2. **落盘位置**：`<便携根>/projects/<项目键>/findings/<会话或 run id>.md`。
   它是 `read` 工具**唯一的越狱例外**（只读白名单前缀）—— 因为落盘位置必须能被模型取回，
   否则"指针"就是死链。这条例外必须与 `read` 的路径封闭检查写在**同一条注释**里。
3. **`supersede` 不改历史**：被取代条目留在账本与文件里，只从提示词中退出。
4. **账本与 findings 不进 `fold_history` 的折叠范围**（折叠只碰对话流那两类消息）。
5. **字节账要可观测**：每轮的 trace 里报 `findings N 条 / X KB（上限 8KB）`，
   否则 8KB 这条线在真机上是不是踩到了，没人知道。
6. **UI 可见**：新增 `agent://findings` 事件 + 会话消息上的 `findings` 字段
   （**必须在 `agent::sessions::SessionMsg` 里声明**，否则 serde 往返会把它悄悄抹掉 —— 这是本仓库
   已经付过代价的坑），气泡下给一个可折叠的「已确认事实」块。

## 6. 判据（**预注册**，实施前先写死）

### 6.1 标准题（用真机上已有答案的那道）

> 「为什么配置模型后，会话 UI 里却一直是模型未知？难道是 anthropic 兼容接口无法探测可用模型？」

**它的正确答案已经拿到**（真应用 + CDP 实测）：

```json
ai_list_models → ["deepseek-flash","deepseek-v4-pro"]
ai_model_caps  → {"model":"deepseek-flash","web_search_anthropic":true,"multimodal":true}
```

⇒ 两条数据源**都正常**，所以「模型未知」**不是探测失败**，而是前端取一次失败后**没有重取**
（`session.js:302-313` 的两个值只在打开/刷新时取）。这道题的价值：**有唯一正确答案、可自动判分**。

### 6.2 实验设计

- **基线**：同一道题跑 **3 次**（当前代码）。指标：同一 `(path, range)` 被**重复读**的次数、
  总工具调用数、**是否给出可用答复**、卡在哪。
- **臂**：只开 findings + 两条守卫（`history_keep_rounds` **不动** ⇒ 单变量）。
- **通过判据**：重复读次数 **≤ 基线的 50%**，且 3 次里 **≥2 次**给出可用答复。
- **否定判据（必须写死）**：findings 累计 **> 上下文 1/3** ⇒ 判**设计失败**（结论把提示词挤爆），
  哪怕主判据达标也不接受。

### 6.3 门禁形状（引擎单测，实施时逐条落地）

| 判据 | 断言 |
|---|---|
| `fold_never_touches_findings_block` | 折叠任意轮次后，findings 块字节不变 |
| `superseded_findings_leave_prompt_but_stay_in_ledger` | 被取代条目不在提示词、仍在账本与落盘文件 |
| `findings_over_cap_spill_with_pointer` | 超 8KB ⇒ 最老条目落盘 + 指针行；总字节回到上限内 |
| `spilled_findings_are_readable` | 指针路径能被 `read` 取回（越狱例外只对它成立，别处仍拒） |
| `repeated_read_of_same_range_is_called_out` | 第二次读同一区间 ⇒ 结果里出现那一行（首读不出现） |
| `stall_guard_forces_final_after_eight` | 连续 8 轮无 findings 无写入 ⇒ 拒绝工具调用并要求 final；9 轮仍不照做 ⇒ run 终止且报告诚实 |
| `record_findings_rides_along_in_a_batch` | 与 read 同批出现 ⇒ 正常受理，且**不占**额外轮数 |
| `ledger_reports_byte_accounting` | trace 里每轮有 `findings N 条 / X KB` |

## 7. 与既有机制的关系（别重复造）

| 既有 | 关系 |
|---|---|
| `tail_history` | **跨会话**的输入历史裁剪；本需求只动**单次 run 内**的 `fold_history`，两回事 |
| `step_agent` 的"引擎写一行摘要" | 同一个念头在子步骤层的实现（≤12 行 / 1.5KB）—— 本需求是**把它抬到主循环层**，不是第二套机制 |
| 记忆层的五算子（`supersede`/`correct`/…） | findings 的版本语义**同构**：证据无损、信念可损 |
| 质量门禁 / 反思 agent | 不变；findings 是**过程**记忆，不替代 `verify`/`reflect` |
| `AGENT_SYSTEM` 的工具清单 | 从 7 个变 8 个 ⇒ 同步改系统提示与断言工具数的门禁 |

**配置键**（沿用 house style，都给一键回退）：`agent.findings_max_bytes`（默认 **8192**）、
`agent.stall_rounds`（默认 **8**）、`agent.findings.enabled`（默认开）。

## 8. 待明确（实施前值得再确认的小点）

1. `record_findings` 的参数名与形状定稿（本文 §4.2 是提案）；
2. 落盘文件是**一会话一份**还是**一 run 一份**（会话复用时怎么续）；
3. 是否给用户一条"清空本会话 findings"的命令（**给**，但只清提示词里的 active 视图、
   不动落盘文件 —— 与"不物理删除"一致）；
4. 停滞守卫的计时是否也把"反复读同一个文件"单独计一分（这轮先不叠加，避免两个守卫互相掩盖）；
5. findings 是否随会话 `SessionMsg` 一起持久化（**是**，否则重开会话就看不见模型当时确认了什么）。
