# 问题：验证的 `__pycache__` 改道撞上 MAX_PATH，被读成「语法/编译错误」

> 归属版本：v1.4（P0 最小评测台**第一次真跑**时发现）· 2026-09-28
> 状态：**已登记，未修**（修它要动 `crates/harness-engine/src/verify.rs`，属引擎改动 ⇒ 等拍板）
> 复现：`rsi_bench --self-check`（含「落点太深 ⇒ 跑之前拒绝」那条）+ `RSI_KEEP=1` 保留现场；
> 当时那两个一次性脚本**已删**（2026-09-30），步骤在本文 §5 里写全

## 1. 现象

脚本化臂里，模型**写对**了 `calc.py`（`write calc.py（32 字节）` + 窄层检查 1 项全过），
第 2 轮交 `final` 时被打回：

```text
[warn] [agent] 第 2 轮交付被打回：[机械验证·全量验证] 未通过：1 项失败（首个：calc.py 退出码 Some(1)）
✗ syntax calc.py：退出码 Some(1)
- calc.py（python）：退出码 Some(1)
  语法/编译错误，先改这个再谈测试
```

模型于是被迫再改一轮（脚本化臂没有第三轮 ⇒ 整轮变成「无效」）。实测**18/18 轮全被打回**，
而同一份夹具、同一个剧本、换成另一个落点就**全过**。

## 2. 机理

`verify.rs` 的 python 语法检查是 `<python_bin> -m py_compile <文件>`，并且为了"跑完仓库干净"
把字节码改道：

```rust
fn py_envs(dirs: &VerifyDirs) -> [(&'static str, &str); 2] {
    [("PYTHONIOENCODING", "utf-8"), ("PYTHONPYCACHEPREFIX", dirs.pycache.as_str())]
}
```

CPython 对 `PYTHONPYCACHEPREFIX` 的行为是：把**源码的绝对路径镜像**到那个前缀底下。于是

```text
pyc 真实路径 = <前缀>  +  镜像的<源码绝对路径>  +  __pycache__/<名字>.cpython-311.pyc
```

长度 ≈ **2 × 落点深度 + 常数**。越过 Windows 的 260 ⇒

```text
[WinError 206] 文件名或扩展名太长。: 'C:\...\pycache'
exit=1
```

`py_compile` 退出 1 ⇒ `CheckResult::from_output` 判「语法/编译错误」⇒ 门禁**打回 final**。

## 3. 两个触发条件（都实测过）

| # | 条件 | 实测 | 估算 |
|---|---|---|---|
| 1 | 落点**很深**（例如深层临时目录） | 自检里的长临时目录：写对了也 12/12 打回 | pyc ≈ 325 字符 |
| 2 | **状态根是相对路径** | `--out target/rsi-bench-rep-a`（相对）⇒ 18/18 打回；改成绝对路径 ⇒ 全过 | 相对前缀在 python 的 cwd（= 项目目录）下解析，再与绝对源码镜像拼接 ⇒ 长度翻倍 |

第 2 条是**宿主也能踩**的：`AppConfig::project_state_root` 若是相对路径，就会命中。
ruyix 宿主一直给绝对路径（`<便携根>/projects/<键>`），所以线上没炸；引擎作为库没守住这条。

## 4. 危害（为什么值得单独记一笔）

**尺子坏了装成读数。** 引擎给出的是一条**代码结论**（「语法/编译错误」），而真实原因是**环境**
（路径太长）。后果三连：

1. 模型被误导着去"修语法"，白烧轮次；
2. 评测台把一次写对的改动读成"这版更差"（奖励劫持的反面：**假红**）；
3. 真用户的便携根一旦够深，正常的改动会被判成语法错。

## 5. 建议方案（待拍板）

| 方案 | 内容 | 代价 |
|---|---|---|
| **(a) 换掉 py_compile**（推荐） | 语法检查改 `python -c "import ast,sys;ast.parse(open(sys.argv[1],encoding='utf-8').read())"` —— **不写任何文件** ⇒ 没有 pycache ⇒ 没有长度问题，也不用再清理 | 比 py_compile 少一层"能编译成字节码"的保证（语法层面等价；字节码写盘从来不是这条检查的目的） |
| (b) 前缀改短 | `PYTHONPYCACHEPREFIX` 指到系统临时目录下的短名（`rsib-pyc-<hash>`） | 多一处需要清理的临时目录；治标 |
| (c) 兜底 fail-closed | `verify` 要求状态根是**绝对**路径，且估算的 pyc 路径超限时如实报「环境不支持（路径过长）」而不是报语法错 | 不修根因，但保证"坏尺子报没有读数" |

倾向：**(a) 为主 + (c) 兜底**；(c) 单独也值得做 —— 它保证这类病再也不装成读数。
