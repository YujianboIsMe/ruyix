# 评测台：最小形状（v1.4 P0）

> 归属版本：v1.4（`doc/v1.4/需求-递归自我改进-v1.4.md` §1.1 的前置依赖、§8 P0）
> 实现：`crates/harness-engine/examples/rsi_bench.rs`（自检 **12 条**：`--self-check`）
> 夹具：`crates/harness-engine/tests/fixtures/rsi_bench_demo/`（**4** 个任务：2 正 + 1 负样本 + 1 白名单边界；两条臂都开 `write_allow`）
> 状态：**可用**（脚本化臂与真模型臂都在；一条真跑读数见 §6）

## 1. 它回答什么

**「这版 harness 比上版强吗？」** —— 此前这个问题在本仓库**没有任何数**。单测证明的是机制成立；
真 run 的成功率没有对照臂。所以先把尺子做出来，再谈自改（判据 7：无信号不采纳）。

## 2. 形状

```text
<任务集>/<任务 id>/
  task.toml      # prompt / expect / judge / tier / notes + [fake] 剧本
  seed/          # 跑之前铺进沙箱项目的夹具（两臂同一份，指纹写进记录）
  judge/         # 判据脚本（拷到 run 目录，**沙箱项目之外** ⇒ agent 看不见）

<臂目录>/
  plugins/tools/<id>/tools.toml   # [[discover]] 行（引擎侧真消费）+ [[pm]] 行（只对宿主生效）
  bench.toml                      # 数值覆盖（L1）：[agent] / [discover] / [reflect] / [gate] …

读数落点 <out>/ = raw-<臂>.json（逐轮原始值）· report.md（人读表）· receipt.json（本轮完整账）
```

### 2.1 `task.toml`

```toml
prompt = "交给 agent 的任务描述（原样进首条用户消息）"
expect = "pass"        # pass（默认）：判据必须通过；fail = 负样本：判据必须**仍不通过**
tier   = "smoke"       # smoke / full（分档跑子集的挂点）
notes  = "这条任务在测什么（人读）"

[judge]
cmd = "python {judge}/check.py"   # {judge}=判据目录（run 目录下） {project}=沙箱项目；cwd = 沙箱项目
timeout_secs = 60

[fake]                 # 只在 --fake（脚本化臂）下用；结构写、不手写转义 JSON
final_text = "…"
[[fake.turn]]
write = [{ path = "calc.py", content = """
def add(a, b):
    return a + b
""" }]
```

### 2.2 判据契约（**0 = 通过，1 = 不通过，其它 = 判据自己坏了**）

第三条是关键：判据写错路径时 python 回 2，那一轮就被记成「候选更差」—— 坏掉的尺子冒充测量结果。
所以 0/1 之外的退出码、超时、起不来，一律记 **invalid**（这一轮**没有读数**），并把输出原文留在记录里。

判据脚本放 `judge/` 并被拷到**项目之外**：agent 连看都看不到考卷（比 P1 的"只读"更强，P0 就成立）。

### 2.3 臂：一臂一进程

`discover::register_extra` 是**追加语义的进程级表**。两臂同进程 ⇒ A 的工具行会留给 B 看，
读数就不再是两臂之差。所以驱动器为每条臂起一个子进程（同 v1.2 配对脚手架的形状）。

**臂不许挑模型**：`bench.toml` 里出现 `[llm]` / `[llm_fallback]` 直接报错并指名文件 ——
被测的东西不能自己选自己的工具，否则读数无从解释。温度也由驱动器给（判据 3：两臂同温度）。

**覆盖非空但一个键都没生效 ⇒ 报错**：拼错一个键的效果与"这条自改什么都没改"在读数上无法区分，
而真实的病是**它根本没跑**（看起来像被门槛拦了，其实压根没试）。所以先绝对化落点、再核验生效
配置与基线**逐字节不同**（生效配置的指纹是**脱敏**后算的，密钥不进读数）。

## 3. 三条自保（对应需求 §1.2 与 §2）

| 自保 | 做法 | 自检里的断言 |
|---|---|---|
| 考卷不可改（判据 2） | 跑前跑后各算一次整棵树的 sha256，变了 ⇒ 本轮**作废**并**指名**是哪个文件（改/新增/删除） | 「考卷变过 ⇒ 指纹变 + 指名到文件」 |
| 无效轮剔除而非当 0（判据 3） | `invalid` / `skipped_budget` 逐条留痕；有效轮占比 < 60% ⇒ **不出裁决**（记「不可判定」） | 端到端产出 `receipt.json` 里可见 |
| 无信号不采纳（判据 7） | 取**中位数**，差额 ≤ `MARGIN`（默认 5 pp）⇒ **拒绝** | 夹具两臂差额 0.0 pp ⇒ 裁决 = 拒绝 |

外加一条**环境自保**：落点太深 ⇒ **跑之前拒绝**（见 §5）。

## 4. 用法

```bash
# 自检（12 条不变量，零成本；CI 可直接跑）
cargo run -q -p harness-engine --example rsi_bench -- --self-check

# 脚本化臂（零成本、确定性；只证明管道与统计）
cargo run -q -p harness-engine --example rsi_bench -- --fake --rounds 3

# 真模型臂（唯一能产出功效结论的形态）
cargo run -q -p harness-engine --example rsi_bench -- \
    --tasks <便携根>/projects/rsi/tasks \
    --arm <…>/arms/baseline --arm <…>/arms/candidate \
    --config target/debug/global/ai.toml --model deepseek-v4-flash \
    --rounds 3 --out <便携根>/projects/rsi/arms --budget-secs 3600
```

退出码：`0` 有裁决 · `3` 作废/不可判定 · `2` 参数或环境错误。

## 5. 环境自保：落点太深 ⇒ 跑之前拒绝

`verify` 用 `PYTHONPYCACHEPREFIX` 把 `__pycache__` 改道到状态桶，而 CPython 会把**源码的绝对路径
镜像**到那个前缀底下 ⇒ pyc 真实路径 ≈ **2 × 落点深度 + 常数**。越过 Windows 的 260，
`py_compile` 报 `[WinError 206]` 退出 1，被引擎读成「语法/编译错误」并**打回 final**。

实测（同一份夹具、同一个剧本）：

| 落点 | 结果 |
|---|---|
| `%TEMP%/rsi-bench-selfcheck-e2e-<pid>-<纳秒>`（长） | 12/12 打回 |
| `--out target/rsi-bench-rep-a`（**相对**路径） | 18/18 打回 |
| `--out /d/…/target/rsi-bench-abs`（绝对、短） | 全过 |

所以评测台：① `--out` 一律**绝对化**（相对路径会让前缀在 python 的 cwd 下二次解析，长度翻倍）；
② 估算 pyc 路径 > 250 ⇒ **拒绝并说明**，而不是出一份被假红污染的读数。
**判据脚本自己会留 `__pycache__`**（它 import 被测模块）：那是判据写的、落在沙盒副本里，
不是 verify 写的 —— 判据若要断言"目录里有什么"，别拿整棵树当白名单比对。

> **2026-10-08 收口（真跑抓出）**：路径闸原先还加了一项"`state/verify/pycache` ＋ 镜像的源码绝对
> 路径"——那是 `PYTHONPYCACHEPREFIX` 的镜像行为，A-5 之后**已经不写了**。留着它把真实便携根
> （键 `D-Projects-Rust-ruyix`）估成 **259 > 250 而拒跑**，可那个世界跑得动。估算已按事实改成
> "项目里的文件 + 原处 `__pycache__`"（实测 148/250），并且这条闸的自检判据**两个方向都钉**
> （原先只有拒绝方向 ⇒ 越保守越绿，真跑时才知道开不了）。现场与另两个缺陷见
> `doc/v1.4/问题-RSI世界在真实便携根跑不起来.md`。

完整机理见 `doc/v1.4/问题-验证pycache改道撞MAX_PATH.md`；**引擎侧已修**（2026-10-08 A-5：语法检查换
`ast.parse`、语法环境加 `PYTHONDONTWRITEBYTECODE`、越限报「环境不支持」）。这里这条闸**保留**，
但理由更新了：它不再防"假红打回 final"，而是**兜底**（别把一整轮烧在注定失败的环境上）。

## 7. 这一版**不能**声称的

- 脚本化臂的数字只说明"管道通、统计对"；**模型行为一点没测到**（`--fake` 的报表里明确写着这句）。
- 任务集只有 3 个任务（2 正 1 负）：**只够看大差异**，单任务层面的胜负不能外推。
- 判据能证明"这几条行为对/不对"，不能证明"这个 harness 整体更强"。
- 真 baseline 的读数要用真模型、多轮、更多任务跑出来 —— 那是 P2 的前置。
