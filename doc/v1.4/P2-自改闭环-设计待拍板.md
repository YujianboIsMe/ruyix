## 1. 一轮自改长什么样（固定形状）

```text
<便携根>/projects/<rsi 键>/rsi/
  allow.toml          # 白名单 + 预算（人写；驱动器**只读**）
  tasks/              # 冻结考卷（P0 格式；驱动器与 agent 都**只读**，跑前跑后算哈希）
  arms/
    baseline/         # 基准臂 = 现状数据面的**副本**（驱动器自动生成）
    round-1/          # 候选臂 = 提议步改出来的那份副本
  receipts/round-1.json   # 一轮完整账：动机 / 证据 / 前后读数 / 回滚点 / 裁决
  out/round-1.patch       # 候选的 diff（**人合并**；驱动器绝不自动进主干）
```

一轮 = 三步，每步都有可判定产物：

| 步 | 谁做 | 输入 | 产物 | 判据 |
|---|---|---|---|---|
| **① 提议** | agent（在**副本**上） | 数据面副本 + 上一轮读数 + 允许改的面 | 改过的副本 | 白名单外写入被拒（P1 闸）；改动只落在副本里 |
| **② 配对测** | 驱动器 | 现存的 `arms/baseline` 与新 `arms/round-N` + 冻结任务集 | `raw-*.json` / `report.md` / `receipt.json` | 判据 3（同任务集/同温度/同轮数、逐轮原始值、无效轮剔除）、判据 2（考卷哈希锁） |
| **③ 判定与产物** | 驱动器 | ② 的读数 | `out/round-N.patch` + `receipts/round-N.json` | 判据 4（提升 > MARGIN 且既有门禁全绿）、6（可回滚）、7（无信号不采纳） |

**人合并**（判据 3 的落实）：③ 只写 `patch` 与 `receipt`，**永不**写进便携根的 `plugins/`。
人看完 receipt 决定合不合；合完的下一步才把 `arms/round-N` 提升成新的 `arms/baseline`。

## 2. 提议步跑在哪（**待拍板**，三个候选）

这一条是唯一需要新代码形状的决定 —— 因为它决定"谁给 agent 起 run"。

| 候选 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **(A) 会话里由人驱动**（推荐先做） | 人在 ruyix 会话里说"按上一轮读数改 X"，agent 用现成的四原语在**副本**上改；驱动器只负责"建副本 / 算 diff / 跑尺子 / 出 patch" | **零新代码**（会话与副本都是现成的）；人能当场看住方向；判据 5（负样本回归）天然有人验收 | 不是"自动",每轮要点一次；"递归"停在人这一环（v1.4 本来就是这样） |
| (B) 评测台加 `--propose` | `rsi_bench --propose --surfaces <副本> --task "…"` 用引擎循环跑一次提议，产物就是改过的副本 | 一条命令一整轮；可进 cron/循环 | 要把"提议"的提示词与上下文也做成数据（提示词片段面目前**还没有加载点**）；等于让测量工具兼任驱动器 |
| (C) 宿主加命令 | 宿主加 `rsi_round` 之类的 Tauri 命令，UI 上点一下跑一轮 | 最终形态 | 最大的一步；且它把 RSI 机制搬进宿主源码 —— 需求 §4.1 明确说落点在**用户侧** |

我的建议：**先 A，把 ②③ 做成脚本**。理由：②③ 才是这一版的骨头（读数、门槛、patch、receipt），
而 ① 用现成机制就够了；A 做完跑通两轮之后，(B)/(C) 只是"把同一件事自动化"，
而且那时才有资格谈要不要把 ① 也交出去（判据 1.1：没有可信信号之前不加自动化）。

## 3. ②③ 的驱动器（无论选哪个候选都要做）

一个零依赖脚本（Python 或 bash，与仓库既有 `scripts/*.js` 同风格：不加 npm/pip 依赖），职责：

1. **只读** `allow.toml` / `tasks/`（缺 `allow.toml` 或缺任务 ⇒ **拒绝开跑**，不猜默认值）；
2. 建 `arms/baseline`（现状数据面的副本）与 `arms/round-N`（提议后的副本）；
3. 跑 `rsi_bench --arm baseline --arm round-N --tasks <…> --rounds N --out arms/`；
4. 读 `receipt.json`：`decision` 非"候选更优" ⇒ 写 receipt 后**到此为止**（判据 7）；
5. 是"候选更优" ⇒ 生成 `out/round-N.patch`（对数据面副本做 `git diff --no-index` 或逐文件对照）
   + `receipts/round-N.json`（动机 / 证据 / 前后读数 / 回滚点 = 副本的哈希 / 裁决）；
6. **绝不**写便携根的 `plugins/`。

驱动器要过的既有门禁（判据 4 的"且既有门禁全绿"）：`cargo test`、`cargo clippy`、
`ui-smoke`、三个几何探针 —— 与自改无关的那些门禁**仍须为绿**，否则不出 patch。

## 4. 判据逐条怎么落

| 判据（需求 §6） | 落实 |
|---|---|
| 3 配对两臂 | `rsi_bench` 已经是一臂一进程、同任务集、同温度、同轮数；逐轮原始值在 `raw-<臂>.json`，无效轮逐条留痕 |
| 4 采纳门槛 | `MARGIN` 已内建（默认 5 pp，"候选更优"才出 patch）；既有门禁由驱动器跑一遍再放行 |
| 5 负样本回归 | 任务集里已有的 `expect=fail` 任务每轮都跑（P0 夹具里那条就是样板）；候选在它上面"通过" ⇒ 记 `wrong` 并报警 |
| 6 可回滚 | `arms/round-N` 与 `out/round-N.patch` 都在用户侧；receipt 里记副本哈希 + 前一轮读数 ⇒ `git checkout`/删目录都能回到改前 |
| 7 无信号不采纳 | 差额 ≤ MARGIN ⇒ 写 receipt 明说"无信号 ⇒ 拒绝"，不产 patch |
| 2 考卷不可改 | 任务集哈希锁已在跑器里；驱动器**只读** `tasks/`，且它自己不写 `tasks/`（fs 只读权限层面也能再兜一层） |
