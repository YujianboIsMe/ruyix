# P1：写入白名单与只读边界（v1.4）

> 归属版本：v1.4（`doc/v1.4/需求-递归自我改进-v1.4.md` §6 判据 1/2、§8 P1）
> 状态：**已落**（引擎闸 + 4 条单测 + 评测台边界任务；宿主 config 表单暂未列这个键，理由见 §5）
> 判据复现：`cargo test -p harness-engine --lib agent::tests::read_write::` 与
> `cargo run -q -p harness-engine --example rsi_bench -- --self-check`

## 1. 这条闸要防什么

自改闭环让 agent 去改**驱动它自己的数据面**（工具表 / 提示词片段 / 技能文档 / lint 规则）。
一旦它能改任意文件，闭环立刻退化成两种坏法（需求 §2）：**奖励劫持**（改判据、删任务）与
**越界破坏**（改别人的项目、改用户配置、改源码）。

所以：**白名单外一律拒绝，而且必须是引擎在落盘之前拒绝** —— 提示词里写「请不要改别的文件」
属于礼貌劝阻，不是边界（需求 §1.2 ②）。

## 2. 形状

| 位置 | 内容 |
|---|---|
| 引擎配置 | `ruyix.code.harness.agent.write_allow`（引擎侧字段 `AppConfig.agent.write_allow: Vec<String>`） |
| 语义 | **空 = 不启用**（出厂默认，老行为逐字节不变）；非空 = 只放行匹配的**项目内相对路径** |
| 模式 | `/` 分段；段内 `*` = 任意字符（不跨 `/`）、`?` = 一个字符；整段 `**` = 任意层级（含零段）。**大小写敏感**（宁严不宽） |
| 例 | `plugins/tools/*/tools.toml` · `plugins/prompts/**` · `*.py` |
| 用户侧清单 | P2 的驱动器读 `<便携根>/projects/<rsi 键>/rsi/allow.toml` 后填进这个字段（本期先由评测台的 `bench.toml` 提供，见 §4） |

拒绝理由（**具体**，模型据此一轮就能改对）：

```text
写 global/ai.toml 被拒：它**不在本 run 的写入白名单内**（白名单 2 条：plugins/tools/*/tools.toml、*.md）。
引擎在解析内容与落盘**之前**拒绝 —— 磁盘、备份、覆盖层都没有这次改动。
白名单外的改动一律不许：改成白名单内的路径，或者如实报告做不到。
```

## 3. 闸装在哪（两个入口，缺一不可）

| 入口 | 位置 | 为什么 |
|---|---|---|
| 单动作 | `Ctx::apply_write`（`agent/tools.rs`） | 正式入口：解析内容 → 落盘/暂存 |
| **并发波** | `dispatch::run_wave` 里的写分支 | 它**绕开了** `apply_write`（自己 `resolve_write` + `flush_write_disk`）—— 只装一处就会留后门 |

注入点：`tool_loop.rs` 建 `Ctx` 时带上 `cfg.agent.write_allow`。**step 子 agent 借的是同一个
`&mut Ctx`**，所以子步骤自动受同一条闸约束，不需要第二套机制（v0.4 的设计红利）。

## 5. 已知边界（**如实说**，别当成已经解决）

1. **`execute` 不受这条闸管**：它是「绊线不是沙箱」（只有破坏性模式拒绝清单）。一条
   `python -c "open('x','w')"` 照样能写。这是**故意的取舍**（把 execute 关掉 = 自改跑不了评测），
   真正的不越界靠**把 run 放在一份副本里跑**：P2 的驱动器给 agent 的项目目录是
   `plugins/` + `skills.toml` 等数据面的**副本**，run 完只把白名单内的 diff 应用回便携根。
   那条路做完之后，「越界」连可写的对象都不存在。
2. **宿主 config 表单暂未列这个键**：它是给 RSI 驱动器用的，手填没有意义（P2 会由驱动器从
   `allow.toml` 注入）。要手填也能配 —— 引擎侧字段已就位，`bench.toml` 与三 scope 配置都能设它。
3. **模式是「路径字面量」匹配**：不解析符号链接、不做大小写折叠、不认 `~`。这些都是
   **fail-closed 方向**的取舍（宁可拒了合法路径，也不要放过一条没认出来的）。
