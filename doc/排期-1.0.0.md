# 排期：v1.0.0（便携根 + 项目状态搬迁 + zip 发行）

**上游**：`doc/需求-便携形态与零残留-v1.0.0.md`（R1–R14 / A1–A12）· `doc/架构-便携根与项目状态搬迁-v1.0.0.md`
**目标**：exe 同目录 = 唯一根；全局与项目状态全在根内；**用户仓库零写入**；
发行物是 zip（纯 exe 也能跑）；卸载 = 删文件夹。
**完成定义（DoD）**：A1–A12 全绿（没绿要进 release 的"已知问题"）+ `doc/release-v1.0.0.md`（中英双语）
+ tag `v1.0.0` + 分支 `1.0.0` 快照（沿用"主干 master 开发、版本分支只作快照"的惯例）。

> **旗舰判据**（这一版真正值钱的东西）：
> **A3/A4 —— 打开项目、跑完一轮 agent（暂存 + 交付 + 起服务 + 验证）之后，
> 用户仓库里没有 `.ruyix`，`git status` 只剩用户自己的改动。**
> 建议把它放在发布门槛的第一条：它一条就覆盖了"零残留"的大半。

## 二、逐阶段：做什么、判据、风险、回退

### P0 探针与判据设计（1 天）—— 唯一的"未知数闸门"

| 项 | 内容 | 判据 |
|---|---|---|
| 探针 1 | Tauri v2 能否指定 WebView2 data directory？用哪个 API？指定后启动正常吗？ | 指定临时目录后启动成功，且 `%LOCALAPPDATA%` 下不新增 ruyix 数据 |
| 探针 2 | mutex 名字加根 hash 后，两份解压副本能否并存；data dir 与 mutex 是否耦合 | 两份副本各起一个、各自可用 |
| 设计 | A3/A4「仓库干净」怎么跑才可信（场景脚本：打开项目 → agent 暂存一次 + 交付一次 → 起托管进程 → 跑一次验证 → 收尾） | 场景写进 `scripts/`（可重复跑，输出 `git status --porcelain` 与 `find . -name .ruyix` 的原始结果） |
| 落点 | 探针结论写回架构文档 §八/§十一，**带命令与原始输出** | 文档里能看见"实测过" |
| 风险 | Tauri 本体不支持 → 退路 `WEBVIEW2_USER_DATA_FOLDER`（建窗口前设），或明确宣布"WebView2 缓存不入根"并在 release 写清 |

### P1 路径收敛（1.5–2 天）

- `paths.rs`：`Paths` 门面（架构 §二）+ `discover`（§三）+ `project_key`（§五）+ 表驱动单测；
- 替换全局 8 处（`main.rs:67`、`config.rs:236/845/857`、`mcp.rs:53/62`、`a2a.rs:51/60`、`capability.rs:27/36`、`agent/config_bridge.rs:69`）；
- 引擎侧：`config.rs:41` 默认值、`:965-974` 相对根、**新增 `project_state_root` 注入字段**（架构 §二末）；
- **判据**：单测全绿；静态门禁（`home_dir()` 只许 `paths.rs` / 引擎 `expand_home`）；全仓无 `.darkhorse`；现有门禁零回归；
- **回退**：这是纯收敛（行为等价），任一判据红就回退单文件，不许顺手改行为。

### P2 便携根与目录模板（1 天）

- 首启按模板建 `config/`、`data/`（含 `logs/`、`cache/`、`webview/`）、`plugins/highlight/`，各带 README；`config/` 带最小可用模板（**只放注释与空壳，不放示例密钥**）；
- 边界按架构 §三 表实现（只读 → 拒绝启动 + 人话；临时目录 → 提醒但不阻断）；
- `--debug` 会话头打印 `根=… | 可写=… | webview=…`；
- **判据**：A1、A2、R13（两种边界摆放各跑一次）。

### P3 项目状态搬迁（2–2.5 天）—— **这一版最容易出事故的一段**

按架构 §六 的七条逐条做，**每条都配一个判据**：

| 改哪 | 判据 |
|---|---|
| ① 项目配置根（`config.rs:911`） | 在项目里改一次项目作用域配置 → 落 `config/projects/<key>/`；用户仓库无新文件 |
| ② 暂存 + 备份（`stage.rs`、`apply.rs`、`engine/agent.rs`） | 确认模式跑一轮 → 暂存在 `data/<key>/stage/`；交付覆盖已有文件 → 备份在 `data/<key>/backups/` |
| ③ 进程日志（`engine/proc.rs:211`） | 起一个托管进程 → 日志在 `data/<key>/proc/`；服务面板仍能读尾 |
| ④ 环境留痕（`env_setup.rs:241`） | 触发一次安装动作 → `data/<key>/env/installs.jsonl` 多一行 |
| ⑤ 会话存档（`sessions.rs:123`） | 新建会话 → `data/<key>/sessions/*.json`；重开仍能载入 |
| ⑥ verify 绝对路径（`verify.rs:495,528`） | 跑一次验证 → 产物在 `data/<key>/verify/`；跨盘也要能跑（实测一次） |
| ⑦ 提示词与文案（`engine/agent.rs:484,1465,1528`） | 全仓 grep `.ruyix/stage` 只剩历史/迁移语境；模型提示词里的路径与实际落点**逐字一致** |
| ⑧ 路径封闭规则（`stage.rs:30,103`） | 试图把产物写进 IDE 状态根 → 被拒（新单测；旧的"拒写 `.ruyix`"用例改成"拒写状态根"） |

- **回退**：P3 期间旧代码路径与新的可以短暂并存（开关或分支），**一旦 A3/A4 绿了就删掉旧路径**，不留两套；
- **风险**：最容易漏的是**读**路径（项目级 tools/skills/mcp/a2a 的读取），
  漏了会表现成"项目配置改了不生效 / 读了旧的"→ 所以每条都要"写一处、读一处"成对验证。

### P4 WebView2 data dir + 单实例（1 天，按 P0 结论）

- **判据**：A5（`%LOCALAPPDATA%` 不新增）、A11（两份副本并存各自正常）；
- **风险**：这两条必须同批 —— 只做一半会出现"第二个实例起不来、缓存却被共用"的更坏状态。

### P5 迁移（1 天）

- 全局：`~/.ruyix/code/**` → `config/`（`runs/` 默认不搬）+ `.migrated-from-legacy`；
- 项目：只搬 `code/*.toml`，其余（暂存/备份/日志/会话）默认不搬 + `.migrated-projects`；
- 用户仓库里剩下的 `.ruyix/`：提示"可以删了"，**用户显式同意才删**；
- **判据**：A10（导入一次、幂等、可拒绝、删旧目录需同意）；
- **回退**：删 `config/` 即回到未迁移；旧目录全程只读。

### P6 打包与元数据（1 天）

- `scripts/package-portable.js`（零依赖 Node，照 `check-style.js` 风格）：`cargo tauri build` → 收 exe → 放模板目录 → 写 `SHA256SUMS.txt` → 打 zip 到 `dist/`；用 `RUYIX_HOME` 指定中间目录；
- 元数据：`tauri.conf.json` 的 `productName → ruyix`、`version → 1.0.0`；两个 `Cargo.toml` 版本同步；`description`/`authors` 复核；
- **判据**：A9（一条命令出 zip、解压逐项齐全、sha256 可校验）、A8（属性页 `ruyix`/`1.0.0`）；
- **风险**：`productName` 改动会牵动 exe 文件名与窗口标题（有测试引用）→ 改完**跑全门禁**，别只看编译过。

### P7 验收与发布（0.5–1 天）

- 逐条跑 A1–A12 并留证据（命令 + 原始输出贴进验收记录）；没绿的进 release 的"已知问题"；
- `doc/release-v1.0.0.md`：中英双栏，照 `release-v0.0.5.md` 的格式，**必须写清"老用户怎么迁移"**；
- 更新 `README.md` 的下载章节（zip 布局 + 纯 exe 也能跑 + 卸载 = 删文件夹）；
- tag `v1.0.0` + 分支 `1.0.0`（快照）。

## 三、这一版明确不做

- 不做安装器（NSIS/MSI）、不做自动更新、不做多用户/服务化（便携版是单用户形态，文档写明）；
- **不实现插件加载**（只建 `plugins/`，加载见 `doc/需求-高亮插件化-v0.14.md`）；
- 不做"长期双根"（遗留目录只作一次性导入源）；
- 不改 agent 沙箱语义（`runs_root` 位置变，产物格式与隔离纪律不变）；
- 不自动删用户的任何东西（旧目录、孤儿状态都要显式同意）。
