## 二、逐阶段：做什么、判据、风险、回退

### P0 探针与接口定稿（1 天）—— **唯一的"未知数闸门"**

| 项 | 内容 |
|---|---|
| 探针 1 | **Tauri v2 能不能指定 WebView2 data directory**？怎么指定（`WebviewWindowBuilder` 的哪个 API）？指定后启动是否正常？ |
| 探针 2 | **两份副本各自指定不同 data dir，同时起两个实例**会怎样（现在的全局 mutex 会踢掉第二个；先确认 mutex 行为与 data dir 无耦合） |
| 判据 | 探针 1：指定 `<临时目录>/webview` 后启动成功，且 `%LOCALAPPDATA%` 下不新增 ruyix 数据；探针 2：把 mutex 名字临时改成带 hash，两份副本能同时跑 |
| 落点 | 结论写进架构文档 §六/§七（含"实测命令 + 原始输出"，不许只写结论） |
| 风险 | 若 Tauri 本体不支持 → 退路：用 `WEBVIEW2_USER_DATA_FOLDER` 环境变量（WebView2 官方支持）在建窗口前设，或接受"便携 = 配置/数据便携，WebView2 缓存除外"并在 release 里明说 |

### P1 路径收敛（1.5–2 天）

- 新建 `src-tauri/src/paths.rs`：`Paths` 门面（架构 §二）+ `discover`（架构 §三）+ **表驱动单测**；
- 按架构 §一 的清单逐处替换（`main.rs:67`、`config.rs:236/845/857/911`、`mcp.rs:53/62`、`a2a.rs:51/60`、
  `capability.rs:27/36`、`agent/config_bridge.rs:69`）；
- 引擎侧：`crates/harness-engine/src/config.rs:41` 默认值改到新布局、`:965-974` 相对路径改相对注入根（R7）；
- **判据**：① 表驱动单测全绿；② 静态门禁：全仓 `home_dir()` 只允许出现在 `paths.rs` 与引擎 `expand_home`；
  ③ 全仓无 `.darkhorse`；④ 现有门禁不回归（`cargo test` / `clippy --all-targets` 0 warning / `fmt --check` /
  `node scripts/ui-smoke.js` / `check-style`）；
- **回退**：这一阶段是纯收敛（行为等价），任何一条判据红了就回退该文件，不许"顺手改行为"。

### P2 便携模式与目录创建（1 天）

- `discover` 三态按架构 §三 实现；**只读目录**场景给人话报错；
- 首启按模板建 `config/`、`data/`、`plugins/`、`projects/`（含各自的 README；`config/` 带最小可用模板）；
- `--debug` 会话头打印 `根=… 模式=…`（这是 A2 的证据）；
- **判据**：删目录 → 启动 → 目录回来且程序可用，旧数据不动（R4）；三态各跑一次，日志里的根正确（A2）；
- **风险**：模板里别塞密钥/示例 key（会被人当默认值用）→ 模板只放注释与分节空壳。

### P3 WebView2 data dir + 单实例（1 天，按 P0 结论）

- 建窗口前设 data dir = `Paths::webview_data()`（便携模式；遗留模式保持 OS 默认）；
- mutex 名字带 `root` hash（架构 §七）；
- **判据**：便携模式启动后 `%LOCALAPPDATA%` 不新增 ruyix 数据（A3）；两份副本并存各自正常（A11/R11）；
- **风险**：data dir 与 mutex 必须同时按根隔离，只做一半会出现"第二个实例起不来但缓存又被共用"的更坏状态 → **两条一起做**。

### P4 迁移（0.5–1 天）

- 触发/动作/幂等/拒绝/失败处理全按架构 §五；
- **判据**：造遗留数据 → 便携首启 → 提示出现；导入后配置与项目列表齐；重复启动不二次导入；
  选"不导入"后仍可用且不再问（A8）；
- **回退**：删 `<root>/config` 即回到未迁移状态（旧目录始终只读不动）。

### P5 打包与元数据（1 天）

- `scripts/package-portable.js`（零依赖，Node，照 `check-style.js` 的风格）：`cargo tauri build` → 收 `ruyix.exe`
  → 拷模板目录 → 写 `SHA256SUMS.txt` → 打 zip 到 `dist/`；支持 `RUYIX_HOME` 指定中间目录（门禁不污染真实数据）；
- 元数据对齐（R8）：`tauri.conf.json` 的 `productName` → `ruyix`、`version` → `1.0.0`、
  `src-tauri/Cargo.toml` / `crates/harness-engine/Cargo.toml` 版本同步、`description`/`authors` 复核；
- **判据**：空 `target/` 起跑一条命令得到 zip；解压后逐项存在 + sha256 可校验（A6/A7）；exe 属性页显示 `ruyix` / `1.0.0`；
- **风险**：`productName` 改动会影响 exe 文件名与窗口标题（也有测试引用）→ 改完跑全门禁，别只看编译过。

### P6 验收与发布（0.5 天）

- 逐条跑 A1–A8 并**留证据**（命令 + 输出贴在发布记录里）；没绿的写进 release 的"已知问题"；
- 写 `doc/release-v1.0.0.md`（照 `release-v0.0.5.md` 的中英双栏格式：本版重点 / 还包含 / 下载与运行 / 已知问题 / 质量状态）；
- 更新 `README.md` 的"下载即用"章节（zip 布局 + 老用户迁移一句话）；
- 版本快照：tag `v1.0.0` + 分支 `1.0.0`（**只作快照，此后仍在 master 开发**）。

## 三、这一版明确不做（避免范围蔓延）

- 不做安装器（NSIS/MSI）、不做自动更新、不做多用户/服务化；
- **不实现插件加载**（只建 `plugins/` 与目录约定）——加载是 `doc/需求-高亮插件化-v0.14.md` 的事；
- 不动项目级 `<项目>/.ruyix/**` 的位置与语义；
- 不迁移 `~/.darkhorse/**` 的历史产物（那是老血统的临时目录，不承诺）；release 里说明一句即可。
