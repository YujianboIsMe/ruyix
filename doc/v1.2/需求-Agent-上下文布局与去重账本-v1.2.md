## 1. 症状与证据（全部来自真机 run，不是推测）

| 现象 | 证据 | 现状判据的错法 |
|---|---|---|
| 22 轮被**误判停滞**而终止 | `target/debug/global/logs/debug.log`：第 22 轮助手消息是 `git grep -n -E "^function \|^async function " -- ui/scripts/main.js`（**正在为拆分方案做调研**），同轮它已在调 `record_findings` 且 claim 为真 | "进展"只算 `read` 新区域 + findings + 写文件 ⇒ **`execute` 式调研（`git grep`）算零进展** |
| 40 轮同样被误判 | 同一日志：模型分块读 `main.js`、grep `state` 用法，第 38 轮触发守卫 | 同上（相邻窗口被当成"重复"是另一个更早的错法） |
| 相邻窗口被误判为"重复读" | 用户报障截图：`main.js (401-+400)`、`(801-+400)`… 八段**互不相交**，全被标记 | 区间相交做成闭区间 + 端点 off-by-one |
| findings 上限恒显示 `0.0KB` | 真机 trace：`findings 16 条 active / 7.4KB（上限 0.0KB）` | `Progress` 走派生 `Default` ⇒ `cap_bytes = 0`（规格写的是 8KB） |
| **每轮都在砸前缀缓存**（本轮新发现，最贵的一条） | 代码：`tool_loop.rs` 每轮重建 `msgs[0]`，把 findings/账本块**拼进 system 消息尾部** | 布局契约被违反：system 属**不可变根**，改它 ⇒ **其后所有缓存块失效**（LSC 定理 1） |

**一句话**：现在的"保留 N 轮 + 每轮折一点"是**规则堆出来的**（`keep_rounds=6→12`、字节 cap、停滞 K=8 ✗），
每一条都是拍的数字，彼此还会打架；而 LSC 把同一件事变成**有目标函数、有定理、有竞争比的调度问题** ✓。

## 2. 目标（抄 LSC 四条，逐条本地化成可测指标）

| # | 目标 | 本仓库的可测指标（真 run 上取，非仿真） |
|---|---|---|
| G1 | **前缀稳定**：最大化厂商前缀缓存复用 | 相邻两轮请求的**公共前缀字节数**占比；若厂商回报命中 token，以它为准（**未验证，先记为待测**） |
| G2 | **有界上下文**：prompt ≤ 预算 B | prompt token 的**上界**（p95）+ 是否出现被 `max_tokens` 截断（`finish_reason=length`） |
| G3 | **零冗余工具执行**：纯工具 + 资源版本未变 ⇒ 不执行第二次 | **重复工具调用次数**（同一规范化调用 key，且版本向量未变） |
| G4 | **事实无损可得**：被压掉的内容靠 **capsule 侧存**召回，**不靠重跑工具** | "为拿回已读内容而重跑工具"的次数；召回后的事实**与原文逐字节一致**（哈希比对） |

## 3. 不可协商的约束

1. **一个可执行文件 + `global/` + `projects/` + `plugins/`**；卸载 = 删目录；
2. **零新运行时依赖**（token 计量用已有的 `tokenizers`；不引入 Python 运行时）；
3. **绝不写入用户仓库**：capsule / 账本落在 `<便携根>/projects/<项目键>/ctx/`；
4. **不改历史**：被压掉的内容只退出上下文，账本与侧存**永久保留**（与记忆层"证据必须无损"同一条公理）；
5. **判据不许建在"逐字相同"上**（多线程浮点归约不定 ⇒ 只比**决策**，不比浮点）；
6. **可回滚**：一个开关关掉 ⇒ 行为与今天**一字不变**。

## 4. 方案轮廓（三块，按风险从低到高；**不搬仿真件**）

| 块 | 内容 | 为什么它治上述症状 |
|---|---|---|
| **① 布局契约 `[S][E][A]`** | 不可变根 S（system + 工具声明 + 任务原文）· 只追加梯子 E · 每步重建的易变尾 A；`align()` 把 region 对齐到块边界，免得"跨块"浪费掉不可变 token | 直接消掉"每轮砸缓存"（G1）——**纯结构改动、零算法风险** |
| **② 去重账本 `ContextLedger`** | 三件：**规范化**（`read("./a")≡read("a")`、省缺省参数）· **包含关系**（整文件读 ⇒ 区间读冗余）· **版本有效期**（纯工具 ∧ 版本向量一致才允许去重） | 替掉"区间相交"和"execute 不算进展"两条错法（G3）；判据从"我觉得像重复"变成**可证条件** |
| **③ 重基线调度 `RebaseScheduler`** | horizon 已知（**H = `MAX_STEPS` = 96**，与上游设定一致）⇒ 反向 DP + 每步 MPC 重规划；未知 ⇒ ski-rental（竞争比 `e/(e−1)≈1.582`） | 替掉 `keep_rounds` 那个拍出来的数字（G1/G2）；`keep_rounds` 降级为**安全下限**而非策略 |

**明确不搬**：上游的 surrogate tokenizer / compressor / cache 模型 / workload（那是**仿真台**，用于让实验只反映策略差异）；我们只**复用它的工作负载定义**做黄金测试（见 §5）。

**替换表**（搬进来必须换掉的三件）：

| 上游件 | 本仓库替换为 | 备注 |
|---|---|---|
| surrogate tokenizer | 真 tokenizer（`tokenizers` crate，已有依赖） | 取不到就退化为字节代理并**在 trace 里写明** |
| surrogate compressor | 先做**抽取式**（同上游思路：无 LLM 调用、确定性） | 是否上 LLM 摘要**另立需求**，不在本期 |
| 仿真 cache 模型 | 真实信号：厂商命中 token（若可得）/ 否则"前缀逐字节未变"代理 | **未验证**，方案里按"先测再定"处理 |

## 5. 判据（**预注册**：先写判读规则，再跑）

**黄金测试（移植是否成功的唯一硬标准）**
把上游 `experiments/` 的 synthetic 96 步工作负载跑一遍，**导出决策轨迹**（每步：执行 / 跳过 + 跳过的原因码），
Rust 端口在**同一输入序列**下必须对齐**同一条决策**（只比决策，不比字节）。

**真 run 实验**
- 标准题两道：① main.js 拆分方案（52 轮那次已成功，作**上界参照**）② 一个诊断题；
- 臂：`forced`（≈现状）· `fixed K`（≡ 保留 12 轮）· **LSC**；其余一字不改；每题 3 次取中位数，留逐轮原始值；
- 主判据：G3 **重复工具调用次数下降 ≥ 50%** 且 G4 **"为召回而重跑"次数下降 ≥ 50%**，同时 G2 不退化；
- **否定判据（写死）**：若 G1 公共前缀占比**下降**（说明布局改错了方向）⇒ 判该期方案失败，回滚到开关关掉的状态；
- 无效轮剔除（跑挂／超时不计 0）✅ 结论分「能声称／不能声称」。
