## 1. 目标形态：三个 region，三条不变式

请求体在**任何时刻**都是三段拼接：

```
[ S 不可变根 ][ E 只追加梯子 ][ A 每步重建的易变尾 ]
  system + 工具声明      压缩后的历史条目        本轮证据/账本/待办
  + 任务原文             （只追加、不就地改）
```

| 不变式 | 判据（可自动查） |
|---|---|
| **I1 S 字节不变** | 相邻两轮请求的 S 段 sha256 相等；S 一旦需要变，说明它被误当成了可变区 |
| **I2 E 只追加** | E 段是上一轮的**前缀**（`starts_with` 判定），压缩只能**追加一条 capsule 摘要**，不许改写既有条目 |
| **I3 A 可重建** | A 段丢弃后仅凭 S+E+侧存即可重建（**这一条正是"不靠重跑工具"的实现**） |

> 现状违反 I1：`tool_loop.rs` 每轮重建 `msgs[0]`，把 findings/账本拼进 system ⇒ 每轮作废整段前缀缓存。
> 这是本期**第一个要挪**的东西，且不需要任何算法。

## 3. `ContextLedger`：去重与有效性的三件套

```rust
/// 一次调用的规范化键（**规范化是去重的前提**）
struct CallKey { tool: Tool, norm_args: String }

/// 一条账本记录（只增不改）
struct LedgerEntry {
    key: CallKey,
    digest: u64,            // 结果摘要（用于"同一结果"的判定与 trace）
    result_ref: Ref,        // → capsule 侧存：全量结果**永不丢**
    version: VersionVec,    // 该调用读到的资源版本
    step: u32,
}

/// 资源版本向量（保守：拿不到就不许去重）
struct VersionVec { entries: Vec<(ResourceId, VersionTag)> }
```

**三件套（逐条对应上游机制，逐条可测）**

| 机制 | 本仓库做法 | 拒绝/接受的规则 |
|---|---|---|
| **规范化** | 路径归一（`./a` → `a`、大小写按平台、分隔符统一）；省缺省参数（`limit`/`offset` 缺省即默认值，不产生新 key）；`execute` 命令去掉首尾空白与 `2>nul` 这类无副作用重定向 | 归一只做**语义等价**的变换；模棱两可 ⇒ **不归一**（宁可多执行一次） |
| **包含关系** | 整文件读 **⊇** 该文件的任何区间读；`grep -n X` **⊇** `grep -n X -- 子路径`（同一版本） | 只有**版本一致**时才允许"用整份顶替片段" |
| **版本有效期** | 资源版本 = 文件 `(mtime, size, sha256)`；仓库级 = `git HEAD + 工作树 dirty`；进程/端口 = 进程表指纹；环境 = 关键工具版本表 | **纯工具**白名单内的调用才可去重；白名单外**一律执行**；版本拿不到 ⇒ **执行**（fail-safe） |

**纯工具白名单（起步集，写进配置，可扩）**：`read`（永远纯）· `execute` 中 `git grep` / `git log` / `git status` / `dir` / `ls` / `findstr` / `type` / `cat` / `where` / `node -e`（**只读脚本**，保守起见先**排除**）· `connect` 的 `list`；
**一律不纯**：`write` · `execute` 里任何构建/安装/服务/写文件 · `connect` 的 `call`。

> 设计取向：**宁可多执行一次，也不许"看起来一样就跳过"**。去重是性能优化，不是正确性优化——这个方向反了会静默给出错答案。

## 4. 去重命中时的**行为**（不能只"跳过"）

命中 ⇒ **不执行**，但必须：① 返回**上次的真实结果**（从 capsule 读，逐字节一致）；② 结果尾部附一行
`（第 N 轮已执行过同一纯调用，资源版本未变；本次直接复用，未重跑）`；③ 记 trace 行 `dedup <tool> <norm_args>`。
—— 模型必须**知道**自己看到的是复用结果，否则它会怀疑"是不是没执行成功"从而再试一次（实测正是这个循环）。

## 5. Capsule 侧存（G4 的物理基础）

- 位置：`<便携根>/projects/<项目键>/ctx/<run-id>/`（**绝不写用户仓库**）；
- 形状：`<step>-<tool>-<hash>.txt` 全量结果 + 一条 JSONL 索引（`key / digest / path / step / version`）；
- 读回：把该目录加入 `read` 工具的**只读白名单例外**（与 findings 落盘同一处例外，必须写在同一段注释里）；
- 生命周期：与 run 同寿；`projects/<键>/` 随项目走，删项目即删；
- 判据：召回内容与原文 **sha256 相等**（这是"无损"的唯一证明）。

## 6. Token 计量与缓存真值

| | 做法 | 降级 |
|---|---|---|
| token | 真 tokenizer（`tokenizers` crate，已有依赖；whisper 那套用法可参考） | 取不到模型文件 ⇒ 字节代理，**trace 里写明"代理计量"** |
| 缓存 | 真值 = 厂商回报的命中 token（**未验证**） | 代理 = 相邻两轮公共前缀字节占比；两种都记 trace，**不混用** |

预算 B 的取值：由 `max_tokens` 与上下文窗口共同推出，**写进配置**（`agent.ctx.budget_tokens`），默认取窗口的 60%。

## 7. `RebaseScheduler`（什么时候压缩）

- **入参**：horizon（H=96）· 当前 ladder 大小 · 预算 B · 每步预计新增 token · 缓存的"用 vs 重建"代价比；
- **已知 horizon**：反向 DP 求最优重基线点 + 每步 MPC 重规划（上游同法）；
- **未知 horizon**：ski-rental（竞争比 `e/(e−1)`）；本仓库 H 已知 ⇒ 主路径是 DP，ski-rental 作为**兜底**（`max_elapsed_secs` 提前终止时 horizon 会变）；
- **触发下限**：无论调度器说什么，都不得低于 `history_keep_rounds`（安全下限，门禁 ≥10）；
- **可观测**：每次决策记 trace：`rebase 决策=执行/跳过 理由=DP|ski-rental|下限 预计省 X 字节`。
