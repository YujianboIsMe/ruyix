# 编码规范（Google 风格）

本项目的代码风格依据 **Google 的语言风格指南**。Rust 没有独立的 Google 风格文档，
Google 内部采用 **Fuchsia Rust style guide**，而它本质就是 **rustfmt 默认风格**，
所以 Rust 侧一律交给 `cargo fmt` 处理。

| 层 | 依据 | 门禁命令 |
|---|---|---|
| Rust | Google / Fuchsia Rust style guide（= rustfmt 默认风格 + 命名约定） | `cargo fmt --check` |
| JavaScript | Google JavaScript Style Guide | `node scripts/check-style.js` |
| HTML / CSS | Google HTML/CSS Style Guide | 同上 |
| JSON（i18n 等） | Google JSON Style Guide | 同上 |

## 开发流程

1. **直接在 `master` 上开发**，不再开特性分支
2. `0.0.x` 等分支只作为**版本备份/快照**，不再往上提交新改动
3. 提交信息格式：`<type>: <中文描述>`，type 取 `feat` / `fix` / `docs` / `chore` / `refactor`
4. 提交前跑一遍门禁（见文末），全绿再提交

## Rust

**自动格式化**（`rustfmt.toml`，只放 stable 参数）：

```toml
max_width = 100
use_field_init_shorthand = true
use_try_shorthand = true
```

其余保持 rustfmt 默认值。**不要手工对齐**，写完直接 `cargo fmt`。

命名（Google Rust 风格）：

| 对象 | 约定 | 例 |
|---|---|---|
| 类型 / trait / enum | `UpperCamelCase` | `RunTarget`、`GitStatus` |
| 函数 / 变量 / 模块 / 文件名 | `snake_case` | `resolve_run_dir`、`git.rs` |
| 常量 / static | `SCREAMING_SNAKE_CASE` | `MANIFEST_FILES`、`MAX_FILE_CHARS` |

其他约定：

- 错误用 `Result<T, String>`，错误信息用中文（如 `format!("执行失败: {}", e)`）
- 注释用中文，`///` 用于公开项，`//` 用于行内说明
- 测试放文件末尾的 `#[cfg(test)] mod tests`，用中文断言消息
- 平台相关代码用 `#[cfg(windows)]` 显式标注（本项目 Windows 优先）
- 不引入无用依赖；clippy 必须 0 警告

## JavaScript

- **2 空格缩进**，禁止制表符
- 语句结尾**必须有分号**
- 用 `const` / `let`，**禁止 `var`**
- 用 `===` / `!==`，只有与 `null` 比较才用 `==` / `!=`
- 命名：函数与变量 `camelCase`，类 `PascalCase`，模块级常量 `SCREAMING_SNAKE_CASE`
- 文件名**小写连字符**（`main.js`、`command.js`、`check-style.js`）
- 公开函数写 JSDoc（`@param` / `@returns`）
- 注释用中文，说明"为什么"而不是复述"做了什么"
- 字符串：**新代码用单引号**（Google JS），存量双引号不强制改写（避免无谓 diff）
- 不用任何 npm 依赖 / 打包器（项目硬约束）

## HTML / CSS

- 2 空格缩进
- 标签名、属性名、CSS 选择器与属性名一律**小写**；属性值用双引号
- `class` 命名小写连字符（`git-init-view`、`run-target-item`）
- CSS 属性声明后必须有分号；冒号后留一个空格
- 短规则可单行（现有风格），复杂规则每个声明一行

## JSON

- 2 空格缩进，文件以换行结尾
- i18n 键保持扁平、点分（`git.init.title`）

## 门禁命令

```bash
cargo fmt --check                        # Rust 格式
node scripts/check-style.js              # JS / HTML / CSS / JSON 风格
cargo clippy --all-targets               # 静态检查（0 警告）
cargo test -p ruyix             # 单元测试
```

`scripts/check-style.js` 的规则说明见脚本头部注释，简表：

| 规则 | 含义 |
|---|---|
| E1 no-var | 禁止 `var` |
| E2 no-tabs | 禁止制表符 |
| E3 indent-2 | 缩进为 2 的倍数 |
| E4 no-trailing-space | 行尾无多余空白 |
| E5 final-newline | 文件以换行结尾 |
| E6 eqeqeq | `===` / `!==` |
| E7 file-name | 文件名小写连字符 |
| E8 json-indent | JSON 可解析且缩进 2 空格 |
| W1 line-length | 单行 > 100 列（仅提示） |

## 例外

| 项 | 说明 |
|---|---|
| `ui/xterm.js`、`ui/xterm.css` | 第三方 vendored 库（MIT），保持原样不校验 |
| 多行模板字符串内部 | 帮助文本等**列对齐**是刻意排版，不判缩进 |
| HTML 标签内的属性续行 | 属性对齐是惯用写法，不判缩进 |
| `W1 line-length` | Google 建议 80 列；存量代码放宽到 100 列且仅提示，不阻断 |
