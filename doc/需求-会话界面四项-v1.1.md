# 需求：会话（agent 对话）界面四项调整（v1.1）

> 归属版本 **v1.1**。用户原话（2026-09-25）：
> 「对 agent 的 UI 做个调整，发送和停止合并为一个按钮。如果模型是多模态模型，那么显示录音按钮，
> 可以输入语音，将录音文件发送给模型，先只兼容 deepseek。然后探测模型供应商的模型列表，
> 在 agent 对话界面出现模型选择下拉框。对话区域，LLM 的最终回复放工具循环输出的下面，
> 现状是个大 bug。先做完这四件事。」

状态：**四项全部落地**；其中第 4 项的"发给模型"那一腿**被实测挡住**（见 §4 结论），
本版本按"能录、不假装发"交付 —— 口径与证据写在下面，改法留了一行开关。

---

## 1. 发送 / 停止合并为一颗按钮

- 一颗 `data-run`：空闲 = ▶ 发送；运行中 = ■ 停止（变红、换 title），**任何时刻都可点**。
  为什么不摆两个互相禁用的按钮：一个永远灰着的按钮既占位又要解释自己为什么灰，而"运行中"
  是一个**状态**而不是一个功能 —— 状态该改外观，不该换按钮。
- Ctrl+Enter 仍只走"发送"（**不是**去点那颗按钮）：手快连按不该把正在跑的任务停掉。
- 停止的行为与原 `data-cancel` 一字不差（取消位 + 一句「已取消」留痕 + 落盘）。

## 2. 对话区顺序：过程在上、结论在下（用户报的 bug）

原先 `msgHtml` 把正文拼在最前，轨迹追加在它**下面** ⇒ 任务跑完后读起来像"先给结论再做事"。
现在的顺序：① 轨迹（思考·执行）→ ② 提问卡 → ③ 最终回复 → ④ 验证/复核 → ⑤ meta。
判据落在**真渲染出来的 HTML** 上（`U41 trace-before-answer`）：源码顺序只能证明"代码那么写了"。

## 3. 会话工具栏的模型下拉框（探测供应商模型列表）

- 数据源是**厂商的** `GET /models`（引擎 `llm::models` → 宿主 `ai_models`），前端不维护名单。
- 每条选项的 title 写清能力（联网 / 读图 / 录音 / 上下文窗口），用户不必去配置面板猜。
- 换模型写 **runtime** 作用域的 `llm.model`（只影响本次运行，不落盘改掉默认），换完**重新问一次
  能力**（联网/录音的可用性跟着模型走）。
- 拿不到列表**不许编**：只留当前模型一项 + 说明（没 Key / 断网 / 该端点没有 `/models`），
  并保持禁用 —— 编一份清单等于让用户选一个可能跑不通的模型。

**实测（2026-09-25）**：`https://api.deepseek.com/anthropic/v1/models` → **404**，
`https://api.deepseek.com/models` → 200（带 `name` / `input_modalities` / `context_window`）。
所以探测加了**主机根回落**（同一 URL 只试一次、回落统一 Bearer），否则 anthropic 用户的
下拉框会静默退回文本框 —— 那正是改造前配置表单的实际行为。

厂商今天只有 2 个模型（`deepseek-flash` / `deepseek-v4-pro`；`deepseek-v4-flash` 与
`deepseek-v4-flash-vision-exp` 官方文档已标为退役旧名）。真机判据：
`cargo test -p harness-engine --test models_live -- --ignored` → `模型数 = 2`，模态分别为
`["text","image"]` 与 `["text"]`。

## 4. 录音按钮（多模态模型出现，把语音发给模型）

### 已落地

- 🎙 由**多模态**门控出现（用户口径）；能不能**发给模型**另看厂商声明的 `input_modalities`
  里有没有 `audio`。两件事分开判，是因为在今天的 DeepSeek 上它们**不同真**。
- 录音：`getUserMedia` + `MediaRecorder`（`audio/webm;codecs=opus` 优先，逐档协商），
  录音中按钮变红 + title 计时；停止后 base64 交给宿主 `voice_save`，
  落 **`<便携根>/projects/<项目键>/voice/voice-<毫秒>.webm`**（项目桶族，**绝不写进用户仓库**），
  会话里回一句「录音已保存（Ns · KB）：<路径>」。
- 守卫：扩展名只留字母数字（会被拼进文件名）、数据 32MB 上限、空录音直接拒绝。

### 结论（实测四条，都是"打过了"而不是"查过了"）

| 入口 | 结果 |
|---|---|
| `GET /models` 的 `input_modalities` | 合法取值只有 `text` / `image`，**没有任何模型声明 audio** |
| `POST /audio/transcriptions` | **404**（没有 ASR 入口） |
| chat/completions 里塞 `{"type":"input_audio"}` | **422** `unknown variant \`input_audio\`, expected one of \`text\`, \`image_url\`, \`file\`` |
| `POST /files` 上传 WAV / TXT | **400** `unsupported file ... formats: webp, png, jpeg, and gif`（类型白名单，不是形状问题） |

⇒ **DeepSeek 今天收不了音频**（文档里 `input_modalities` 的枚举也只有 text/image）。
所以"录音发给模型"这一腿**无法验证、也不该假装** —— 本版本的口径是：
**能录、存进项目桶、在会话里说清"没发出去"**；等厂商声明 `audio` 的那天，
`ai_models` 里那条 `audio` 会自己变 true，按钮的 title 与行为随之变成直发。
真机测试里专门埋了**反向判据**（`models_live.rs`）：一旦有模型声明 `audio`，
那条 assert 会红 —— 那是"该把落盘改成直发"的信号，而不是需要忽略的噪音。

### 待拍板（用户选）

语音要**今天就能用**，只有"本地转写"这一条路（厂商侧没有入口）：

1. **本地 ASR（推荐）**：whisper.cpp + `ggml-small` 之类，走与项目记忆**同一套**机制
   （模型不进 git、运行时按需下载、单 exe 自检），录音 → 本地转写 → 把文本作为消息发给模型。
2. 等厂商支持音频（代码已就绪，零改动）。
3. 不理，录音只当"语音备忘"存着（本版本现状）。
