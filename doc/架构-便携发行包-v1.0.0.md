# 架构：便携发行包与目录布局（v1.0.0）

**归属版本**：v1.0.0　**上游需求**：`doc/需求-发行包改zip-v1.0.0.md`
**一句话**：把"全局路径从哪儿来"从**散落各处的 `home_dir()` 拼接**收敛成**唯一解析点**，
根可以是"exe 同级目录"（便携）也可以是 `~/.ruyix/code`（遗留），两种模式共用同一套相对布局。

## 二、目标：`Paths` 门面（宿主的唯一解析点）

```rust
/// 全部全局路径的**唯一**解析点：构造一次，注入给各处（含引擎）。构造之外不许再拼 home。
pub struct Paths {
    root: PathBuf,          // 便携 = exe 目录；遗留 = ~/.ruyix/code
    mode: Mode,             // Portable | Legacy
}

impl Paths {
    /// R2 的判定只在这一个函数里（含 RUYIX_HOME / portable.marker / 遗留回落）
    pub fn discover(exe_dir: &Path) -> Paths;

    // 相对布局 —— 两种模式的差别只体现在这三个函数里（见 §四 的表）
    pub fn config_dir(&self) -> PathBuf;      // 便携 <root>/config        | 遗留 <root>
    pub fn data_dir(&self)   -> PathBuf;      // 便携 <root>/data          | 遗留 <root>
    pub fn plugins_dir(&self)-> PathBuf;      // 便携 <root>/plugins       | 遗留 <root>/plugins

    pub fn projects_dir(&self) -> PathBuf;    // 便携 <root>/projects      | 遗留 <root>/projects
    pub fn runs_root(&self)    -> PathBuf;    // <data>/runs               | <root>/agent/runs
    pub fn debug_log(&self)    -> PathBuf;    // <data>/logs/debug.log     | <root>/debug.log
    pub fn webview_data(&self) -> Option<PathBuf>; // 便携 Some(<data>/webview) | 遗留 None（不折腾）

    /// 项目级：位置**不变**（`<proj>/.ruyix/code`），放在这里只是"没有第二处拼路径"
    pub fn project_config(&self, proj: &str) -> PathBuf;
}
```

**引擎侧（zero-tauri）不 `discover`** —— 它是库，不该知道"exe 在哪"。它继续从 `AppConfig.workspace_root`
拿根（这个字段已经存在，宿主 `config_bridge.rs:69-71` 已经在注），本单只做两件事：
1. 把**默认值**从 `~/.darkhorse/harness/runs` 改到新布局（R7）；
2. `~/` 展开保留，但**相对路径改为相对注入的根**解析（现在是相对 home）。

## 三、便携根判定（R2 的算法，只有一个实现）

```
discover(exe_dir):
  1) 若 RUYIX_HOME 非空        → root = RUYIX_HOME                 （脚本/CI/多环境用）
  2) 若 exe_dir 下存在 config/ 或 data/ 或 portable.marker
                              → root = exe_dir，mode = Portable
  3) 否则                      → root = ~/.ruyix/code，mode = Legacy
```
**细节与边界（都要有明确行为，不许"看情况"）**：

- 判定在**启动最早期**做一次，结果缓存；`--debug` 日志开头必须打印 `根=… 模式=…`（这是 A2 判据的证据）；
- **exe 所在目录只读**（放到 `C:\Program Files\` 或只读 U 盘）：便携模式**照常进入**，但**第一次写失败时**必须给一句人话
  （"这个目录不可写，请把文件夹拷到可写位置，或用 RUYIX_HOME 指定数据目录"），而不是静默崩；
- **`current_exe()` 失败**（极端情况）：回落遗留模式 + 日志一行说明；
- 便携根**不做规范化大小写/短路径的猜测**：拿到的就是拿到的（路径比较沿用现有 `clean_path` 的纪律）。

## 四、布局映射（旧 → 新，机械可对）

| 内容 | 现位置（遗留 / 今天） | 便携模式新位置 |
|---|---|---|
| 分节配置 | `~/.ruyix/code/<section>.toml` | `<root>/config/<section>.toml` |
| 项目列表 | `~/.ruyix/code/projects.toml` | `<root>/config/projects.toml` |
| MCP / A2A / 工具 / 技能 | `~/.ruyix/code/{mcp,a2a,tools,skills}.toml` | `<root>/config/…` |
| agent 沙箱产物 | `~/.ruyix/code/agent/runs` | `<root>/data/runs` |
| 调试日志 | `~/.ruyix/code/debug.log` | `<root>/data/logs/debug.log` |
| 命令发现缓存等 | （进程内 / 未落盘） | `<root>/data/cache/` |
| WebView2 user data | `%LOCALAPPDATA%`（OS 默认） | `<root>/data/webview` |
| 插件 | （无） | `<root>/plugins/` |
| 项目 | 任意路径 | 默认工作区 = `<root>/projects` |
| **项目级 `.ruyix/`** | `<项目>/.ruyix/**` | **不变** |

> 遗留模式**不是**"老路径的兼容层"，而是**同一套代码的另一组根**：`~/.ruyix/code` 直接当 `config_dir` 与 `data_dir`，
> 所以老用户**零迁移、零改动**（A1 判据靠它成立）。

## 五、迁移（R5）

- **触发**：便携模式首启，且 `<root>/config` 为空（或只有模板），且 `~/.ruyix/code` 里存在**真数据**
  （判据：`projects.toml` 有非空列表，或存在任一 `<section>.toml`/`mcp.toml`/`tools.toml`/`skills.toml`）；
- **动作**：**复制**（不是移动）`config` 类文件到 `<root>/config/`；`agent/runs` 这类大目录**默认不搬**（可选项）；
- **幂等**：成功后写 `<root>/config/.migrated-from-legacy`（含时间戳与源路径），下次不再提示；
- **可拒绝**：用户选"不导入"→ 写一条 `<root>/config/.migrated-skip`，永不再问（要改就在面板里重新触发）；
- **失败处理**：单个文件复制失败 → 记录 + 继续（不半途退出）；全部失败 → 报错并保持"未迁移"状态；
- **旧目录只读不动**：出问题能回退（把 `<root>/config` 删掉即回到"空配置 + 旧数据仍在"）。

## 六、WebView2 user data（R6）—— 便携的成败点

- **为什么必须**：WebView2 默认把 user data 放 `%LOCALAPPDATA%\...`。不改的话"便携版"会在 C 盘留一份
  与 zip 无关的状态：拷走文件夹 ≠ 带走全部状态，且两台机器上两份副本会**共用**同一份缓存；
- **怎么设**：Tauri v2 的 `WebviewWindowBuilder` 支持指定 data directory（`data_directory(...)`）；
  取值 = `Paths::webview_data()`，**必须在建窗口之前**设好（现在是 `main.rs:1688` 直接建窗口，没有这一步）；
- **风险（未测，先列）**：① 同一 data dir 被两个进程同时打开 → WebView2 会报错（这与 R11 单实例策略耦合，
  见 §七）；② 老用户从"OS 默认"切到"根内"会丢 cookie/缓存 —— 对本应用无影响（无登录态缓存需求）；
  ③ 网络盘/只读目录上的 data dir 是否可用未测 → 沿用 §三 的"写失败给人话"。
- **决策**：便携模式**必须**设在根内；遗留模式**保持 OS 默认**（不折腾现有用户）。

## 七、单实例（R11）

现状：`instance.rs` 用**全局命名 mutex**（`CreateMutexW`）判"已有一个实例在跑"。
对便携版是错的：两份解压到不同目录的副本会互相踢。改法（待拍板）：
- **按根区分**：mutex 名字里带上 `Paths::root` 的 hash（例：`ruyix-<hash>`）→ 不同根互不影响；
- 连带影响：同一根下两个实例仍然只允许一个（保持现有行为）；
- 与 §六 的一致性：mutex 按根区分后，WebView2 data dir 也按根隔离 → 两份副本各用各的缓存 ✓ 不打架。

## 八、与插件化（v0.14）的接口

本单只**建目录 + 定位置**，加载实现留给 `doc/需求-高亮插件化-v0.14.md`：

| 插件种类 | 目录 | 谁读 |
|---|---|---|
| 语法高亮（query / 主题 / 词表） | `<root>/plugins/highlight/<id>/`（`highlights.scm`、`theme.css`、`plugin.toml`） | 宿主高亮模块 |
| 动态 grammar（若将来上法子 4） | `<root>/plugins/grammars/<lang>.dll` | 宿主（`libloading`） |
| 全局与项目两级 | 全局 `<root>/plugins/`；项目级 `<项目>/.ruyix/plugins/` | 合并规则沿用 `capability.rs` 的"按名合并、项目覆盖全局" |

## 九、不变量与门禁（改完不许退化）

1. **`home_dir()` 只允许出现在 `paths.rs`** —— 静态门禁（grep）+ 新单测；引擎侧只允许出现在
   `expand_home` 那一处（`~/` 展开），且默认根不再含 `.darkhorse`；
2. **全仓无 `.darkhorse`**（含文档里的示例）；
3. `Paths::discover` 有**表驱动单测**：三种摆放（env / 同级目录 / 都没有）× 两种模式 → 根与各子路径逐项断言；
4. **打包脚本可重复**：用 `RUYIX_HOME` 指向临时目录跑，不触碰真实用户数据（否则门禁会污染开发机）；
5. **项目管理式不变**：`<项目>/.ruyix/**` 的路径与语义一个字不改（有现成测试钉着，动了会红）。

## 十、风险表

| 风险 | 影响 | 应对 |
|---|---|---|
| Tauri v2 的 data directory API 细节与 WebView2 锁冲突（**未测**） | R6 可能改不成，或与单实例打架 | 阶段 P1 先做**一次性探针**：指定 data dir 起两次实例，看行为 |
| 便携根下**没有写权限**（Program Files / 只读介质） | 启动即失败体验 | §三 的人话报错 + `RUYIX_HOME` 逃生口 |
| 迁移把大目录一起搬（`agent/runs` 可能几百 MB） | 首启卡很久 | 默认不搬 runs，只搬配置；大目录走"可选" |
| 老用户误以为"数据丢了"（其实迁到 zip 里了） | 信任问题 | 迁移提示 + release 文档显式说明新布局 + 旧目录保留不动 |
| 打包脚本在 CI 上跑（无 WebView2/无 Edge） | 跑不了浏览器门禁 | 打包**不跑**门禁；门禁在提交前跑（保持现状） |
| zip 内 exe 被杀软/SmartScreen 拦 | 用户装不上 | release 文档给"解除锁定"/校验 sha256 的说明 |
