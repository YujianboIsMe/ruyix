# 需求：会话历史持久化（活过重启）
## 归属版本：v0.9 · 状态：**已实施**（2026-09-21）· 提出：2026-09-21

> 用户原话：*"现在会话历史没有持久化，重新打开 IDE，会话历史全丢。做一个持久化吧，
> 存在 `<project>/.ruyix` 里，持久化方案你自己定。"*

## 1. 结论先行：存储层一直在写，病根在**加载**

先把事实摆出来（实测，不是推测）：

| 观察 | 结果 |
| --- | --- |
| `<项目>/.ruyix/code/agent/sessions/` 是否存在会话文件 | **存在，而且一直在写**：cloud-shop 里 **27 个**，最新那条是当天最后一次对话 |
| 重启后会话面板显示什么 | **"暂无会话"** —— 文件在盘上，列表从来没被加载 |

根因：`refreshList()` 全仓**只被调用一次** —— 在 `attach()` 末尾，也就是**启动那一刻**。
而那一刻项目往往还没打开 → `root()` 为空 → 直接 `return`，**之后再也没人叫它**。
所以"持久化"这件事的存储层是好的，断的是"项目打开 → 拉一次列表"这条线。

⇒ 本版的"方案"不是另造一套存储（那只会多一个真相源），而是：**把这条链路补齐 +
把持久化的语义定死**（下面 §3/§4 的每一条都对应一类真实的数据丢失路径）。

## 2. 存储布局（我定的）

```
<project>/.ruyix/code/agent/sessions/<sess_…>.json     # 一个会话一个文件，pretty JSON
```

- **一个会话一个文件**（不是 SQLite、也不是单个大 JSON）：会话是"按 id 整条读写"的对象，
  分文件让**损坏面最小**（一条坏文件只影响它自己）、人能直接打开看、git 可 diff；
  同时不动"IDE 侧零服务依赖"这条纪律。规模上足够（一次对话几十 KB）。
- 文件名即 id 的唯一事实来源（读回来时以文件名为准，防手改错位）。
- **快照跟着消息走**：`plan` / `verify` / `reflect` / `ask` 四类结论存进消息本身，不靠 `run_id` 回读
  —— 会话跑的是工具循环，本来就不落 RunRecord（这条从 v0.4/v0.8 起就是既定纪律）。
- 目录名沿用既有约定（`code/agent/sessions`）：`<project>/.ruyix/` 下已经住着
  `backups/`（写前备份）、`stage/`（确认模式暂存）、`proc/`（托管进程日志）、`env/`（安装记录），
  会话加进去即可，不再发明新层级。

## 3. 三条不变量（这次真正补上的）

1. **打开项目必须同步一次列表**：新增 `SessionUI.syncForProject(autoOpenNewest)`，
   在 `openProject()` 的收口点调用（启动恢复走的是同一个函数，所以一处挂上两处生效）。
   它顺带把**最近一条有消息的会话接成 tab** —— "接着上次继续"，
   而空会话（新建但一句没用过）不占位，免得每次开项目都弹一个空聊天。
2. **用户那句话立刻落盘**：`sendMessage()` 里 push 完用户消息就 `persist(s)`。
   原先只在 run **结束后**才写：run 跑一半崩了 / 被强杀，整段对话（包括用户自己说的话）都没了。
3. **原子写**：先写同目录 `<id>.json.tmp`，再 `fs::rename` 覆盖。
   截断式写入（`fs::write`）被中断会留下**半截 JSON**，而 `list()` 会跳过解析失败的条目
   —— 用户看到的是"那条对话整段消失"，且**没有任何提示**（静默数据丢失，最坏的一种）。
   临时文件刻意用 `.tmp` 后缀：`list()` 只认 `*.json`，残留的临时文件不会被当成会话。

## 4. 两条边界语义（同样是为了不再"看不见地丢东西"）

- **空会话不落盘**：`agent_session_new` 只签一个 id，真正写盘发生在第一条消息之后。
  否则每点一次"新建"就留一个 0 条消息的空文件 —— 面板里全是幽灵条目
  （实测 ai-gateway 里就躺着一个"只被创建、从未写入"的空会话；而"历史看不见"的账最后都算在持久化头上）。
- **删除幂等**：文件已经不在（空会话从未落盘、或上个进程被强杀）也算成功。
  用户点 ✕ 的意图是"这条没了"，此时报错只会让他以为删失败了。
- **坏文件只影响它自己**（有单测钉住）：一条坏 JSON 不许把整个列表打空 ——
  那同样会表现成"历史全丢"，而且更吓人（盘上明明有几十条）。

## 5. 加载语义

- `agent_session_list` → 按 `updated_at` 倒序（新的在前）；解析失败的单个文件跳过，不影响其它。
- 点开会话 → `agent_session_load` 读全文渲染；老会话缺字段照旧解析（`#[serde(default)]` 一路保留）。
- 面板每条显示：标题（首条用户消息截断，另有"未命名会话"兜底）+ 消息条数 + 删除按钮。

## 6. 验收（都是真跑出来的）

| 层 | 证据 |
| --- | --- |
| 存储不变量（Rust 单测） | `save_is_atomic_and_leaves_no_temp_file`（覆盖落成新全文 + 目录里不留 `.tmp`）、`delete_is_idempotent`、`a_corrupt_file_only_drops_itself_from_the_list`（好文件还在 + `.json.tmp` 不被当成会话） |
| 静态契约（ui-smoke **U28**，5 条） | 打开项目处有同步调用 / `syncForProject` 存在且会接上最近一条 / 用户消息立刻落盘的标记 / 原子写（`with_extension("json.tmp")` + `fs::rename`）/ 坏文件容错被钉住 / 空会话不落盘 + 删除幂等 + 旧错误串已消失 |
| **真机活体（CDP）** | `node scripts/session-persist-probe.mjs` 两阶段（之间**真的重启应用**）：<br>① 后端列表 == 盘上文件数（27 = 27）<br>② 面板渲染 27 条（不是"暂无会话"）<br>③ 打开项目后自动接上最近一条有消息的会话<br>④ 写入探针会话 → 文件出现在 `<root>/.ruyix/.../sessions/` 且内容一致<br>⑤ 无 `*.json.tmp` 残留<br>⑥ 连删两次都不报错<br>⑦ **重启后**：该会话在列表里、面板画得出、点开后 2 条消息与标题逐字读回 |

## 7. 不做（明确的边界）

- 不做云同步 / 多设备（会话是本地项目资产）。
- 不做自动清理（除非用户自己删）—— 但空会话不再产生，面板因此不会长草。
- 不做跨项目共享：会话跟项目走（换项目 = 换 `.ruyix`）。
- 不做"运行中实时落盘每一条工具调用"：粒度过细只会把磁盘写爆；本版的粒度是
  **用户消息 + 每轮 run 结束**（拿到的安全性已经覆盖"崩了不整段消失"）。
