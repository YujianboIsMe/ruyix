# 需求：会话执行轨迹（看得见 agent 在干什么）

## 归属版本：v0.0.5 · 状态：**已实施**（2026-09-23）· 提出：2026-09-23

## 1. 用户原话与事实

> 「这里的 AI 执行过程，完全不能可视化，只显示三个点。优化下，要显示**思考过程**和
> **执行过程**，一行显示不全就用省略号。」

三个点不是"引擎没给数据"，而是**前端把它扔了**。开工前先核过三件事：

| 事实 | 证据 |
|---|---|
| 引擎每次工具调用都发一条日志 | `agent.rs:3753`：`[agent] 第 {step} 轮 {tool} {✓\|✗} {brief}`（批里每条各一行，轮号相同） |
| 阶段通告也一直在发 | `agent.rs:3294` / `3914`：`stage("agent", "start"/"done", …)`；宿主 `sink.rs` 原样 `emit("agent://log"/"agent://stage")` |
| 前端**监听**了，却只改字符串、从不重渲染 | `session.js` 原 `agent://log` 分支：`if (p.level === "ok") runningPlaceholder.text = …`（没有 `el.innerHTML`） |

于是运行中的气泡永远停在初始的 `…`，而 `p.level === "ok"` 的那几行（答复/完成）把它
**覆盖**成一行日志 —— 既看不到过程，原本的"正在忙"也没有了。

## 2. 目标 / 明确不做

**目标**：运行中与运行后都能一眼看出这轮 agent 做了什么；每条占**一行**，装不下用省略号，
hover 给全文；重开会话仍看得见（跟着消息落盘）。

**不做**（都是"看起来更能干、其实在骗人"的那一类）：

- **不编造思维链**。`Action` 里没有 `thought` 字段，提示词第 1 条明写"每轮只输出一个 JSON 对象，
  不要输出解释文字"—— 所以界面上不许出现"模型正在思考……」这种自己脑补的文案。
  能拿到的"思考"是**模型亲口声明的计划**（`plan` 的步骤标题）与**引擎自己的阶段判定**，照实展示。
- **不改引擎、不改提示词**。数据早就够了；加一个思维链字段要动提示词契约、烧 token、还会让
  JSON 变胖（进而截断重发），与本需求无关。
- **不新开面板**。过程挂在气泡下面就地长出来 —— 用户盯着的地方就是它出现的地方。

## 3. 方案

### 3.1 一条流水线，两个来源

事件 → `pushTrace(kind, text)` → 消息对象上的 `m.trace` → `rerenderRun()`（与 `fillMsgs`
同一套渲染函数）→ `.session-trace` 小节。

| 事件 | 变成哪一行 | kind |
|---|---|---|
| `agent://stage` | `p.detail`（为空退回 `stage status`） | `think` |
| `agent://plan` | `列了 N 步计划：<步1> → <步2>` | `think` |
| `agent://log` + `✓` | `第 N 轮 read ✓ ui/session.js（905-1145）` | `do` |
| `agent://log` + `✗` / warn / error | 原样（红） | `fail` |
| `agent://log` + `完成，共 N 轮` | 原样（绿） | `done` |
| `agent://log` 其余（检索/折叠/提问/裁决） | 原样 | `think` |

分类**只按日志自己说的事**（`traceFromLog` 一个纯函数，无状态机、无启发式打分）。
`agent://verify` / `agent://reflect` / `agent://ask` 不进轨迹 —— 它们各自已有视觉更重的小节
（验证/复核小节、提问卡），再抄一份进轨迹只是噪声。

### 3.2 思考与执行**交错**成一条列表，不拆成两段

引擎的时序是 `想 → 做 → 想 → 做`。按"思考区 / 执行区"分栏会把真实顺序打乱（读者再也
答不出"它是先想到还是先做的"）。所以是一条时间线，每行自带图标（💭 / ⚙ / ⚠ / ✅）与配色。

### 3.3 一行一条

```css
.session-trace-text { flex: 1 1 auto; white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
```

- `nowrap` 禁折行 —— "一行"是这个需求的字面要求；
- `overflow: hidden` 在这里**干两件事**：裁掉溢出，并把 flex 子项的 `min-width: auto`
  解析成 0（规范如此）—— 所以**不需要**再写 `min-width: 0`（写了也不起作用，实测摘掉无差别）；
- `text-overflow: ellipsis` 收尾；
- 全文进 `title`（hover 可见）—— 省略号是**显示**策略，数据侧不留截断（`TraceSnap.text` 存全文）。

气泡里最多画最近 **24** 行（更早的折成一行 `… 更早 N 条未显示`，数据侧上限 200 行）。
一轮 40 次调用的长 run 不能把气泡撑爆，而"最近发生了什么"才是正在盯的人要的。
措辞是"**未显示**"而不是"已收起"：超过 200 行上限的那部分是**真丢了**，说成"收起"就是撒谎。

### 3.4 无轨迹的消息宽度放宽

轨迹装的是路径 / 命令 / 报错原文，比对话正文长；`msgHtml` 给有轨迹（或正在跑）的消息挂
`.session-msg--trace`，`max-width` 从 78% 放宽到 94%。不带轨迹的消息一字不变 —— 不用 `:has()`
（本仓库样式表里没有任何 `:has()`，不为此破例）。

### 3.5 跟着消息落盘

`sessions.rs::SessionMsg` 新增：

```rust
#[serde(default, skip_serializing_if = "Vec::is_empty")]
pub trace: Vec<TraceSnap>,   // TraceSnap { kind, text }
```

两条属性都是必须的：删 `default` → 老会话读不回来；删 `skip_serializing_if` → 每个旧文件
被改写一遍。这条纪律与 `plan` / `verify` / `reflect` / `ask` 同源（结构体不声明，`agent_session_save`
的 serde 往返顺手抹掉，UI 还拿返回值覆盖自己的 messages）。

## 4. 不变量与**反向验证**（绿而不会红的门禁是摆设）

| # | 不变量 | 怎么证明它会红（实测过） |
|---|---|---|
| 1 | 两个进度事件必须被**渲染**，不能只监听 | 把 `agent://log` 分支换回 `runningPlaceholder.text = …` → U41 红 7 项（`trace-rows` / `trace-kinds` / `trace-saved` / `trace-text-intact` …） |
| 2 | 省略号三件套缺一不可 | 摘掉 `text-overflow: ellipsis` → U41 `trace-ellipsis` 红 |
| 3 | `trace` 字段的 serde 属性 | 删 `default,` → U41 `trace-persist` 红 |
| 4 | 真几何：一行高 + 真溢出 + 无横向滚动条 | 摘掉 `overflow: hidden` → U42 红 3 项，并报出"消息区 hBar=10"（横向滚动条真的长出来了） |
| 5 | `kind` 只认白名单（不走原型链） | 换回 `TRACE_ICON[t.kind] ? … : …` → U41 `trace-kind-whitelist` 红 |

第 5 条的由来：`kind` 是**会被持久化、从盘上的会话文件读回来**的字符串（输入不是常量）。
真值判断会被原型链命中 —— `kind: "constructor"` 时图标格里渲染出
`function Object() { [native code] }`，class 拼成 `session-trace-row--constructor`（实测）。
改成 `Object.prototype.hasOwnProperty.call(TRACE_ICON, t.kind)` 后越界值一律按 `think` 画。

第 4 条是**只有真浏览器能量到**的那一类（Node 的 DOM 桩没有布局引擎），所以挂
`scripts/session-trace-layout.js`：真 `index.html` + `styles.css` + `session.js` 在无头 Edge 里
跑起来，喂真事件，再逐元素量 `offset/client/scroll`。`--shot=<png>` 顺手出图，让"看得见"
这件事本身也能被人复核。

## 6. 已知遗留（不在本版）

`rerenderRun()` 是整段 `[data-msgs].innerHTML` 重渲染（沿用 `appendGate` 的老做法）。
`.session-apply` 差异面板是**运行时 append 的节点**，不进 `messages` 模型 —— 所以同一会话里
再跑一轮时，上一轮打开的写回面板会被这一次重渲染冲掉。这是**改动前就存在**的行为
（老代码在每个 verify/reflect 事件上做同一件事），本版只是让它发生得更早一点。
要真正修掉得先决定"写回面板的已加载 diff 要不要进消息模型"，属独立决策。
