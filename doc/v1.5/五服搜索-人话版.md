# 五服搜索（分层搜索）人话版

> 这条线叫 **v1.5 分层搜索**，「五服」是当初定的比方。本文是**给人读的**那一份；
> 工程档是另外两份：`doc/v1.5/需求-分层搜索-五服-v1.5.md`（要什么、怎么设计的）与
> `doc/v1.5/实施-分层搜索-v1.5.md`（真落了什么、读数是多少）。两份都只讲事实，本文负责讲明白。

## 0. 先说名字（容易混，先对齐）

- **「五服」只是文档里的比方**（甸服 / 侯服 / 宾服……古人按远近分天下）。**代码里一个名字都没有** ——
  落地的标识符只有五个 scope 名：`session` / `project_mem` / `global_mem` / `files` / `kb`。
- 它不是「第五个工具」，而是 **`read` 的第二种问法**：同一个工具，`path`（读文件）和
  `scope`+`q`（检索）**二选一**。
- 为什么这很重要：四个原语（读 / 写 / 执行 / 连接）编码的是**效果**。检索不写盘、不改状态、
  结果由资源当前状态决定 ⇒ 它**就是读**。加第五个原语会把"四原语 = 四种效果"这条地基挖掉。
  （先例：常驻服务也是这么处理的 —— **加维度，不加原语**。）

## 1. 一句话说清

以前 agent 想「找东西」只能去敲命令行（`git grep` / `findstr`）；现在它能**主动问某一层**：
"这句话在哪儿出现过？" —— 一次问一层，答案带**来源**（哪个文件 / 第几轮 / 第几个工具）和**版本**。

## 2. 为什么非要它（原来是三条真账，不是不好看）

1. **不进账本**：藏 `execute` 里时，带管道的命令判"不纯"（`git grep -i -l x | head` 就是），
   于是**不参与去重** ⇒ 同一件事换个拼法就能重跑。而"同资源版本没变就别重复干"是整套 harness 的省钱原则。
2. **提示词在替工具擦屁股**：系统提示里那条"优先 `git grep -i -l`，`findstr` 多掩码不可靠"是
   一条 **Windows 专属补丁** —— 它存在只是因为检索没有原生入口。
3. **结果没有来源与指纹**：终端文本回来，模型不知道那片内容属于哪个文件、哪个版本；
   账本也没法给它定版本（定不了版本就没法复用）。

## 3. 五服到底是哪五层（大白话）

| 层 | scope | 它是什么 | 谁写的 | 一句话 |
|---|---|---|---|---|
| 1 会话内 | `session` | **本次 run** 里被折叠/复用过的正文（侧存）+ 结论 | 引擎自己 | "这次对话里说过的话" |
| 2 项目记忆 | `project_mem` | 本项目的记忆库（信念 + 事件账本） | 引擎自己 | "我（对这个项目）曾经相信的事" |
| 3 全局记忆 | `global_mem` | 跨项目的同一套库 | 引擎自己 | "我在别的项目里也相信过的事" |
| 4 项目文件 | `files` | **磁盘上的现状** | 用户 / 磁盘 | "现在实际写的是什么" |
| 5 知识库 | `kb` | 声明进来的语料 + FTS5 索引 | 被声明入库的语料 | "外部常识" |

**第一刀开了前四层**；第 5 服（`kb`）留作第二刀 —— 它的预算 / 去重 / 信任级是另一套设计，
现在仍按老样子**被动注入**（需要时自动塞进提示词，只是模型还不能主动问它）。

## 4. 为什么第 5 服不是「操作系统文件」（这是当初定的边界）

两条硬理由，都不是"怕麻烦"：

- **没有 owner 就没有准入**：全盘搜索没有主人 ⇒ 只能退化成**敏感词黑名单**，而黑名单永远漏
  （今天的 `ai.toml`（带 API Key）、`.env`、SSH key、浏览器 cookie 库……明天是谁？）。
  换成"被声明的语料"就变成**准入门**：不做声明就进不来。
- **没有主人就没有指纹**：账本那句"同资源版本未变 ⇒ 不重复执行"依赖一个可判定的版本
  （文件 `(mtime,size)` / git HEAD / 事件序号）。"整个盘在某一刻的样子"给不出这个 ⇒ 要么每次真跑，
  要么拿旧结果冒充新的（后者更坏）。

> 一句话：**只有"被声明的语料"+"有指纹的索引"能进第 5 服。**

## 5. 真正新增的设计：五服 → 三张表

比方本身不值钱，值钱的是**每一层都必须回答同样三个问题**：

| 问题 | 在问什么 | 各层怎么答 |
|---|---|---|
| **准入**（凭什么能搜） | 这一层凭什么可以被检索 | 要么被 **jail**（`files` 只能搜项目根，路径检查拦住 `..` / 绝对路径 / `.git`）；要么被**声明**（`kb`）；要么**引擎自己产的**（1/2/3） |
| **新鲜度**（能不能复用） | 这一层的"变了没有"怎么判 | `files` = **git HEAD + 工作树脏否**；记忆两层 = **事件序号**（见 §7 的坑）；`session` = 侧存索引文件 |
| **权威**（冲突谁让谁） | 两层说法不一样时信谁 | **文件 > 记忆**。磁盘上的现状最硬；记忆是"我曾经相信"，可能过时 |

两条由此推出来的硬规矩：

- **扇出由内向外**（近的先答、够用就停），**权威由外向内**（文件 > 记忆）—— 两个方向相反，
  所以**一次调用只查一层**，结果块**逐条标来源与时间**。
- **冲突并列回给模型，引擎不裁决、不覆盖**。引擎挑一个才是危险动作：那是**静默改写事实**。

## 6. 模型侧长什么样（一个例子）

```json
{"read": {"scope": "files", "q": "RETRY_POLICY", "path": "src"}}
```

- 一次**只**一层；`scope` 必填（不填就给具体理由打回）。
- `path` 是**限定**（"只在这个子树里找"），`files` 层才接受；它不是"读那个文件"。
- 结果上限 `MAX_HITS = 50` 条、每条裁 200 字符、整块 6000 字节，超了在结尾说明"截断在第 N 条"。
- **没命中是合法答案**，不是错误：会告诉你"在哪一层、用什么词找的、库/索引当前什么状态"。
- 拒绝了会**逐条给理由**：未知层 / 缺 `q` / 两个形状同时给 / 与窗口参数（`offset`+`limit`）混用 /
  库不可用 / 路径越界。

## 7. 怎么做到"同一件事不重复问"（含两个真踩出来的坑）

键 = **层 + 归一后的词 + 归一后的限定路径**（空白/大小写/`./src` ≡ `src` 都归一到同一个键）。
命中 ⇒ **不执行**，把上次的原文还回去并**标注"未重跑"**。

两个坑是实施时才逼出来的，都写进了代码注释和判据：

- **坑 1：记忆库跑 WAL。** 原先想用记忆库文件的 `(mtime,size)` 当版本 —— 错的：小写入落
  `mem.db-wal`，**主库文件的 mtime/size 根本不动** ⇒ 库里变了、账本却说没变 = **假新鲜**
  （拿旧结果冒充新的）。改用**只追加事件表的序号**（`MAX(seq)`）。
- **坑 2：会话层是"自失效"的。** 检索自己的结果也会进侧存 ⇒ 下一次检索的版本**必然**变了 ⇒
  **必然重新执行**。这不是 bug，是**有意的方向**：第 1 服的输出就是它输入的一部分，
  复用会给出**子集**；而"拿旧结果冒充新的"比多跑一次坏得多。判据把这件事钉住：
  谁要是"聪明地"把版本源改成不算自己写的那几条，那条判据会红。

**拿不到版本 ⇒ 每次都真执行**（fail-safe）。所以**非 git 仓库里文件层永不复用** ——
这不是漏做，是刻意留的安全方向。

## 8. 它一个字节都不写

检索没有任何写路径：不碰暂存（`stage/`）、不碰备份（`backups/`）、不碰写白名单。
判据不是看日志，是**整棵树的指纹跑前跑后对比**（路径 + 类型 + 字节数）——
"盘上没变"才算没写。

## 9. 怎么知道它真的行（读数，不是感觉）

- **单测 14 条**（`agent/tests/search.rs`），逐条对上需求里**先写死再实现**的 8 条判据：
  同层同词同版本第二次不执行 / 一个字节都不写 / 拒绝给具体理由 / 越界不许绕过 / 不混排 /
  无命中不是错误 / 老的 `read{path}` 路径逐字节不变 / 提示词少一条 Windows 补丁。
- **真模型冒烟**（`examples/search_smoke.rs`，退出码即判据：`0` 形状被接住且答案对 /
  `2` 做对了但形状没被接住 / `1` 答案错 / `3` 没 Key 大声跳过）。实测 `deepseek-v4-flash` 通过：
  - 模型**主动**用了这个形状，并在答案里自己写明 `scope=files, q="RETRY_POLICY"`；
  - 两处真命中（带行号）都对；它**正确解释**了为什么生成物目录里那个 `target/gen.rs` 不算
    —— 这正是"**没搜**"与"**没有**"可分这条设计的直接效果；
  - 读数里出现 **`仍重复执行 1`**：那正是 §7 那条 fail-safe 在真跑里的样子（临时项目不是 git 仓库，
    文件层的版本不可判）。

## 10. 一句话版（面试 / 讲给别人听）

> "找东西"不是一个新工具，而是 `read` 的第二种问法：**一次一层**，先开四层
> （会话内 / 项目记忆 / 全局记忆 / 项目文件），结果带**来源**和**版本**；
> 权威序是**文件 > 记忆**，冲突**并列不覆盖**；同层同词同版本**不重复问**；**一个字节都不写**。
> 第 5 服不是操作系统文件 —— **没有 owner 就没有准入，没有主人就没有指纹**。

## 11. 常见误解（先破四个）

- **"五服 = 五个工具"** → 不是，是**一个**工具（`read`）的**一种形状**。
- **"越远的层越权威 / 越可信"** → 反了。离磁盘最近的 `files` 最硬；记忆是"我曾经相信"。
- **"冲突时引擎会挑一个给我"** → 不挑。并列给你，并说明各自来源与时间 —— 引擎不许静默改写事实。
- **"搜不到 = 没有这件事"** → 不是。"没搜到"会告诉你"在哪层搜的、用的什么词、库/索引什么状态"，
  这是**有信息**的答案。（同理："没搜"和"没有"是两件事 —— 跳过的目录会被列出来。）
- **"五服的名字进了代码"** → 没有。代码里只有那五个 scope 名。
