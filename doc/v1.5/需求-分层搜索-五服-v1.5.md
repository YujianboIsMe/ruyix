## 1. 要解决的问题：缺的不是搜索，是"能主动问"

现状（2026-10-08 核过的代码事实）：

| 层 | 后端**已经存在** | agent 工具循环够得着吗 |
|---|---|---|
| 1 会话内 | `agent/capsule.rs` 侧存（sha256 校验）+ `findings` + `fold_history` | ❌ 只能**按键召回**（`capsule.get(&Ref)`）——折掉的正文不能按内容找 |
| 2 项目记忆 | `mem/`：`ledger`（EventKind/Origin）+ `fold`（Belief）+ `embed`（candle 向量腿默认编入）+ `retrieve.rs::now` | ❌ 工具循环没有动作；宿主 8 个 `mem_*` 只有"看账本"的口（beliefs / why / as_of / receipts） |
| 3 全局记忆 | 同一套，`retrieve.rs::global_now(mem, q, limit)` **已写好但全仓没被调用** | ❌ 同上 |
| 4 项目文件 | **无原生实现** —— 只有 `execute` 里的 `git grep` / `findstr` | ⚠️ 走 shell，代价见 §2 |
| 5 知识库 | `kb/`：SQLite **FTS5** + 中文 bigram + 去重/MMR + 来源与信任级 + 显式预算 + `KbInjection` | ❌ 只有**被动注入**（`pipeline.rs` 在 plan/repair 各检索一次）；且宿主**没有** kb 命令 |

**结论**：五层里四层半有后端，缺的是**一个统一的、能主动查询的读入口**；而唯一"能主动问"的第 4 层正走 `execute`，代价是下面三条真账。

## 2. 为什么不能继续把搜索藏在 `execute` 里

1. **不进账本**：白名单认 `git grep`/`findstr`/`where`/`find`，但**带管道时每段首 token 都得纯** ⇒ `git grep -i -l x | head` 判不纯 ⇒ 不参与去重 ⇒ 同一件事**换个拼法就能重跑**（`fresh_cmd` 按命令字面近似，这是它自己文档承认的洞）。
2. **提示词在替工具擦屁股**：系统提示里"优先 `git grep -i -l`，`findstr` 多掩码不可靠"是一条 **Windows 专属补丁**；原生检索一上，这条失去存在理由。
3. **结果没有来源与指纹**：终端文本回来，模型不知道那片内容属于哪个文件、哪个版本，账本也没法给它定版本。

## 3. 定性：**`read` 的一种形状**，不是第五个原语

- 四原语编码的是**效果**（读 / 写 / 执行 / 连接）。search 不写盘、不改状态、结果由资源当前状态决定 ⇒ **它是读**。加第五个原语会挖掉"四原语 = 四种效果"这条地基（v0.6 的常驻服务已经立了先例：**加维度，不加原语**）。
- 模型侧形状：`read {scope, q, path?, max_hits?}`（原有 `read {path, offset, limit}` 一字不动）。
- 引擎侧：`Action::Search(SearchSpec)` —— 新**变体**，不是新原语；在账本里它是**一等公民**（`Tool::Search`），否则谈不上"同参数同版本不重复执行"。

## 4. 五服 → 三张表（这才是新增的设计内容）

隐喻的价值不在"五层"，在**每层要回答同一组问题**。远的不是更真，近的也不是更权威。

| 服 | scope | 准入（凭什么能搜） | 新鲜度（版本 ⇒ 能否进账本） | 权威（冲突谁让谁） |
|---|---|---|---|---|
| 1 会话内 | `session` | 引擎自己产的（本 run 的侧存 + 账本正文） | 侧存索引 `(mtime,size)` | 最弱：过去说过的话 |
| 2 项目记忆 | `project_mem` | 引擎自己产的（本项目 scope） | 记忆库文件 `(mtime,size)` | 弱于文件：它是"我曾经相信" |
| 3 全局记忆 | `global_mem` | 引擎自己产的（跨项目，**默认开**） | 同上 | 同上；跨项目命中必须**标来源** |
| 4 项目文件 | `files` | **路径 jail**（项目根；`path` 走 `safe_rel_path`） | git `HEAD + 工作树脏否`；不是仓库 ⇒ **没有版本 ⇒ 每次真执行**（fail-safe） | **最强**：现在磁盘上是什么 |
| 5 知识库 | `kb` | 声明式语料 + FTS5 索引指纹 | （已具备） | 中：外部常识，且**是数据不是指令** |

两条由此推出的硬规矩：

- **扇出顺序由内向外**（近的先答、够用即停）；**权威序由外向内**（**文件 > 记忆**）。两者方向相反 ⇒ 一次调用**只查一层**，结果块**逐条标来源与时间**，冲突**并列回给模型**，引擎**不许静默覆盖**。
- **五层没有一层允许"任选路径"**：要么被 jail（4），要么被声明（5），要么是引擎自己产的（1/2/3）。这是**准入门**，不是敏感词黑名单 —— 黑名单永远漏，准入不做就进不来。
  - 因此第 5 服**不是**"操作系统文件"：全盘搜索没有 owner（准入只能退化成黑名单），也给不出可判定的版本（账本"同资源版本未变 ⇒ 不重复执行"依赖 `(mtime,size)`；"整个盘在某一刻的样子"给不出这个）。

## 5. 第一刀的范围（本次实施）

**开四层**：`session` / `project_mem` / `global_mem` / `files`。
**不开**：`kb`（它的预算 / MMR / 信任级是另一套设计，先保持被动注入；作为同一张表的第五行、第二刀再加）。

其余约束：

| 约束 | 取值 |
|---|---|
| 一次调用几层 | **一层**（`scope` 必填；不混排） |
| 结果上限 | `MAX_HITS = 50` 条；每条裁剪 200 字符；整块 `MAX_BYTES = 6000` 字节；超了在结尾说明"截断在第 N 条" |
| 无命中 | **是合法答案**（附"在哪一层、用什么词找的、库/索引状态"），不是错误 |
| 拒绝 | 每层给**具体理由**（未知 scope / 缺 q / 两个形状都给 / 库未安装 / 模型腿不可用 / 路径越界） |
| 写盘 | **零**：search 没有任何写路径（不碰 `apply_write`、不碰白名单、不碰暂存/备份） |
| 账本 | `Tool::Search` 参与去重：键 = `scope + 归一后的 q + 归一后的 path`；资源 = 该层**版本源**（侧存索引 / 记忆库文件 / 仓库版本） |
| 受管 | 与 `read` 同款：可进批、可在 step 子 agent 用（只读）、进 trace（`search <scope> <q>`） |

## 6. 预注册判据（先写死，再实现）

1. **同 scope 同 q 同版本，第二次不执行** —— 走账本命中，返回上次原文 + 标注（`files` 层在非 git 仓库里**永不命中**，那是 fail-safe，不是缺陷）。
2. **search 一个字节都不写**：跑前跑后项目树 + 状态根指纹一致（含"没有暂存、没有备份"）。
3. **每层拒绝都给具体理由**：未知 scope / 缺 `q` / `path` 与 `scope` 同时给 / 路径越界，逐条断言。
4. **越界不许被绕过**：`files` 层的 `path` 过 `safe_rel_path`，`..` / 绝对路径 / `.git` 全拒。
5. **五层不混排**：一次调用的结果只含一个 scope 的条目。
6. **无命中不是错误**：空结果带层级与库状态说明，退出码/审计都算"成功"。
7. **提示词少一条 Windows 补丁**：`agent_system_prompt()` 的 Windows 检索提示改为指向 `read{scope:"files"}` 优先（`findstr` 那句退为兜底）。
8. **老路径逐字节不变**：`read {path,...}` / 账本对 `read` 的包含关系 / 波次冲突规则一字不动（回归测试全绿）。

## 7. 明确不做（本刀）

- `kb` 层的动作（第二刀）；
- **跨层混排与自动排序**（新鲜度/权威不同，混在一起模型分不清哪条是"现在写的"、哪条是"三个月前记的"）；
- OS 全盘搜索（§4 的准入门）；
- `execute` 越界闸（A-6 已拍板不补，见 `doc/v1.4/拍板单-未决六项.md`）；
- 五服的名字进标识符（`甸服/侯服…` 只留在文档里当理据；代码用 `session|project_mem|global_mem|files|kb`）。
