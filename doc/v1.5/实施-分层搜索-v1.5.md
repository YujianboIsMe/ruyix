| 面 | 位置 | 说明 |

**写盘 = 零**：检索没有任何写路径（不碰 `apply_write` / 白名单 / 暂存 / 备份）。唯一的写是侧存自身的
校验计数。判据 `files_search_finds_hits_and_never_writes` 用**整棵树的指纹**（路径 + 类型 + 字节数）
跑前跑后对比 —— 比看日志可靠：盘上没变才是没写。

## 2. 两处与需求预注册不同的地方（实测逼出来的）

### 2.1 记忆层的版本不能用库文件的 `(mtime,size)` —— 库是 WAL

需求 §4 本来写"记忆两层看记忆库文件 `(mtime,size)`"。**错的**：记忆库跑在
`PRAGMA journal_mode=WAL`（`mem/mod.rs`），小写入落 `mem.db-wal`，**主库文件的 mtime/size 不动**
⇒ 拿它当版本会**假新鲜**（库里已经变了，账本却说没变，于是拿旧结果冒充新的）。

改用**事件序号**（`SELECT COALESCE(MAX(seq),0) FROM events`）做指纹：事件表是只追加的（`seq`
自增主键），任何一次入账都让它变大 ⇒ 版本必变。**拿不到 ⇒ `unknown` ⇒ 每次都真执行**（fail-safe）。

### 2.2 会话层是**自失效**的（不是缺陷，是方向）

第 1 服的版本源是侧存索引文件。而**检索自己的结果也进侧存**（账本记结果 = capsule 落一条）⇒
下一次检索的版本**必然变了** ⇒ **重新执行**。判据把它钉住了
（`the_session_layer_is_self_invalidating_and_that_is_the_safe_direction`）：谁要是把版本源改成
"不算自己写的那几条"，那条会红。

理由：第 1 服的输出**就是它的输入的一部分**（下一次检索能搜到上一次的结果）⇒ 复用会给出**子集**，
而"拿旧结果冒充新的"比多跑一次坏得多。

**旁证（正好是同一条证据的另一面）**：文件层在 git 仓库里**能**复用 ——
`a_repeated_files_search_is_served_from_the_ledger` 实测 trace 打出 `dedup search files|mark-1`，
第二次把上次原文还回去并标注"未重跑"。**非 git 仓库里文件层永不复用**（`repo = None ⇒ unknown`），
那条是本刀有意留的 fail-safe，不是漏做。

## 3. 判据读数（14 条，逐条对需求 §6）

| 需求判据 | 用例 |

| 1 同层同词同版本第二次不执行 | `a_repeated_files_search_is_served_from_the_ledger`（端到端，git 仓库；trace 断言 `dedup search files\|mark-1`）+ `the_ledger_treats_a_search_as_a_first_class_pure_call`（键归一：空白/大小写/`./src`≡`src`）+ `a_search_without_a_version_source_always_executes`（拿不到版本 ⇒ `unknown`） |

| 5 五层不混排 | 结构上成立（一次一个 `scope`）；`the_loop_runs_a_search_and_hands_the_hits_back` 断结果块只含一层 |

| 8 老路径逐字节不变 | 引擎全量 **472 passed / 0 failed / 8 ignored**（`read {path,…}`、账本的包含关系、波次冲突规则都没动） |

另有三条**本刀自己加的**判据（前面几条的边角，缺了就是"看得见的功能、看不见的洞"）：
`a_search_counts_as_the_read_tool`（工具名必须是 `read`：批上限、审计计数按工具名对账）、
`a_step_may_search_but_not_plan_or_connect`（子步只读面）、
`a_missing_memory_store_is_an_error_not_an_empty_answer` / `the_session_scope_needs_a_capsule`
（"库不可用" ≠ "没有记忆"，逐条明说）。

## 4. 真模型读数（`examples/search_smoke.rs`，2026-10-08）

单测只能证明"解析器认这个形状"，证明不了"模型会发它" —— 所以另有一条**真模型冒烟**：

```bash
cargo run -q -p harness-engine --example search_smoke -- --config target/debug/global/ai.toml
```

夹具是一个 4 文件的小项目（两处真命中，其中一处含生成物目录里的假命中）。退出码即判据：
`0` 形状被接住且答案对 · `2` 任务做对但**形状没被接住**（走老路）· `1` 答案错 · `3` 没有可用 Key（**大声跳过**）。

实测（`deepseek-v4-flash`，两跑都过）：

- 模型**主动**用了这个形状，并在答案里自己写明 `用 read 的检索形状 q="RETRY_POLICY", scope=files`，
  还把跳过的目录名单照抄出来；两处真命中（含行号）都对；
- 它**正确解释**了为什么 `target/gen.rs` 不算（那是"没搜"与"没有"可分这条设计的直接效果）；
- **`仍重复执行 1`** —— 那正是 §2.2 的 fail-safe 在真跑里出现的样子：临时项目**不是 git 仓库**
  ⇒ 文件层的版本不可判 ⇒ 同一个词搜第二次**重新执行**而不是复用（账本如实数了出来）。
  同一台机器上 git 仓库里的那次是复用的（单测 `a_repeated_files_search_is_served_from_the_ledger`）；
- 模型仍会用 `execute`（`dir /s /b`、`findstr`）做**交叉取证** —— 新入口没有把老路挤掉，
  两者分工：检索负责"找"，execute 负责"另一条独立证据"。

**第一版仪器自己踩了一个坑**（已修，如实记）：判"误报生成物"时只看 `answer.contains("target/gen.rs")`，
于是把模型那句"它确实有这个词，但它在被跳过的目录里"判成了误报 ⇒ 假红。现在的判据是：
提到它的那一行**必须同时带一个"排除"的说法**，否则才算误报。

## 5.5 会话层（第 1 服）改版：正文来源从 capsule 换成**留痕**（2026-10-09）

用户更正「甸服……应该是本 session 内**前几个 run**」+ 一个刚需场景（"我一个会话里第 1 个 run 和第 3 个
run 关于【user 表 password 字段长度】有没有冲突"）。核过三件事，结论是**不是检索写得不对，是要搜的
东西压根没存下来**：

1. 会话文件（`sessions/<id>.json`）里只有 `role/text` 与**派生品**（`trace` 一行摘要、`findings`、
   `plan`/`verify`/`reflect`）—— 工具调用的**输入与结果原文一个字段都没有**；
   `SessionMsg.run_id` 字段在、但聊天 run 跑工具循环**不落 RunRecord** ⇒ 恒空；
2. capsule 只留"被折掉 / 可复用"的那部分结果，且**一 run 一目录** ⇒ 跨 run 一个来源都没有；
3. 第 1 服此前能搜到的，只有"本 run 里已经离开上下文的一小块"。

改法（详见 `doc/v1.5/需求-会话层跨run检索-v1.5.md` §6）：新增 `agent/transcript.rs`（本 run 的留痕，
与 capsule 同目录、两份文件、各管一件事），`session` 层改读"本 run + 历史里那几个 run"的留痕；
`HistoryMsg.run_id` 当钥匙、宿主 `carry_session_runs` 保证它不被转录压实吃掉；UI 把
`ReplyAgent.run_id` 存进消息，环才闭上。

判据：跨 run 端到端（两个历史 run 的**不同说法都要在**结果里 —— 冲突要看得出来，引擎不许替它挑一个；
顺序 本 run → 新 → 旧；检索一个字节都不写项目）· 缺留痕时明说"没有读数"· 钥匙不被压实吃掉的纯函数判据 ·
ui-smoke **U77**。读数：引擎 485/0/8 · 宿主 182/0/3 · ui-smoke 449/449。

## 5.7 三服验收（侯服 / 绥服 / 要服，2026-10-09）

用户口径「甸服、侯服、绥服、要服做好」。甸服的教训（实现了 ≠ 用得上）在这里逐服重演了一遍：

- **侯服**（项目记忆）：库里**项目 scope 0 条** ⇒ 结论从来没进过记忆库。修：`Ctx::record_finding`
  顺路写 `mem::record_finding_obs`（`key = finding.<claim 指纹>`，**必须带 key** 才会折成信念、
  检索才读得到；键用 claim 指纹而不是"主题"，因为矛盾的结论必须并存）。
- **绥服**（全局记忆）：只有命令发现（3 条信念）。修：宿主每次跑把 `machine::facts()`
  （不含时间）记成 `key = machine.note` 的全局观察。
- **要服**（项目文件）：不认 `.gitignore`（老路 `git grep` 认）。修：清单问 git
  （`gitops::listed_files` = `ls-files --cached --others --exclude-standard -z`），
  不是仓库才回退目录树并发话说清；目录树遍历补**已访问目录**守卫（junction 绕死）。
- **顺带修的宿主 bug**：`record_compaction` 用的是"上一次的 scope"（它在 `set_scope` 之前跑）
  ⇒ 22 条收据全落 `_global`，切项目时还会落进上一个项目。改成显式传本项目 scope（谁先谁后都对）。

判据与现场证据：`doc/v1.5/验收-三服-侯绥要-v1.5.md`。

## 5. 没做的（与需求 §7 一致）

`kb` 层的动作（第二刀）· 跨层混排与自动排序 · OS 全盘搜索 · `execute` 越界闸（A-6 已拍板不补）·
五服的名字进标识符。另：`max_hits` / `MAX_BYTES` 目前是模块常量（不是配置键）—— 需求 §5 的表先按
"出厂即用"给了默认值，等真跑出"要调"的证据再上配置表（按仓库惯例：**先有读数，再有旋钮**）。
