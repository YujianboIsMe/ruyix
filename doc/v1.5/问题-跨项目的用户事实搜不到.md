## 1. 现象（用户原话）

> 「我在 A 项目里跟 agent 说了明天我有两场面试。我切换另一个项目，Agent 不记得了。这玩意能用吗？」

- **A** = `D:\Projects\Rust\ruyix`（21:17–21:24，四次 run）
- **B** = `D:\Projects\Python\ai-property`（21:28，一次 run）

## 2. 现场证据（实查，不是推断）

### 2.1 同一个会话里，它是**搜得到**的（甸服正常）

| 时间 | run | 发生了什么 |
|---|---|---|
| 21:17 | `20261009-211756-ctx` | 用户：「我明天又两场面试。」 |
| 21:18 | `20261009-211846-ctx` | 用户：「昨天我面试了一场，哎。」 |
| 21:21 | `20261009-212100-ctx` | 用户：「明天我有几场面试？你记得吗？」→ 答「**记得 —— 两场**」，并引用 21:17 那轮原话 |

这条走的是**甸服**（`session` = 本会话留痕，**含前面几个 run**）—— 2026-10-09 刚交付的跨 run 检索在真用里生效了。

### 2.2 同一个项目、**换一个会话**就退化

21:22 新建会话（run `20261009-212240-ctx`）再问，回答变成：

> 「**我的记录里是「明天两场」，但我这一轮没能核到你的原话** —— 建议以你自己的日程为准。」

甸服的正文是**留痕**，而留痕按会话（run 目录）存 ⇒ 新会话看不到上一个会话的提问。
这次靠**侯服**（项目记忆里的 `finding.95289a80` 等）兜住了 —— 前提是模型当时记过。

### 2.3 换项目后：五层的真实返回（run `20261009-212805-ctx`，逐条来自留痕）

| 层 | 引擎返回的原文（节选） | 判定 |
|---|---|---|
| `files` | 「命中 14 条」—— 全在 `面试话术文档.md` / `项目业务追问.md` / `项目技术栈追问.md`；搜 `面试安排`/`10-10`/`10月10`/`一面`/`offer`/`interview` 全 0 | 只有**准备材料**，没有日期/场次 |
| `session` | 「命中 1 条，**查了 1 份留痕**」，唯一命中是**本次提问自己** | 新项目 = 新会话 |
| `project_mem` | 「scope `D-Projects-Python-ai-property`，**命中 0 条**」 | scope 不对 |
| `global_mem` | 「scope `_global`，**命中 0 条**」（该 scope 共 4 条活信念） | 那里没有"你的事" |
| `kb` | 「知识库**一个来源都没有**……没有来源不是「搜了没命中」」 | 没配语料 |

模型自己也没偷懒：一共 14 次工具调用，还补了 `findstr`（`.workbuddy/memory/*.md` → `exit=1`）、
`dir`、桌面搜索，最后如实说"我不知道，不给你编一个数字"。

### 2.4 库里到底有什么（`global/memory/mem.db` 实查）

- 含「面试」的信念 **16 条，全部在 `D-Projects-Rust-ruyix` scope**，例如
  `finding.95289a80`：「用户自述明天（2026-10-10 周六）有两场面试；出处是用户自己在今天 21:17
  那一轮的会话发言「我明天又两场面试。」，不是我从项目里推断的。」
- `_global`（绥服）**只有 4 条**：`machine.note` + `tool.cargo` / `tool.docker` / `tool.git`
  —— **没有任何一类 key 是"用户说过的话"**。
- 这些条目都是**模型的转述**（claim 写"用户自述…"，证据指向 session 检索结果）；模型自己在
  一条 finding 里写着「不构成两条独立来源的交叉验证」。**用户原话从未一等公民地进过记忆层。**

### 2.5 顺带查出的两个独立缺陷（建议一起登记、另案处理）

1. **向量腿是坏的**：`global/memory/model/bge-small-zh-v1.5/` 只有 `config.json`（776 B）+
   `tokenizer.json`（439 KB），**缺 `model.safetensors`** ⇒ 记忆两层只剩**词法腿**。
   引擎在结果里如实写了「腿 = 词法（向量腿不可用：…缺文件：model.safetensors）」——不是静默降级，
   但"按需获取模型"这条链没走通（装了个半截目录就停在那儿）。
2. **跨 run 的钥匙全压在助手消息上**：会话 JSON 里**用户消息的 `run_id` 恒为 `None`**，
   只有助手消息带 run id。某轮助手没交付（取消 / 失败 / 超轮）时，那段留痕就断链，
   甸服的"前几个 run"会少一个却看不出来。

## 3. 根因

**准入表缺一格：五层里没有一层负责"委托人本人的事实"。**

| 服 | 谁写的 | 范围 | 为什么接不住这句话 |
|---|---|---|---|
| 甸服 `session` | 引擎自动 | **本会话**（含前几个 run） | 换项目/换会话 ⇒ 看不到 |
| 侯服 `project_mem` | 模型 `record_findings` | **按项目 scope 隔离** | 事实记在 ruyix 的 scope；且用户口述不是"代码结论" |
| 绥服 `global_mem` | 只有命令发现 + 机器事实 | 跨项目 | **没有任何写入方会写"用户的事"** |
| 要服 `files` | 磁盘 | jail 在项目内 | 事实不在任何项目文件里（模型已核过） |
| 荒服 `kb` | 声明式语料 | 跨项目 | 尚未配置任何来源 |

**换项目 = 同时换掉「会话」和「记忆 scope」**，能看见它的两层同时失效，剩下三层本来就不负责这件事。

所以：**不要先改检索代码**。五层都被问到了、每层的返回都是对的；错的是**没有任何一层负责存**。

## 4. 影响面（不止这次面试）

任何"你告诉我、但项目里没有"的事实：日程 / 偏好 / 身份 / 家庭 / 待办 / 口头约定 / 硬性边界
（"这块别动"）。**跨项目时尤其明显**（同一项目内至少还有项目记忆与旧会话留痕兜底）。

## 5. 修法候选（A / B / C / D，附我的立场）

| 候选 | 做什么 | 代价 / 风险 | 我的立场 |
|---|---|---|---|
| **A** `record_findings` 加作用域 | 给 findings 一个 `project` / `global` 选择；**个人事务、偏好、日程、硬边界**这类由模型显式声明为全局 | 靠模型判断"该不该往全局记"，可能记多（噪声）或少（漏） | **倾向**：与既有机制同构（一个动作加一个维度），不新增工具 |
| **B** 宿主认显式口令 | 用户说「记住：…」「记一下」时，宿主**直接把那句**落一条全局观察 | 触发权在用户手里 —— 朴素但**不会漏**；不覆盖用户没声明但很重要的场合 | **倾向**（与 A 并行，不替代） |
| **C** 甸服扩成跨会话 / 跨项目 | 检索范围从"本会话"放宽到"最近 N 个会话" | 改掉"会话内"的定义；跨项目会带来噪声与**隐私越界**（B 项目会看到 A 项目的一切发言） | **不建议** |
| **D** 记忆面板加「提升为全局」 | 人工把某条 finding 归置到 `_global` | 全手动；但**可见、可控、可撤销** | 可作兜底（与用户"看得见的交付"偏好一致） |

两个必须一起定的技术点：

1. **键的语义**：日程类事实是**版本更新**（昨天 1 场 → 明天 2 场），不是"两条并存"。
   所以全局侧建议用**主题键**（`user.interview`）而不是 claim 指纹 —— 记忆库的 `events` / `beliefs`
   本来就有 `valid_from` / `valid_to`，更新留痕天然合适。**这与"矛盾的结论必须并存"不冲突**：
   那条纪律管的是**对项目的判断**，日程是**时间轴上的取值**。
2. **权威级别**：这类事实**不是对项目的断言** ⇒ 与项目文件冲突时不该套用"以文件为准"，
   而应标成"用户自述（时间）"，并让引擎**并列**（与 §4 表同一条纪律）。

## 7. 判据草案（预注册，动手前先写死；照 v1.4 的实验纪律）

1. **跨项目正例**：在 A 项目说一句（显式口令或模型声明），切到 B 项目问 ⇒ `read{scope:"global_mem"}`
   命中，且命中带"用户自述"与时间；
2. **对照臂**：同一句话**不声明**时，全局层**条数不增长**（不许把闲聊灌进全局）；只钉"能搜到"的话，
   任何"什么都往全局塞"的实现都会绿；
3. **权威序不变**：项目文件里的说法不会被全局记忆顶掉（冲突**并列**，引擎不裁决）；
4. **更新语义**：先说"两场"、后说"改成一场" ⇒ 最新值生效、旧值留痕（`valid_to`），
   检索里能看到"曾有过旧值"；
5. **写盘 = 零**沿用五服那条：在这些路径上项目树指纹跑前跑后一致。

## 8. 今天的临时办法（已告知用户，零代码）

唯一天生跨项目的一层是 **`kb`**：把一份"我自己的记事 / 日程"目录加进配置 `harness.kb.roots`
（表单里能填，索引由宿主自动建），之后**任何项目**里都能 `read {scope:"kb"}` 找到它。
局限：它只认"语料目录"，得有人把话写进去（用户写，或让 agent"记一下"时顺手写）。
