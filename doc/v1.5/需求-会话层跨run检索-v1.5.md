## 1. 口径 vs 代码事实（逐条判）

| 口径 | 判定 | 依据（代码） |
|---|---|---|
| 「本 run **还在上下文里**的部分无需搜索」 | ✅ **对** —— 而且这条该写成纪律（"先在上下文里看，再检索"） | 布局契约 `[S][E][A]`：未折的正文就在**可追加段**里，模型眼前就有 |
| 「**所以** session 不该包括本次 run」 | ⚠️ **只对一半** | `fold_history` 把老轮次压成一行事实，**正文已离开上下文**、落进 `ctx/<run-id>/` 侧存（`capsule.rs`）。那一部分恰恰是第 1 服现在唯一能**按内容**找回的东西（此前只能"同键重发"才召回） |
| 「甸服 = 本 session 内**前几个 run**」 | ✅ **方向对，但现在做不到** | 见 §2 两个缺口 |

**一句话**：session 要包括的不是"本次 run 的全部"，而是"**本会话里已经离开上下文的那些正文**" ——
本 run 折掉的那部分算，仍在上下文里的那部分不算。

## 2. 两个缺口（缺了它，"前几个 run"无从谈起）

1. **实现只读本 run**：`agent/search.rs` 的 `SearchScope::Session` → `ctx.progress().capsule()`；
   而 capsule 落点是 `<便携根>/projects/<键>/ctx/<run-id>/` —— **一个 run 一个目录**
   （`capsule.rs::create`）⇒ 前几个 run 的侧存不在它的视野里。
2. **session → run 的映射不存在**：`SessionMsg.run_id` 字段**已经在了**，但聊天 run 跑的是工具循环
   （`agent_reply`）**不落 RunRecord** ⇒ 全仓字面量都是 `run_id: None`，重启后连"这个会话的 run 是哪几个"
   都无从判定。（非聊天的 `agent_run` 有 RunRecord，映射天然有。）

> 好消息：**钥匙已经插在门上** —— 字段在、capsule 的 run-id 也在（`tool_loop.rs` 建侧存时就定了名），
> 缺的只是"把本次 run 的 run-id 交回宿主并写进那条 assistant 消息"。

## 3. 候选方案

- **A（建议）：把 `session` 重新定义成「本会话里已经离开上下文的正文」，按时间倒序。**
  1. 引擎把本次 run 的侧存 run-id 交回（`AgentOutcome` → `ReplyAgent`），宿主写进该 assistant 消息的
     `run_id`（字段已存在，只是"填上"）—— 这是跨 run 的**唯一钥匙**；
  2. `session` 检索时按该会话的 run 列表（新→旧）逐个查内容；**一次一层不变**；
  3. 版本源从"一个 index 文件"变成"参与检索的那些 index 的指纹组合"（仍可判"变了没有"）；
     命中仍走账本（同层同词同版本不重复问）。
  命中**必须标明**属于哪个 run / 第几轮 / 哪个工具 —— "刚说过"与"上一个 run 说过"含义不同。
- **B：只补「前几个 run 的原始对话」**（读 `session.json` 的消息），不动 capsule。便宜，但
  **折掉的中间正文（工具调用与结果）仍找不回** —— 而那恰恰是最需要找回的部分。
- **C：跨 session 也算**（把别的会话搜进来）。**不建议**：那是另一个概念（"我记得在哪个会话里聊过…"），
  和"本会话内"混在一起，权威序只会更糊。

## 4. 判据草案（先写死，再实现）

1. 本 run **未折**的正文**不在**第 1 服的结果里（它还在上下文 ⇒ 搜它是白烧一轮）——这条也是那条纪律的判据。
2. 本 run **已折掉**的正文**在**第 1 服的结果里，且标明"本轮第 N 轮 / 哪个工具"。
3. **上一个 run** 的正文在第 1 服里找得到，且标明是哪个 run（"刚说过"与"上一个 run 说过"必须可分）。
4. 同层同词同版本第二次不执行（版本源换成多 index 指纹组合后仍然成立）。
5. 一个字节都不写（沿用 v1.5 的整树指纹判据）。
6. 字段为空的历史会话**不报错**：如实说明"这个会话没有可检索的历史"，不是"没有记忆"
   （与既有纪律"库不可用 ≠ 空答案"同款）。
