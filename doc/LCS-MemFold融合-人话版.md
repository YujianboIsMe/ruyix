# LSC × MemFold 融合人话版（两套东西怎么不打架）

> 前置：`doc/LCS-人话版.md`（LSC = 上下文怎么排、什么时候压）、
> `doc/MemFold-人话版.md`（记忆折叠 = 什么能折、什么不许折）。
> 这份讲**它们本来互相冲突在哪、我们怎么把它们拧成一套**。
> 代码位置都写在每节里（`文件:行`），可以直接对着看。

## 0. 一句话概括冲突与融合

| | 它想要什么 | 它讨厌什么 |
|---|---|---|
| **LSC** | 前缀**一个字都别动**（动了缓存全废、钱白花） | 每轮改前面的东西 |
| **MemFold** | 结论**每轮都要看得见**（看不见就重读、就忘） | 把事实丢了 |

**正面冲突**：MemFold 要求的那块「进展记忆」**每轮都在变**，而 v1.1 把它拼在
`system`（也就是 LSC 的不可变根 `S`）里 —— 每轮重建 `system` ⇒ LSC 的第一条铁律（I1）
当场被踩，**它后面的一切**（任务头 + 整段历史）都不再是公共前缀。

**融合的一句话**：

> 把「**必须变**」的东西挪到最后（易变尾 `A`），把「**必须留**」的东西做成只追加条目（梯子 `E`），
> 把「**可以丢**」的东西折成一行、正文归档到磁盘。
> 三者各归其位，两套要求就不再互斥。

### 0.1 先破三个最容易搞反的地方

| 容易搞反的想法 | 实际是什么 |
|---|---|
| 「**一个 run 跑完**，压成一行」 | **跑的过程中**就在折：每轮（调度关）或调度器决定的那一刻（调度开），把**超出保留窗口的老轮次**各自缩成一行。run 结束之后**没有**「收尾压缩」这一步 —— 那时请求早发完了，上下文已经完成使命 |
| 「压出来的一行**塞进不可变根 `S`**」 | 恰恰相反：`S` 是**唯一绝不许被写**的地方。折完的结果**留在历史里当新基底**；**新**信息（结论/账本）走**每轮重建的尾 `A`**；被折掉的**全量正文**在磁盘（capsule / findings spill） |
| 「整个 run 就只剩那一行信息」 | 折掉的只有**正文**：**结论与证据一个字都不折**，而且**保留窗口内的正文一字不动**（`keep` 是安全下限）。全量原文在侧存里，按哈希随时取回 |

现场长这样（`agent/tool_loop.rs:1146-1154`，调度开时只在 `d.rebase` 那一轮折）：

```text
[agent] 第 N 轮 历史折叠 3 轮（省 12345 字节；下限仍保 4 轮正文）
```

折完还有一行记账：`base_bytes = msgs_bytes(&msgs)` —— 把**当前历史记为新的基底**。
LSC 里那个词「**重基线（re-base）**」，说的就是这个动作。

## 1. 冲突的根源：一个说「别动」，一个说「必须动」

- **LSC 的两条铁律**（`agent/context.rs` 抬头那张表）：
  - **I1** `S`（system + 工具声明 + 任务原文）**字节不变** —— 改了它，它之后**所有**缓存块失效；
  - **I2** `E`（梯子）**只追加** —— 就地改写老条目同样作废其后缓存。
- **MemFold 的两条铁律**（`agent/findings.rs` 抬头）：
  - 对话流的**正文**可以折（噪声居多）；
  - **结论与「已做过什么」不许折** —— 折了模型就重读、就失忆。

于是有一处**天然对撞**：进展记忆块的位置。
- 放 `system`（v1.1 的做法）：位置固定、看着"对缓存友好"，但它**每轮都在改** ⇒ 违反 I1；
- 不放进去：MemFold 要的「每轮都看得见结论」落空。

**实测代价**（v1.2 需求 §1）：同一份动作序列过两臂（配对），
公共前缀占比只有 **33.2%（脚本化臂）/ 54.1%（真轨迹回放）** —— 就是这一处对撞的量。

## 2. 融合法则：按「可变性」分四档

| 档 | 装什么 | 谁的要求 | 规则 | 载体 |
|---|---|---|---|---|
| **S 不可变根** | system 提示 + 工具声明 + 任务原文 | LSC I1 | **一个字节都不许动** | `msgs[0]`，全程不动 |
| **E 只追加梯子** | 历史这一路：老轮次折成的一行、追加的摘要 | LSC I2 | 新信息**只加不改**；折叠是「原地缩一次，之后不再动」 | 历史消息 |
| **A 易变尾** | **findings 块的当前快照**、最新观察、待办 | MemFold「每轮都要看得见」 | 每轮整块重建，**只活这一次请求** | 请求体最后一条 |
| **磁盘** | 被折掉的正文、超限的结论 | 两者共识：**证据不许丢** | 按哈希无损召回；**落盘 ≠ 删除** | capsule 侧存 / findings spill |

这就是融合的**全部秘密**：不是让谁让步，而是**按"这个东西会不会变"重新分家**。
会变的放最后（改了也只影响尾巴），要长期留的做成只追加（加了不碰老的）。

> **一处措辞要较真**（我自己第一版就写糊过）：折叠**不是**「往梯子上再加一条摘要」，
> 而是**把老轮次的正文原地缩成一行**，并把缩小后的历史当作**新的基底**（`fold_history`
> 直接替换那两条消息的正文；幂等，同一轮再折写进去的是同一串文本）。
> 梯子说的「只追加」，管的是**新信息**（结论、账本、新摘要）不许回头改旧条目。

## 3. 最硬的一处工程冲突：下标纪律

融合真正的难点不在概念，在**代码里一处很别扭的依赖**：

- `fold_history` 折历史是**按下标**改老消息正文的（`RoundSlot` 记着「第几轮对应哪条消息」）；
- LSC 又要求「请求体里得有一条尾」。

如果那条尾**留在 `msgs` 里**跨轮存在，历史的下标就会整体偏一格——**折错消息，甚至越界 panic**。

**解法（`agent/tool_loop.rs:353-392`）**：

```text
请求前：tail_idx = msgs.len(); msgs.push(尾)      ← 尾只在这一刻存在
       ↓ 调模型
返回后立刻：msgs.remove(tail_idx)                  ← 摘掉，下标纪律回到原样
```

两个细节，都是必须的：

1. **摘尾在所有出口之后**（包括"调用失败、退避重试"那条 `continue`）——
   漏一条出口 ⇒ 下一轮会攒出第二条尾，记账就脏了；
2. 摘掉之后 **线上请求体仍然是 `[S][E][A]`**（两条臂在这一点的字节形状相同）——
   否则两臂读数就没法比了。

所以：**MemFold 的下标纪律和 LSC 的尾巴形状，两者都要，靠"发前 push、发后立刻摘"同时保住。**

## 4. 谁当守门人：运行时 I1 断言

契约不能只写在注释里。`agent/tool_loop.rs:400-417` 每轮**运行时**核对一遍：

- 取发出去那条请求的 `msgs[0]` 算指纹；
- 开着布局（`agent.ctx.layout`）却**指纹变了** ⇒ 记一条 **error**：
  「布局契约 I1 被违反：S 段指纹 A ≠ 上轮 B（layout=on 时它必须逐轮逐字节相同）」。

还有一个**计量纪律**值得抄：量尺（公共前缀占比 + 厂商回报的 `cache_read` 真值）由
**独立开关** `agent.ctx.metrics` 控制。为什么要分开？因为**对照臂也必须能量**——
仪器只长在实验臂上，「占比上升」就无从比较。

## 5. 第二处冲突：什么时候折

- MemFold 这边有个数字：**保留最近 `keep` 轮正文不动**（老做法，拍出来的）；
- LSC 这边说：**时机应该算**（携带费 vs 重建费，动态规划 + 每轮滚动重规划，
  视野未知退化成 ski-rental）。

**融合方式：把一方的硬数字降级成另一方的约束边界。**

- `keep` 不再是"策略"，降级为**安全下限**：绝不在 N 轮之内折、折叠后仍保 N 轮正文（拍板 3）；
- 真正决定权归调度器，判定顺序 **预算 → 安全下限 → DP / ski-rental**；
- 再加一条 `MARGIN = 5%` 材料性下限：算出来只差几个百分点就不折腾（折一次要**打断前缀**，不划算）。

方向性很妙：**LSC 希望少折（折=断前缀），MemFold 希望别爆** ⇒
两者共同的最优解正好是「够用就好、别勤折」。实测这条也落地了：**折叠次数 8 次 → 1 次**。

## 6. 第三处冲突：去重与「重读」

- LSC 的 G3（**零冗余执行**）说：同一个纯工具、资源版本没变 ⇒ **不许执行第二次**；
- MemFold 的老毛病（ISSUE-8）恰好是：**正文被折掉 ⇒ 模型重读 ⇒ 又被折掉 ⇒ 再读**，
  96 轮跑完 0 结论。

这两个如果各干各的，会互相打死对方：**去重命中却不给原文 = 让模型干瞪眼**。

**融合点：不许重跑 ⇒ 必须能无损召回**（G3 与 G4 是一对，缺一个就回到死循环）：

| 机制 | 落点 | 保证 |
|---|---|---|
| **capsule 侧存** | `<便携根>/projects/<键>/ctx/<run-id>/` | 被折/被去重命中的**全量正文**；召回**逐字节 sha256 校验**，不符报错计数（绝不静默给脏数据） |
| **findings 落盘** | `<状态根>/findings/findings.md` | 结论超字节上限时，最老的 active **追加落盘**并标记，**提示词里留指针行**；只剩一条时**不再落盘**（宁可超一点也不空手） |
| **账本有界** | 提示词里的账本段 | 只放最近若干行，更早的**显式**写「省略了多少条」——**不静默截断**（静默截断会让模型以为"没做过"，正是要治的病） |

所以三样东西是**一件事的三个零件**：折叠（腾地方）、去重（别重复干）、侧存（腾掉的东西能拿回来）。

## 7. 融合之后，一条请求长什么样

```text
第 N 轮请求体 = [ S 不可变根 ][ E 只追加梯子 ][ A 易变尾 ]
                    ↑ 全程不动      ↑ 只加不改      ↑ 每轮重建、发完即摘
                                                      └─ 进展记忆快照 + 本轮观察 + 待办

被折掉的正文  → capsule 侧存（sha256 召回）        超限的结论 → findings.md（留指针行）
已做过的调用  → 引擎账本（有界、显式说省略了多少）   结论/证据 → 梯子（永不折、只追加）
```

四类信息，四个去处，**各有一条判据**：

| 信息 | 去哪 | 判据 |
|---|---|---|
| 结论 + 证据（F1/F2…） | 梯子 `E`（只追加） | 空证据不许入库；取代不改历史；字节可观测 |
| 已做过什么（读/跑过） | 账本（有界） | 显式说明省略量；不靠模型自觉 |
| 老轮次的正文 | 折成一行 + 正文进 capsule | 「为召回而重跑工具」= 0；召回 sha256 相等 |
| 每轮要看的快照 | 尾巴 `A` | 每轮重建；`S` 指纹逐轮不变（运行时断言） |

## 8. 谁负责什么（以后别又打架）

| 问题 | 谁答 | 在哪 |
|---|---|---|
| 每轮要不要变？ | MemFold：要，但**只在尾巴** | `tool_loop.rs:339-374` |
| 能不能放前面？ | LSC：不能（I1） | `context.rs` 抬头 |
| 什么时候折？ | LSC 调度器（`keep` 只是下限） | `scheduler.rs` |
| 折什么？ | MemFold（正文可折，结论不可） | `findings.rs` |
| 折掉的正文去哪？ | 两者共识：侧存 | `capsule.rs` |
| 怎么知道没折坏？ | 运行时 I1 + G1/G2 + 配对读数 | `tool_loop.rs:400`、`examples/ctx_layout_ab.rs` |

**消融一下看得更清楚**（同一份输入，配对两臂）：

| 只开什么 | 事实会不会丢 | 前缀占比 | 结果 |
|---|---|---|---|
| 只 MemFold（v1.1 位置：拼 `system`） | 不丢 | **33.2% / 54.1%** | 记忆保住了，但每轮砸缓存 |
| 只 LSC（关掉进展记忆） | **会丢** | 好看 | 模型回到"重读—被折—再读"闭环 |
| **两个都开（现状）** | 不丢 | **72.4% / 75.1%（+21.0pp）** | 这才是融合要的结果 |

（两个数字都来自 v1.2 需求 §8 的配对回放；前者是未开布局的臂，后者是开了的臂。）

## 9. 一句话版（讲给别人听）

> LSC 和 MemFold 看似冲突：一个要求"前缀一个字都别动"，一个要求"结论每轮都得看见"。
> 我们的融合是**按可变性分四档**——不变的放根（`S`）、只追加的放梯子（`E`）、
> 每轮要变的放尾巴（`A`）、能丢的折成一行而正文进侧存（磁盘）。
> 工程上最硬的一处是**下标纪律**：折叠按下标改老消息，而尾巴又要进请求体，
> 解法是"**发前 push、发后立刻摘**"，并且有一条**运行时断言**盯着 `S` 的指纹逐轮不变。
> 一句话：**不是让谁让步，而是把"会变"和"要留"分开安置。**
