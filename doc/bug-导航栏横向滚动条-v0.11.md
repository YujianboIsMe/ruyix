# 需求：导航栏过宽时加水平滚动条
## 归属版本：v0.11 · 状态：**已实施**（2026-09-24）· 提出：2026-09-24（用户）

> 用户原话：*"UI优化：现状：导航栏没有水平滚动条。期望：改成过宽时加上水平滚动条。"*

## 1. 根因（实测，不是猜的）

`scripts/nav-layout.js` 先量了一遍**修复前**的基线：

```
短内容：内容区 259px（滚动宽 259）｜横条 0px
长内容：内容区 249px（滚动宽 249）｜横条 0px        ← 内容永远等于视口宽
长文件名：宽 157px（内容 477px）｜scrollLeft 能到 0px（上限 0）
```

一个 477px 的长文件名被塞进 157px 的格子，`text-overflow: ellipsis` 吃掉 **320px**。
`.`nav-content` 其实是 `overflow-y: auto`（按 CSS 规范另一轴会算成 auto），但**内容永远不宽于
视口** —— 于是横向滚动条永远不出现，长名也永远读不全。两件事是同一个病因。

## 2. 修法（全在 `ui/styles.css`）

| 落点 | 改动 | 为什么 |
|---|---|---|
| `.nav-content` | `overflow-y: auto` → `overflow: auto` | 两个方向都能滚（`auto` = "过宽时才加"，不是常驻） |
| `.file-tree` | `min-width: max-content` | 内容按需撑宽 → 长路径不再被省略号吃掉，超出部分交给 `.nav-content` 横滚 |
| `.file-tree .tree-node` | `width: fit-content` | 行按**自己的内容**排（不被撑到"最宽那一行"）→ 行末的刷新按钮待在**行自己的末尾**，短行看得见、长行滚到最右就看见 |
| `.tree-node:hover::before` | 铺到可视区右缘的伪元素 | 行按内容宽度排之后 hover 底色只会铺内容那么宽（短行缩成一小条）——用一层伪元素补回整条，溢出部分被 `.nav-content` 裁掉 |

**只改文件树**：项目卡片 / 会话 / 运行目标那几个列表**保持原样**（名字走省略号，本来就装得下；
一起改反而把它们行右缘的编辑/删除按钮也拖进同一个坑）。能力面板更不动（说明文字要折行）。

## 2.1 后续修正：按钮盖住了路径（用户圈出来的瑕疵）

第一版给行右缘的按钮用了 `position: sticky; right: 0`，把按钮钉在可视区右缘。**这必然遮字**：
按钮被钉住不动，而路径文字从它底下滚过去 —— 用户实测："导航栏文件路径很长，触发水平滚动条时，
刷新符号盖在文件路径上"。**钉住的元素 + 滚动的文字 = 遮挡，这是几何上的必然，换谁写都一样。**

改法：**行按自己的内容宽度排，按钮就待在行自己的末尾**（普通文档流，谁也不压谁）：
短行的按钮看得见（名字后面紧跟），长行的按钮滚到最右就看见。配套加了 `:hover::before`
把 hover 底色铺回可视区右缘（否则短行的底色会缩成一小条）。

同时**把改动范围收窄到文件树**：第一版顺手给项目卡片 / 会话 / 运行目标列表也加了
`min-width: max-content`，它们行右缘同样有按钮（项目编辑/删除、终端新窗口），会掉进同一个坑 ——
那几个列表的名字本来就靠省略号读得下，退回原样。

### 踩过并记下来的两个错法

1. **给行加 `min-width: 100%`**（想让短行铺满可视宽度）：那个 `100%` 相对**最宽的父级**解析，
   等于把每行都撑到最宽那一行 —— 实测普通目录行的刷新按钮被推到 **557px**，滚出 260px 的侧边栏。
2. **给按钮 `position: sticky; right: 0`**：按钮钉住、文字滚动 ⇒ 按钮压在路径上（本单的瑕疵）。
   正确姿势是"行多宽按钮就在多宽的行末尾"，不是把按钮钉在视口上。

## 3. 判据

### 真几何探针 `scripts/nav-layout.js`（ui-smoke **U44**）

真 index.html + styles.css，用真 markup（形状照抄 `main.js::renderTreeEntry`）往
`#file-tree` / `#project-list` 塞行，无头 Edge 里量"短内容 / 长内容"两场景：

```
短内容：内容区 259px（滚动宽 259）｜横条 0px｜纵条 0px
长内容：内容区 249px（滚动宽 557）｜横条 10px｜纵条 10px
长文件名：宽 477px（内容 477px）｜scrollLeft 能到 308px（上限 308）
  ok  短内容时不出现横向滚动条（「过宽时才加」）
  ok  长内容时出现横向滚动条（10px，内容 557px > 视口 249px）
  ok  横向真能滚：可滚 308px
  ok  长文件名没被压缩（477px 装下 477px 的内容）
  ok  滚到底时长文件名整条进入可视区
  ok  纵向仍可滚（内容 936px > 视口 552px）
  ok  长目录行：刷新按钮在名字右侧（名字右 502 ≤ 按钮左 502），没有遮挡     ← 本单的瑕疵判据
  ok  短目录行：刷新按钮在名字右侧（名字右 64 ≤ 按钮左 64），没有遮挡
  ok  长目录名的文字也没被压缩（422px 装下 422px）
  ok  短目录行的刷新按钮不滚就在可视区（右 89 ≤ 导航右界 260）
  ok  长目录行滚到最右时刷新按钮进入可视区（194..219）
```

`ui-smoke` **307/307**（含 U44；同批还有 U43/U45）、check-style PASS、clippy 0、fmt 干净、
引擎 351 / 宿主 121 不变。

## 4. 边界（没验的）

- **只改文件树**：项目卡片 / 会话 / 运行目标列表维持原样（名字走省略号），它们没有单独量过
  （也不需要 —— 没动过）。
- `:hover::before` 那条 hover 底色**量不到**（无头里没有鼠标交互）：判据只到"规则在不在 + 行的几何"，
  真机观感需重启 ruyix 过一眼。
- 真机观感（横滚条出现/消失时机、刷新按钮位置、hover 底色是否铺满一条）需重启 ruyix 肉眼确认。
