# 需求：导航栏过宽时加水平滚动条
## 归属版本：v0.11 · 状态：**已实施**（2026-09-24）· 提出：2026-09-24（用户）

> 用户原话：*"UI优化：现状：导航栏没有水平滚动条。期望：改成过宽时加上水平滚动条。"*

## 1. 根因（实测，不是猜的）

`scripts/nav-layout.js` 先量了一遍**修复前**的基线：

```
短内容：内容区 259px（滚动宽 259）｜横条 0px
长内容：内容区 249px（滚动宽 249）｜横条 0px        ← 内容永远等于视口宽
长文件名：宽 157px（内容 477px）｜scrollLeft 能到 0px（上限 0）
```

一个 477px 的长文件名被塞进 157px 的格子，`text-overflow: ellipsis` 吃掉 **320px**。
`.`nav-content` 其实是 `overflow-y: auto`（按 CSS 规范另一轴会算成 auto），但**内容永远不宽于
视口** —— 于是横向滚动条永远不出现，长名也永远读不全。两件事是同一个病因。

## 2. 修法（全在 `ui/styles.css`）

| 落点 | 改动 | 为什么 |
|---|---|---|
| `.nav-content` | `overflow-y: auto` → `overflow: auto` | 两个方向都能滚（`auto` = "过宽时才加"，不是常驻） |
| **名称/路径型列表**<br>`.file-tree` `.project-list` `.terminal-list`<br>`.agent-history-list` `.run-targets-list` | `min-width: max-content` | 内容按需撑宽 → 长名不再被省略号吃掉，超出部分交给 `.nav-content` 横滚。**只给这几个列表加**：给 `.nav-panel` 统一加会让能力面板里的说明文字也**停止折行**（那是文本面板，不是名称列表） |
| 行右缘的按钮<br>`.tree-refresh` / `.project-item-edit` / `.project-item-del` / `.terminal-new-window` | `position: sticky; right: 0` + 底色 | 行会被带到"最宽那一行"的宽度，按钮原本会落到视口之外 —— 粘在可视区右缘：短行看不出差别，长行滚到哪都点得到 |

**踩过并记下来的错法**：先试了给行加 `min-width: 100%`（想让短行铺满可视宽度）——那个 `100%` 是
相对**最宽的父级**解析的，等于把每行都撑到最宽那一行：实测普通目录行的刷新按钮被推到
**557px**，直接滚出 260px 的侧边栏。正确姿势是 `sticky`，不是撑宽。

## 3. 判据

### 真几何探针 `scripts/nav-layout.js`（ui-smoke **U44**）

真 index.html + styles.css，用真 markup（形状照抄 `main.js::renderTreeEntry`）往
`#file-tree` / `#project-list` 塞行，无头 Edge 里量"短内容 / 长内容"两场景：

```
短内容：内容区 259px（滚动宽 259）｜横条 0px｜纵条 0px
长内容：内容区 249px（滚动宽 557）｜横条 10px｜纵条 10px
长文件名：宽 477px（内容 477px）｜scrollLeft 能到 308px（上限 308）
  ok  短内容时不出现横向滚动条（「过宽时才加」）
  ok  长内容时出现横向滚动条（10px，内容 557px > 视口 249px）
  ok  横向真能滚：可滚 308px
  ok  长文件名没被压缩（477px 装下 477px 的内容）
  ok  滚到底时长文件名整条进入可视区
  ok  纵向仍可滚（内容 915px > 视口 552px）
  ok  普通目录行的刷新按钮仍在可视区（右边缘 249 ≤ 导航右界 260）
  ok  终端列表过宽时也能横滚（内容 638px > 视口 259px）
  ok  终端行的 🪟 图标仍在可视区（右边缘 259 ≤ 导航右界 260）
```

`ui-smoke` **275/275**（新增 U44）、check-style PASS、clippy 0、fmt 干净、引擎 351 / 宿主 121 不变。

## 4. 边界（没验的）

- 探针覆盖**文件树 / 项目列表 / 终端列表**（含它们行右缘的按钮）；`.agent-history-list`（会话）
  与 `.run-targets-list`（运行目标）用的是同一套类与规则，但**没有单独量过**。
- **能力面板**（MCP/技能/工具）**故意不动**：那里是说明文字，折行比横滚可读；若它内部出现
  确实过宽的元素（长表格 / 长路径），再单独处理。
- 真机观感（横向滚动条的出现与消失、sticky 按钮的悬停底色）需重启 ruyix 肉眼过一遍。
