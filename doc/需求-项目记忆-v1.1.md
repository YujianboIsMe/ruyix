## 1. 目标：一句话

**让 ruyix 同时满足两条公理**（论文里的 EC + BS），并且在既有形态内落地：

| 公理 | 通俗说法 | 验收形态 |
|---|---|---|
| **EC**（证据完备） | **历史一条不丢** | 任意一条曾经到达的观察，之后任何时刻都能**按原样**取回 |
| **BS**（信念可靠） | **前文能被后文推翻** | 被推翻的内容**不再**出现在"当前事实"里；但**仍**能按时间点查到它曾经成立 |
| **BC**（上下文有界） | 注入给模型的东西有上限 | 与历史长度无关的 token 预算 |

论文的关键洞见是：**这三条只有在"同一份存储既当证据又当信念"时才互相打架**。所以本方案的骨架就是把它劈成三层 ——
**账本（证据，只追加）／折叠（信念，可重推导）／视图（注意力，有界可丢弃）**，每一层只承担一条公理。

## 2. 现状对照：我们今天的"记忆系统"是什么

散落五处，各有各的失效方式：

| 现存的"记忆" | 实际形态 | 对应公理 | 失效方式（具体症状） |
|---|---|---|---|
| 会话历史 `projects/<key>/sessions/*.json` | 只追加 + 每条消息带快照（`m.plan/trace/verify/reflect`） | EC 部分成立 | **无脱敏**、无压实、无溯源；恢复老会话时旧结论被当事实重新注入（**违反 BS**） |
| `discover` 工具链发现 | **300 秒 TTL 缓存** | 都没有 | TTL 既不是证据也不是信念 —— 它是"冒充新鲜度的驱逐策略"；过期即全部重探（每轮白烧） |
| 配置 / 运行目标 / 终端目标 | 就地覆盖 | 违反 EC | 改名/删条目后**旧值不可恢复**；没有"谁什么时候为什么改的" |
| `env install` / `plugins.jsonl` | 只追加 JSONL（**成功也写**） | EC 成立 | 只有**动作**没有**信念**；不会回答"所以这台机器上 mvn 到底在哪" |
| `CLAUDE.md` / `doc/bugs.md` | 人工维护的"当前信念视图" | BS 成立 | 没有版本链（谁推翻的、依据是什么）；**人肉**维护 |
| 复核/验证结论（`m.verify` / `m.reflect`） | 每条消息的快照（claim/evidence/verdict） | —— | **这就是"收据"的雏形**，但没有落在账本里、没有指回原始事件 |

**一句话归纳**：我们**已经有了证据层和视图层，缺的是"折叠"**——也就是"哪些当前为真、依据是什么、被谁推翻"这一层。这正是论文说两个阵营镜像失败的位置：只追加的东西（会话、JSONL）不会消解矛盾，覆盖式的东西（配置）反过来把历史烧掉了。

## 3. 要吸收的四条（按性价比排序）

### ① 压缩收据（最便宜，立刻可做）
今天每一次有损操作都**没有收据**：`execute` 输出裁剪、步骤摘要上限（12 行/1.5KB）、注入清单被截、KB/摘要压缩。
→ 每次压缩落一条**收据**：覆盖了哪些事件、什么离开了视野、**怎么换回来**（原始日志的路径/事件 id）。
价值：把"静默丢失"变成可审计事实。ruyix 的现成优势：完整日志本来就落文件（proc 日志、`--debug` 日志），"换回来"只是路径查询。

### ② 项目信念账本（价值最高，本需求的**主交付**）
只装**仓库记不住的事实**：工具链位置、构建/测试/运行命令、用户偏好、项目约定与坑。
每条信念 = `{键, 值, 有效期区间, 溯源(事件 id), 状态(active/superseded/contested), 修订链}`，写入只追加。

- **`discover` 的 TTL 缓存升级成账本条目** —— 从"过期即遗忘"变成"我能说出我为什么这么以为，并且我能复验"。
- harness 的独特优势：**信念可以复验而不必信任**（探一次文件系统 / 跑一次命令就是证据），所以这套东西在 IDE 里比在聊天助手那儿更站得住。

### ③ 结构性替代过滤（BS 的落点，**不是**降权）
检索默认模式 `now`：**先**按 `状态 ≠ superseded 且有效期覆盖查询时间` 结构性排除，**再**打分。
论文引用的实测（"未过滤的历史路径损害时序推理"）与我们自己的教训同向：把被推翻的旧值降权留在候选里，只会制造偶发幻觉。

### ④ 两个便宜查询：`why` 与 `as-of`
- `why(b)`：这条信念的完整修订链 + 依据 —— **一次调用回答"你凭什么这么认为"**。
- `as-of(t)`：某时刻的信念状态 —— 回答"当时我们以为是什么"。
  这两个是"可审计"的实际入口；`diff` / `counterfactual` 成本高、收益靠后，**本版本不做**。

## 4. 架构（三层的落点）

```
<便携根>/projects/<key>/memory/mem.db        ← SQLite（不写用户仓库，符合"零残留"）
├── events     账本：append-only，(id, ts, kind=obs|rev, payload, prov[], prev_hash, hash)
├── beliefs    折叠结果（可丢弃、可重建）：(key, valid_from, valid_to, value, status, prov, revs)
├── index_v    向量 + FTS5 虚表（视图之二：检索用）
└── receipts   收据：(视图快照/压缩动作, 覆盖事件集, 离开视野的内容, 换回路径)
```

- **账本**：`events` 只追加；`prev_hash` 链式（防篡改是可选项，字段先留着）。**决策即记录**：模型裁决的事件本身落账（含 `prov` 指向依据事件），因为裁决器非确定 ⇒ 重放必须靠记录。
- **折叠**：`fold(prefix) -> beliefs`，增量（每条事件 O(1) 改槽位）+ 每 K 条一个检查点。**放进 `beliefs` 表的是缓存**，删掉能从 `events` 重建 —— 这是 EC 不被破坏的关键。
- **视图**：注入给模型的是**有界块**（token 预算），逐出只是移出视图；每次压缩签发收据。
- **检索**：`now` = 结构性过滤 → 打分 → 组装（信念在前、证据在后、带溯源编号）。
  打分 = **FTS5/BM25 与向量余弦的加权融合**（经验值：BM25 腿权重压到 0.1 量级、>2 核心词走 OR 提召回，见技能 `code-search-retrieval-tuning`）；低于阈值**弃答**，不用被推翻/无依据的内容作答。

## 5. 技术选型（本机实测，非推测）

### 5.1 向量库：SQLite BLOB + 暴力余弦（**不引入新依赖**）

- 引擎**已经依赖 `rusqlite 0.32 { features = ["bundled"] }`**（`crates/harness-engine/Cargo.toml:16`）⇒ SQLite + FTS5 现成。
  *实施第一步自检*：建一张 `USING fts5` 虚表，不通就改带 `bundled-full` 特性。
- 量级测算：**2 万条 × 512 维 fp32 ≈ 40 MB**，单查询暴力余弦 **< 5 ms** ⇒ HNSW/sqlite-vec 在这个量级只增加依赖，不增加价值。
- 升级路径写进注释：**超 2 万条**再换 HNSW（`usearch`），接口不变。

### 5.2 嵌入模型候选（ModelScope 实测清单）

| 模型 | 体积 | 维度 | 备注 |
|---|---|---|---|
| **`BAAI/bge-small-zh-v1.5`** | **95.8 MB**(fp32) | **512** | **推荐**：中文强、体量小、CPU 快；int8 量化后约 24 MB |
| `iic/nlp_gte_sentence-embedding_chinese-small` | 60.5 MB | 512 | 更小的备选 |
| `AI-ModelScope/bge-base-zh-v1.5` | 409 MB | 768 | 质量档 |
| **`D:\Models\bge-m3`（已在盘）** | 2.1 GB | 1024 | 质量最高档（也可做 rerank 语料）；作为**可选高档**，不作默认 |
| `Qwen/Qwen3-Embedding-0.6B` | 1.19 GB | 1024(MRL 可截到 128) | 体积劝退，不作默认 |

**关于"128 维"**：本机没有原生 128 维的中文小模型；而**维度不是本场景的约束** —— 1000 条信念 × 512 维 = 2 MB。
真正的约束是**模型体积与推理依赖**（绿色便携不能带 Python）。所以建议**按"体积/中文质量/推理路径"选，不按维度选**；
若确有 128 维需求，走 MRL 截断（Qwen3-Embedding 支持 32–1024）而不是去找原生 128 维模型。

### 5.3 推理路径（**待拍板**，三条，成本已诚实标出）

| 路径 | 依赖 | 代价 | 评价 |
|---|---|---|---|
| **A. `fastembed-rs`**（ONNX Runtime） | `ort` + 自带 BGE-small-zh 权重 | 构建要拉 ONNX Runtime（约 20MB 运行时） | **首选**：零导出工作、量化权重开箱可用 |
| **B. `candle` 直接吃 safetensors** | 纯 Rust，无 C++ 运行时 | 自己写一点点 BERT 前向 | 次选：最贴合"绿色"，工作量略大 |
| **C. Python sidecar** | 需要用户的 Python + torch | 破坏便携形态 | **否决** |
| D. 本机 `bge-m3` | 需自建 ONNX 导出 | 2.1GB | 只在"高质量档"再考虑 |

注：ModelScope 上这几个仓库**都没有随库提供 ONNX**（实测文件清单），所以 ONNX 路线要么用 fastembed 自带权重，要么自己导出。

### 5.4 分词
- 中文：`jieba-rs` 预分词后进 FTS5（技能 `sqlite-fts5-fulltext-search` 的触发器 + 坑清单直接复用：**不要用 FTS5 特殊 `delete` 命令**，用 `DELETE FROM fts WHERE rowid=?`）。
- 标识符：查询侧与索引侧**共用同一套 `split_identifier`**（camelCase/snake_case 切开），否则 `handleCommand` 这类符号搜不到。

## 6. 与模型的分工（**不许把裁决放到热路径**）

论文每片段一次 LLM 裁决、每轮视图维护 c·log n 次调用；IDE 里一轮 96 步，照搬即自毁。所以：

1. **规则能定的，不叫模型**：环境/工具链/文件存在性 —— **探针即证据**，纯确定性。
2. **只有语义冲突**（"这个项目用的是 X 还是 Y"）才让模型裁决，且**异步/批量**做（run 结束后、空闲期），不在轮内。
3. 裁决器出错不是灾难：它是一次可被修订的事件（修订闭包），争议槽位标 `contested` 双方并存。
4. **不确定性必须被表示，不许被插值抹平** —— 摘要里"把矛盾平均掉"是本代数明令禁止的。

## 7. 预注册判据（**跑之前钉死，含对照臂**）

**实验 A：EC（历史一条不丢）** —— 造 N=200 条混合事件（含被推翻的）→ 随机抽 20 条按 id 取回，**逐字节比对**原文哈希。
判读：20/20 通过才算 EC 成立；任何一条取不回 = 失败（不许用"摘要等价"顶替）。

**实验 B：BS（前文被后文推翻）** —— 构造 30 组"先断言→后推翻"（世界漂移 15 / 误信 15）：
- 判据 B1：`now` 检索在 30/30 组上**不返回**被推翻的值；
- 判据 B2：`as-of(推翻之前)` 在 30/30 组上**返回**旧值（历史没被烧掉）；
- 判据 B3：`why(新值)` 能给出指向推翻事件依据的链路（非空 `prov`）。

**实验 C：对照臂（证明差异是架构性的，不是"我们做得更努力"）** —— 三臂同题：
| 臂 | 实现 | 预期 |
|---|---|---|
| ①只追加 | 不做折叠、检索不去重 | B1 失败（旧值复活），B2 成功 |
| ②破坏式 | 覆盖式写（模拟配置现状） | B1 成功，**B2 失败**（历史没了） |
| ③本方案 | 账本 + 折叠 + 过滤 | B1、B2 都成功 |
判读：若三臂结论与上表方向不一致 ⇒ 说明机制没生效，**修机制而不是改判据**。

**实验 D：有界与可复验**
- D1：注入块 token 数在预算内且**与历史长度无关**（事件 ×10 后复测，注入块涨幅 < 5%）；
- D2：每条注入条目都有 `why` 链（100%），且**≥1 条能被探针复验**（例：工具链路径重新探测一致）；
- D3：收据可换回 —— 从收据给出的路径能取到被裁剪内容的原文（抽样 10 次，10/10）。

**能声称 / 不能声称**
- **能声称**：上述 A–D 的判据；"被推翻的内容不再出现在当前事实里、但仍可按时间点查到"。
- **不能声称**：不宣称提升任务成功率或准确率（那需要 ChunkQA 式受控世界，ruyix 没有）；不宣称替代 git 或 `CLAUDE.md`；不宣称反事实回放可信（副作用不可重跑）。

**门禁落点**（新增，与既有纪律一致）：Rust 契约测试（fold 确定性 / 过滤正确性 / 收据可换回 / `as-of` 边界）+ 一个真机脚本 `scripts/memory-probe.mjs`（跑真 exe，验 A–D，退出码 0/1，失败打印原始证据）。

## 8. 待拍板点（逐条给我的建议）

| # | 待拍板 | 我的建议 | 理由 |
|---|---|---|---|
| ① | 嵌入模型与推理路径 | **bge-small-zh-v1.5 + fastembed-rs（A 路）**；把 bge-m3 作为"高质量档"可选 | 95.8MB/512 维，中文强、CPU 快、零导出工作；不破坏便携形态 |
| ② | 账本范围 | **只装"非仓库事实 + 引擎决策"**，转录不搬家（会话 JSON 继续当证据，账本引用它） | 代码事实 git 已经无损且有修订代数；搬转录只会让账本膨胀并带来泄密面 |
| ③ | 脱敏 | **入账前强制过 `observe::redact`** | 转录里有 key/私有代码；账本是长期存储，比日志更该脱敏 |
| ④ | 向量使用范围 | **只服务记忆检索**（信念/观察），**不**做代码全文检索 | 代码检索是 Code-Rag 的地盘；ruyix 里做会与既有 KB 职责重叠 |
| ⑤ | 首个交付切片 | **先做 ②（信念账本 + discover 升级）+ ①（收据）**，再做 ④（as-of/why 查询面） | 前者直接减掉"重复探查"的浪费，可立刻用真机判据证明；后者是审计能力，价值高但不阻塞 |
| ⑥ | 模型文件放哪 | 默认**便携根外**的用户可配路径（如 `D:\Models`），便携根内只放"路径引用" | exe 目录要保持在十几 MB 级；"绿色"不等于把 100MB 权重塞进包里 |

## 9. 明确不做（以及为什么）

- **不做**对话转录的 git 管理：转录 diff 无意义、提交噪音、并发冲突，且**转录含密钥与私有代码，进带远端的仓库就是泄密路径**（见上一轮讨论的结论）。
- **不做** `diff` / `counterfactual` 查询：成本高、收益靠后；且副作用不可重跑，"反事实"在 IDE 里只能审计不能重演。
- **不做**热路径上的 LLM 裁决（§6）。
- **不做**第二个真相源：信念只装"仓库记不住的东西"，能进仓库的（代码/文档/git 历史）一律不复制。

### 实测数据（都是跑出来的）

- **向量腿**：`bge-small-zh-v1.5`（95.8MB / 512 维），`candle` 纯 Rust 推理，CLS + L2 归一化。
  真机判据通过，包括"**词法零重叠**、只有语义腿能召回"那条（查「如何给数据做快照」命中「记忆库每天压缩一次…」）。
- **阈值是量出来的**（`mem::tests::向量腿_阈值标定`，`-- --nocapture` 可复跑）：
  明显无关 0.180~0.290 ｜ 改写/同义 ≈0.45 ｜ 直白相关 0.59~0.735。
  **教训**：绝对余弦切不开"改写"与"跨话题但都短"（0.45 vs 0.41），所以它只当**低位弃答下限**（0.30），
  排序交给 RRF；"符号查询别用语义腿"交给**结构性规则**（全 ASCII 查询不走语义腿）。
- **写路径不算向量**：第一版每条信念写入时算向量，200 条事件的测试从 4s 涨到 **148s**；
  改成检索时按需补（`embed::ensure_vectors`，一次上限 400 条）后回到 **19.6s**，写入 ~1ms。

### 测试当场抓到的两个真缺陷（留档）

1. **哈希链只验前后指针、不重算内容哈希** ⇒ 直接 `UPDATE events.value` 验不出来。已改为重算内容指纹（`content_of_parts` 与 append 共用）。
2. **语义腿阈值拍得太低（0.35）** ⇒ 查 `file.cargo_toml.dep` 时把 `person.7.city = 巴黎` 排到第 1（无关条目顶掉精确命中）。
   修法见上（结构性规则 + 低位下限），并留下了标定测试。

### 切片 2（已交付）：记忆看得见

引擎里有账本/折叠/收据，不等于用户知道**记了什么、凭什么、什么时候变的、丢过什么** ——
看不见就等于没有。所以切片 2 把四问摆到界面上：

| 件 | 位置 | 说明 |
|---|---|---|
| 记忆面板 | `ui/memory.js`（`window.MemoryUI`，顶栏「记忆」菜单 / 命令动词 `mem`） | 当前信念（可搜）· why 修订链 · as-of 时间轴 · 收据；每行点「凭什么」展开修订链 |
| 标签页与唯一入口 | `ui/main.js`（`_isMemory` + `EDITOR_PANES` 加 `memory-view` + `showPane`） | 与配置/服务/会话同一套互斥机制（bug 3 的病不会再犯） |
| 文案 | `ui/lang/{zh-CN,en}.json`（各 39 键） | 中英齐全，面板零硬编码中文 |
| 人写入口 | 后端 `mem_record`（`origin=human`） | 与探针/引擎决策在账本里同列，但来源可区分 |
| 门禁 | `ui-smoke` **U54**（7 条子判据） | 面板存在且调真命令 / 只经 showPane / 动词注册 / 中英文案齐 / 缺模型说人话 / 后端注册 / **记忆不许被插件化** |

`now` 的一处语义在面板上被显式表达出来：**被推翻的条目不在"当前信念"里**，
但它们**点得开**（why / as-of）—— 界面上"看不到"与"不存在"因此被分开。

### 还没做（登记在案）

- **真实布局探针**：U54 是**契约**静态判据（与服务面板 U23 同规格）；没做"无头浏览器里真跑一遍面板"的
  布局探针（内存面板的表格/展开链目前只在静态契约层被钉住）。

  **没做**每次启动都弹的状态栏提示 —— 那会变成噪音，与"降级要说话"的本意相悖。
